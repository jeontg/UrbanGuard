## 1. 흐름 이력 저장 — 예측의 전제

### 무엇이 문제였나

흐름 지표(속도·방향분산·발산도)는 **계산되고 판정에도 쓰이는데**
(위험도 가중치 65%), **어디에도 저장되지 않았습니다.**

| 남는 것 | 안 남는 것 |
|---|---|
| 위험행동 이벤트 (배회·침입) | **평온했던 관측** |
| 등급이 오른 순간 | **그때의 흐름 수치** |

그래서 **「평소보다 붐비나」에 답할 수 없었습니다** — 비교할 어제가 없습니다.

> ⚠️ **`surge` 가 특히 문제였습니다.** 이름 그대로 「평소 대비 배수」인데
> 그 「평소」가 **프로세스 메모리의 최근 60건**뿐입니다. **재시작하면
> 사라지고**, 새로 쌓이는 60건이 다시 「평소」가 됩니다. 폭우 직후에
> 재시작하면 **붐비는 상태가 평소로 굳습니다.**

### 만든 것

| 항목 | 내용 |
|---|---|
| `crowd_observations` 테이블 | 인원·밀집도 + **흐름 4종** + 판정·근거 |
| 마이그레이션 | `a1c47f30d9b2` (head) |
| `core/crowd_history.py` | 기록 · 시계열 · **기준선** · 보존기간 |
| 연결 | 상시 탐지에서 **평온한 관측도** 기록 |
| 보존 | 기본 **400일** — 계절성(주중·주말·행사철)을 보려면 1년 이상 필요 |

### 설계에서 신경 쓴 세 가지

**① 「못 봤다」와 「사람이 없었다」를 구분합니다.**
프레임을 못 받았는데 인원 0 으로 남기면 「사람이 없었다」로 읽힙니다.
`failed` 로 표시하고 **시계열에서는 뺍니다** — 못 본 구간을 0 으로 채우면
예측이 **「사람이 빠졌다」로 학습**합니다.

**② 관측이 없으면 빈 기준선을 줍니다.**
0 을 돌려주면 「평소에 아무도 없다」로 읽혀 **지금 인원이 전부 급증으로**
보입니다.

**③ 기준선은 중앙값입니다.**
평균이면 튀는 값 하나에 끌려갑니다. 행사 하루가 평상시 기준을 올려 버리면
그 뒤로 아무것도 급증으로 안 잡힙니다.

> **이력 기록이 관제를 멈추지 않습니다.** 실패는 삼키고 로깅만 합니다.

### 개인정보

**사람의 형상이나 식별 정보를 담지 않습니다.** 인원수와 흐름 수치만 남으므로
증거 영상(S-88)과 성격이 다릅니다. 그래도 무한히 쌓지 않도록 보존기간을
두었습니다.

## 2. ⚠️ 좌표 중복 — 진단은 끝, 수정은 보류

### 확인한 것

```
등록 CCTV 39개소 · 서로 다른 좌표 38개
겹치는 좌표 (35.147345, 129.059051)
```

| 항목 | 정체 | 판정 |
|---|---|---|
| `BLOCK-BEOMNAEGOL` 범내골교차로 | **부산 ITS 실시간 CCTV**<br>`its-stream3.busan.go.kr/.../cctv_10.stream` | **좌표가 기준** |
| `BLOCK-GUANGBOK` 광복로 | **데모 영상** `gwangbokro-demo` | 자리표시자 |
| `BLOCK-GUANGBOK1` 광복로1 | **데모 영상** | 자리표시자 |

실시간 스트림이 붙은 쪽이 실제 설치 지점이고, **광복로 두 대는 데모라
범내골 좌표를 복사**한 것입니다. 세 대가 사실상 같은 점에 찍혀 있던 이유입니다.

### 왜 고치지 않았나

**광복로의 정확한 좌표를 근거 있게 확보하지 못했습니다.** 검색으로는 부산시
중심 좌표 수준까지만 확인됐습니다.

> **추정값을 넣으면 「중복」이 「틀린 값」으로 바뀔 뿐입니다.**
> 중복은 눈에 띄지만 그럴듯한 오좌표는 안 띕니다.

**정확한 좌표를 알려 주시면 바로 반영하겠습니다.**

### 그때까지의 영향

| 영향 | 내용 |
|---|---|
| 지도 | 세 지점이 **겹쳐 표시** |
| 반경 질의 | **같은 장소로 취급** |
| 기상 연계 | 광복로가 **범내골 강수량**을 받음 |

## 3. 문서 정정 — 「흐름 부재」 서술

앞선 문서 여러 곳에 **「인파 흐름(속도·방향)이 없다」** 고 적었습니다.
**사실이 아닙니다.**

| 문서 | 바뀐 내용 |
|---|---|
| `202608171242` 국내외 국가사업 분석 | 3곳 — 「흐름 없음」 → **「흐름은 있으나 시계열 예측 없음」** |
| `202608171315` 기술스택 설계서 | 2곳 — 「흐름 자체를 안 만든다」 → **가중치 65% 사용 중** 명시 |
| `202608171820` SSE·DB 판단 | 1곳 — 남은 과제를 **「시계열 예측」** 으로 |

**지우지 않고 `※ 2026-08-17 정정` 표시를 남겼습니다.** 이력이 보여야
합니다.

특히 「쓰면 안 되는 문장」 표의 **「인파 흐름을 예측합니다」** 는 이유가
달라졌습니다.

| 예전 이유 | 지금 이유 |
|---|---|
| 흐름 분석 기능이 **없어서** | 흐름은 **재지만** 앞을 **내다보진 않아서** |

**제안서 검증에서 반박당하는 지점이 다릅니다.**

> ⚠️ **제안서에 「흐름이 없다」고 쓰면 우리 기능을 스스로 깎는 셈입니다.**
