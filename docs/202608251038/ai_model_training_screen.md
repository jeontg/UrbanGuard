## 1. 화면 구조

### 1-1. 진입 경로 — 사용자 확인(2026-08-25): "둘 다"

○ 전용 화면 하나(`/settings/training`)에 4개 도메인 탭
○ **더해** 왼쪽 메뉴의 침수·교통위험·인파관리·도로 노면 4개 도메인
　그룹에도 각각 "AI 모델 학습" 링크를 뒀다 — "위험등급 관리(S-95)"와 같은
　방식(사용자 요청: 담당자가 자기 도메인에서 바로 찾을 수 있게)
○ "운영 설정" 그룹(AI 모델 운영·설정 옆)에도 같은 링크를 뒀다 — SYS 기준
　메뉴에 **총 5곳**에서 이 화면으로 들어올 수 있다

### 1-2. 화면 흐름

1. 도메인 탭을 고른다
2. **학습 데이터 확인** — 준비됨/준비 안 됨과 실제 경로를 그대로 보여준다
3. 준비됐으면 **파라미터**(에폭·배치 크기 등, 도메인마다 다름)를 정하고
   "학습 시작"
4. 진행 중 배너에 **실시간 로그 꼬리**와 상태가 뜬다(4초마다 자동 갱신).
   화면을 닫아도 학습은 계속된다
5. **최근 실행 이력**에 지표(F1·mAP50 등, 도메인마다 다름)가 남는다

### 1-3. 권한 — 사용자 확인: "시스템관리자(SYS) 전용"

기존 "AI 모델 운영(S-61)"·"AI 모델 설정(S-84)"과 같은 권한
(`SETTINGS_SYS`)으로 통일했다. 부서담당자(MGR)·관제요원(OPR)은 화면·API
모두 403이다.

## 2. 도메인별 구성

| 도메인 | 학습 스크립트 | 모델 구조 | 학습 데이터 상태(2026-08-25) |
|---|---|---|---|
| 침수 | `train_flood_water_cpu.py`(기존, 경로만 수정) | LR-ASPP MobileNetV3 (BSD) | **준비됨** — 1,570장(보관소) |
| 교통위험 | `train_traffic_vehicle_yolo.py`(신규) | YOLO11s 검출 (AGPL) | **없음** — 라벨링 선행 필요 |
| 인파관리 | `train_crowd_person_frcnn.py`(신규) | Faster R-CNN (BSD) | **없음** — 라벨링 선행 필요 |
| 도로 노면 | `train_road_defect_yolo.py`(신규, 기존 3개 스크립트를 화면용으로 통합) | YOLOv8n 검출 (AGPL) | **준비됨** — RDD2022/SVRDD(보관소) |

### ★ 발견 — 기존 학습 스크립트 2종이 조용히 깨져 있었다

2026-08-14, 학습 데이터 약 14GB를 프로젝트 폴더에서
`D:\dev-PoC_DATA\`(보관소)로 옮겼다. 그런데 침수·도로 노면 학습 스크립트
3종(`train_flood_water_cpu.py`·`train_road_defect_prototype_v2.py`·
`train_svrdd.py`)은 **여전히 옛 프로젝트 폴더 경로를 하드코딩**하고
있었다 — 확인해 보니 그 경로들이 전부 빈 폴더였다. 이번 학습 화면을 만드는
과정에서 발견해, 프로젝트 폴더에 데이터가 있으면 그것을, 없으면 보관소를
자동으로 읽는 공용 모듈(`common/data_archive.py`)로 고쳤다. **사용자
확인: "보관소를 그대로 읽는다"** — 보관소 데이터를 프로젝트로 복사해
오지 않는다.

### 교통위험·인파관리는 왜 학습 데이터가 없는가

○ 교통위험 — 지금 운영 중인 차량검출은 COCO 사전학습 YOLO11s를
　파인튜닝 없이 그대로 쓴다(「4대 탐지 기능 기술 정리」§2-2)
○ 인파관리 — 지금 운영 중인 사람검출은 **mock(합성 궤적) 모드**이고,
　실제 검출기(torchvision Faster R-CNN)도 COCO 사전학습 그대로다(§2-3)

**사용자 확인(2026-08-25): "4개 전부 같은 구조로"** — 두 도메인도 화면·
스크립트·데이터 규칙을 다른 2개와 동일하게 만들어 두고, 라벨링된 데이터가
채워지면 코드 수정 없이 곧바로 학습이 가능하게 했다. 기대 경로는:

- 교통위험 — `data/datasets/traffic_vehicle_own/yolo/`(또는 보관소
  `D:\dev-PoC_DATA\07_학습데이터_교통\`)
- 인파관리 — `data/datasets/crowd_person_own/yolo/`(또는 보관소
  `D:\dev-PoC_DATA\08_학습데이터_인파\`)

두 경로 모두 **아직 존재하지 않는다** — 라벨링 작업이 먼저 필요하다.

### 왜 인파관리도 YOLO 형식 라벨을 쓰는가

실제 검출 모델은 torchvision Faster R-CNN이지만, **라벨링 형식**은
침수·도로 노면과 같은 YOLO 상자 텍스트(단일 클래스 person)로 통일했다.
학습 스크립트가 그 텍스트를 상자 좌표로 변환해서 쓸 뿐이다 — 라벨링
담당자가 도메인마다 다른 도구·형식을 새로 배우지 않아도 된다.

## 3. 새로 만든 DB 표 — `training_runs`

학습 실행마다 파라미터·상태·로그 경로·성능 지표를 남긴다. 4개 도메인이
평가 지표가 전부 달라(세그멘테이션 F1/IoU vs 객체검출 mAP50/precision/
recall) `metrics` 칼럼을 JSONB로 뒀다. 상세 설계는 DB 설계서 3-35절
(`docs/202608191140/db_design_spec.md`, v10) 참고.

⚠️ **학습 완료가 운영 반영을 뜻하지 않는다.** 학습이 끝나도 새 체크포인트가
자동으로 운영에 적용되지 않는다 — "AI 모델 운영·설정" 화면에서 관리자가
직접 골라야 한다. 화면에도 이 안내를 그대로 띄운다.

## 4. 안전장치

| 장치 | 이유 |
|---|---|
| **서브프로세스로 실행**(웹 서버 스레드가 아님) | 학습이 CPU를 몇 시간 점유한다. 별도 프로세스로 띄우면 관제 서비스와 스케줄링이 분리되고, 학습이 죽어도 관제 전체가 죽지 않는다 |
| **동시 1건 전역 제한**(도메인 무관) | GPU가 없다 — 두 학습을 동시에 돌리면 서로 느려질 뿐 빨라지지 않는다 |
| **데이터 없으면 시작 자체를 거부** | 데이터 없이 "학습했다"는 결과를 내면 안 된다 |
| **재기동 후 상태 정직하게 기록** | 서버가 재기동되면 실행 핸들을 잃어 정확한 종료 코드를 알 수 없다. 그때는 "결과를 알 수 없다"고 적지, 성공·실패를 추측해 단정하지 않는다 |
