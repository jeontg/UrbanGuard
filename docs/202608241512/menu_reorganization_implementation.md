## 1. 구현 내용

### 1-1. 대응·통보 통합

기존에 "대응"(시설물 원격제어 1항목만)과 "알림·통보"(승인 대기함·통보
이력 2항목) 두 묶음으로 나뉘어 있던 것을, 실제 업무 순서(조치 → 승인 →
확인)에 맞춰 하나의 묶음으로 합쳤습니다. 위치도 "이벤트" 묶음 바로 다음
— 사건을 발견한 직후 손이 가는 자리 — 로 옮겼습니다.

```
③ 대응·통보   시설물 원격제어(S-11) · 승인 대기함(S-50) · 통보 이력(S-51)
```

### 1-2. 설정·관리 6묶음 → 3묶음

8/24 오전 회차에서 "설정"(12항목)·"관리자"(6항목) 2개 묶음을 6개로
쪼갰으나(카메라·지점 관리/SOP 관리/AI 모델 관리/시스템·기관 관리/계정·
감사/오류·증거 관리), 헤더가 늘어난 만큼 세로 길이가 오히려 길어지는
문제가 있었습니다. 성격이 비슷한 것끼리 다시 3묶음으로 합쳤습니다.

```
⑨ 운영 설정    CCTV 관리(S-80·81) · 위험등급 관리(S-95) · 지점 방향 관리(S-96)
              상·하류 관리(S-97) · 디지털 SOP(S-86) · 위험유형별 SOP(S-98)
              AI 모델 운영(S-61) · AI 모델 설정 · 물 세그멘테이션(S-84)
              AI 모델 설정 · 침수 파이프라인(S-84)
⑩ 기록·감사    감사 로그(S-91) · 증거 영상 관리(S-88) · 영상 반출 관리대장(S-94)
⑪ 시스템 관리  사용자·권한 관리(S-90) · 오류 관리(S-92) · 오류 코드 사전(S-93)
              기관 정보·화면(S-85) · 서버 운영(S-87)
```

감사 로그를 "기록·감사"로 옮기면서, MGR(부서담당자)에게 "계정·감사"
묶음이 감사 로그 1개만 보이던 문제(제안서 §③ 최소주의 지적)도 함께
해소됐습니다 — MGR은 사용자·권한 관리 권한이 없어 계정 관련 항목이 아예
없기 때문입니다.
