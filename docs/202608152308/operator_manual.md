## 1. 시작하기

### 1-1. 접속

브라우저에서 관제 서버 주소로 접속하면 로그인 화면이 나옵니다.

> **⚠️ 비밀번호를 5회 틀리면 10분간 잠깁니다.** 잠기면 시스템관리자에게
> 비밀번호 재발급을 요청하십시오.

### 1-2. 최초 로그인 — 비밀번호 변경

계정을 처음 받으면 **임시 비밀번호**입니다. 로그인하면 비밀번호 변경 화면이
뜨고, **바꾸기 전에는 다른 화면으로 갈 수 없습니다.**

비밀번호 규칙
- 9자 이상
- 영문 대문자·소문자·숫자·특수문자 중 **3종류 이상**

### 1-3. 내 권한 확인

화면 오른쪽 위에 이름과 역할이 표시됩니다. 역할에 따라 **보이는 메뉴가
다릅니다.** 권한이 없는 메뉴는 비활성이 아니라 **아예 나오지 않습니다.**

| 역할 | 할 수 있는 일 |
|---|---|
| **관제요원 (OPR)** | 전 도메인 관제, 탐지 실행, 알림 **요청** |
| **부서담당자 (MGR)** | 담당 도메인 관제·설정, 알림 **발송**, 시설물 제어 |
| **시스템관리자 (SYS)** | 전 기능 + 계정 관리 + 시스템 설정 |

> **관제요원은 주민 경보를 직접 보낼 수 없습니다.** 요청만 가능하며 다른
> 사람이 승인해야 발송됩니다. 야간 1인 근무 시 단독 발송을 막기 위한 장치입니다.

## 3. 일상 관제 업무

### 3-1. 통합 상황판 (S-01)

근무 시작 시 처음 보는 화면입니다. 세 도메인의 현재 상태를 한눈에 보여줍니다.

확인 순서
1. **위험 등급이 올라간 지점**이 있는가
2. **처리하지 않은 이벤트**가 있는가
3. **승인 대기 중인 알림**이 있는가

> **⚠️ 화면 수치가 실제 분석 결과인지 확인하십시오.** 인파 검출이 모의(mock)
> 상태면 화면에 경고가 뜹니다. **그 상태의 인원 수는 실제 영상값이 아닙니다.**

### 3-2. 이벤트 처리 (S-02 · S-03)

이벤트는 「사건」 단위입니다. 같은 지점에서 위험이 이어지면 **새로 만들지 않고
갱신**되므로 목록이 도배되지 않습니다.

처리 흐름

```
 [발생]  탐지가 이벤트를 만듦
    ↓
 [확인]  관제요원이 열어 보고 담당 지정
    ↓
 [조치]  현장 확인 · 시설물 제어 · 알림 요청
    ↓
 [종결]  처리 완료 또는 오탐 표시
```

**등급이 내려가도 최고 등급(`peak_level`)은 남습니다.** 위험이 지나간 뒤에도
그 사건이 얼마나 심각했는지 알 수 있어야 사후 보고가 가능하기 때문입니다.

**오탐이라고 판단되면 반드시 「오탐」으로 표시하십시오.** 모델 개선의 근거가
됩니다.

### 3-3. 인파 선택 탐지 (S-30)

인파관리 화면 맨 위 「CCTV 선택 탐지」에서 지점을 골라 실행합니다.

1. 지점 선택
2. **「▶ 분석 실행」** 클릭
3. **30초 관측** — 남은 시간이 카운트다운으로 표시됩니다
4. 결과 확인

> **⚠️ 30초 동안 화면이 멈춘 것처럼 보여도 새로고침하지 마십시오.**
> 버튼에 남은 초가 표시됩니다.

**결과 읽는 법**

| 항목 | 의미 |
|---|---|
| 인원 최대·평균 | 관측 구간의 값 |
| 밀집지수 최대 | 격자 기준 밀집도 |
| 위험등급 | **관측 구간에서 가장 위험했던 순간**의 등급 |
| 탐지된 위험행동 | 배회·침입 |
| 관측 마지막 화면 | **사람 영역이 가려진 상태**로 표시 |

> **⚠️ 「침입 구역 미설정」 표시가 있으면 침입은 탐지되지 않습니다.**
> 밀집도·배회만 분석됩니다. ROI 설정이 필요합니다(5-3절).

> **⚠️ 관측 30초에 분석 프레임이 5장 정도로 적습니다.** 검출이 느려 표본이
> 얇습니다. **단독 근거로 삼지 말고 영상을 함께 확인하십시오.**

**동시에 두 곳을 분석할 수 없습니다.** 다른 사람이 실행 중이면 안내가 뜹니다.

### 3-4-B. ★ 노면 실시간 관제 (S-44) — 2026-08-13 신규

노면 탭 맨 위에 있습니다. **상시 순회가 지금 어디를 보고 있는지**와 **각 지점의
결과가 얼마나 오래된 것인지**를 보여 줍니다.

```
 실시간 관제  [상시 순회 동작 중]  대상 8개소 · 지점당 15분 주기 · 12회차
 ● 3/8 올림픽교차로 관측 중   7초 경과
```

| 표시 | 뜻 |
|---|---|
| `3/8 … 관측 중` | 이번 바퀴에서 세 번째 지점을 보는 중 |
| `대기 중 · 다음 순회까지 12분` | 한 바퀴를 마치고 쉬는 중 |
| **「갱신 지연」** 배지 | 기대 주기의 2배를 넘겨 **실제로 관측되지 않고 있음** |
| **「반영 대기」** 배지 | S-80에서 방금 「상시」로 바꿨고 아직 순회 목록에 안 들어감 |
| **「관측 중」** 배지 | 지금 이 지점을 보는 중 |

> **⚠️ 「상시」 배지만 보고 관측 중이라고 읽지 마십시오.** 「반영 대기」나
> 「갱신 지연」이 붙어 있으면 그 지점은 지금 아무도 보고 있지 않습니다.

#### 집중 감시 — 급한 지점을 짧은 주기로

상시 순회는 15분 주기라 **결빙·낙하물·사고 잔해**처럼 분 단위로 변하는 상황에는
늦습니다. 지점 카드의 **「◉ 집중 감시」**를 누르면 그 지점만 **60초 주기**로
반복 관측하고, 라이브 영상이 함께 표시됩니다.

- **한 번에 한 지점만** 됩니다(분석기가 하나뿐이라 여럿을 돌리면 상시 순회가 굶습니다)
- 다른 지점을 켜면 이전 감시는 자동으로 멈춥니다
- **30분이 지나면 스스로 멈춥니다** — 켜 두고 잊는 것을 막기 위해서입니다
- S-80에서 그 지점의 노면 사용을 끄면 감시도 함께 멈춥니다

#### 학습 데이터 자동 수집 (시스템관리자만)

같은 화면에 있습니다. **기본은 꺼져 있고, 켜는 것은 개인정보 검토를 마친 뒤의
결정입니다.**

| 켜면 | 내용 |
|---|---|
| 무엇을 | 상시 순회가 관측한 프레임 일부를 디스크에 저장 |
| 얼마나 | 지점당 하루 8장 · 같은 지점 최소 30분 간격 · 총 2GB까지 |
| 사람은 | **자동으로 가립니다.** 가리지 못한 프레임은 저장하지 않습니다 |
| 차량번호판은 | ⚠️ **가리지 못합니다** |

**「가진 영상에서 프레임 뽑기」**로 담당자가 촬영한 영상을 넣을 수도 있습니다.
**원본 영상은 보관하지 않고 프레임만 남깁니다.** 60장 기준 1~2분 걸립니다.

> **⚠️ 수집한 프레임을 외부로 보내기 전에는 반드시 확인하십시오.**
> 차량번호판이 가려지지 않은 상태입니다.

### 3-4. 노면 현황과 AI 탐지 (S-40 · S-41)

**노면 현황(S-40)에는 S-80에서 「도로 노면 관리」로 지정한 CCTV만 나옵니다.**

지점 카드를 누르면 **오른쪽에 그 지점의 탐지 결과**가 표시됩니다.

| 표시 | 뜻 |
|---|---|
| **미분석** | 아직 본 적이 없습니다 |
| **분석 실패** | 시도했으나 **영상을 받지 못했습니다** |
| 정상·주의·경계 | 실제로 분석한 결과입니다 |

> **⚠️ 「분석 실패」와 「정상」을 혼동하지 마십시오.** 실패는 아무것도 못 본
> 것이고, 정상은 보았는데 손상이 없었다는 뜻입니다.

**분석 실행**은 두 곳에서 됩니다.

1. **노면 현황 카드의 「▶ 분석 실행」** — 보고 있는 지점을 바로 분석 (권장)
2. **「AI 손상 탐지 실행」(S-41)** — 모드를 골라 실행

| 모드 | 설명 | 소요 |
|---|---|---|
| 기존 영상 | 파일 전체에서 12장 표본 | 수십 초 |
| 실시간 CCTV | **15초 관측** | 20~30초 |

**동영상으로 등록한 지점도 실시간 모드로 분석됩니다** — 스트림이 없으면 등록된
파일을 읽습니다.

> **⚠️ 「연결이 거부되었습니다」가 뜨면** 같은 카메라를 침수·인파가 상시로 보고
> 있어 동시 접속이 막힌 것입니다. 잠시 뒤 다시 시도하거나, 시스템관리자에게
> **상시 지정을 줄여 달라고** 요청하십시오.

> ### ⚠️ 노면 탐지 결과를 그대로 믿지 마십시오 (2026-08-13 시험 결과)
> 현재 모델은 **부산 교통 CCTV(240p)에서 실사용 수준이 아닙니다.**
>
> - 예전 모델은 **탐지 0건**이었습니다 — 0건이 「손상 없음」이 아닙니다
> - 새 모델(SVRDD)은 탐지가 나오지만 **전부 차선 도색을 균열로 읽은 오탐**이었습니다
>
> **어느 쪽이든 육안 확인이 필요합니다.** 탐지 결과를 그대로 보수 지시로 쓰지
> 마십시오. 지금은 **「점검할 지점을 좁히는 참고 자료」**로만 쓰는 것이 맞습니다.

> **⚠️ 분석 결과는 서비스를 재시작하면 「미분석」로 돌아갑니다.** 손상이 잡힌
> 건은 이벤트 목록에 남습니다.

### 3-5. 현장 제보 확인 (S-43)

시민·직원이 올린 제보를 확인하고 처리합니다.

> ### ⚠️ 사진 확인 시 반드시 알아 두십시오
> **사람은 자동으로 가려지지만 차량번호판은 가려지지 않습니다.**
> 전용 모델이 없어 **육안으로 확인**해야 합니다. 번호판이 보이면 외부로
> 공유하지 마시고 담당자에게 알리십시오.

마스킹에 실패한 사진은 화면에 경고가 표시됩니다. 그 상태의 사진은 개인정보가
그대로 담겨 있을 수 있으니 취급에 주의하십시오.

## 4. 대응 업무

### 4-1. 알림 요청과 승인 (S-50)

#### 요청 (누구나 가능)

이벤트 상세에서 통보를 요청합니다. 대상은 세 가지입니다.

| 계층 | 대상 |
|---|---|
| 내부 | 관련 부서 |
| 기관 | 112·119·재난상황실 |
| **주민** | **문자·알림톡** |

#### 승인 (요청자 본인은 불가)

> ### ★ 주민 경보는 2인 승인입니다
> **요청한 사람은 자기 요청을 승인할 수 없습니다. 역할과 무관합니다.**
> 시스템관리자도 자기가 요청한 건은 승인하지 못합니다.

승인 대기함에서 내용을 확인하고 승인 또는 반려합니다. 반려 시 사유를 남기십시오.

#### 「심각」 단계 단독 발송

급박해서 승인자를 기다릴 수 없을 때만 사용합니다.
**사후 승인 대상으로 표시되고 감사 로그에 남습니다.** 남용하지 마십시오.

> **⚠️ 기관 통보(112·119·재난상황실)는 요청까지만 기록됩니다.**
> 시스템이 자동으로 전송하지 않습니다. **기존 절차(유선 등)로 직접
> 처리하셔야 합니다.** 시스템에는 요청 사실과 승인 이력만 남습니다.

### 4-2. 시설물 원격제어 (S-11)

세 가지 모드가 있습니다.

| 모드 | 동작 |
|---|---|
| **권고만** | 「무엇을 해야 하는지」만 표시. **제어하지 않음** |
| 원격요청 | 담당자 확인 후 명령 전송 |
| 자동 | 조건 충족 시 자동 제어 |

> **기본값은 「권고만」입니다.** 차단기·경보기 오작동은 사람이 다칠 수
> 있습니다. **모드 변경은 시스템관리자만 가능합니다.**

## 5. CCTV 관리 (S-80 · S-81) ★

설정 권한(MGR·SYS)이 있어야 합니다.

### 5-1. CCTV 등록

「+ CCTV 등록」을 펼치고 입력합니다.

| 항목 | 설명 |
|---|---|
| **ID** | `CAM-SEOMYEON` 형태. **대문자로 시작, 나중에 바꿀 수 없음** |
| 이름 | 서면교차로 |

### 5-1-B. 여러 지점을 한꺼번에 등록하기

「⇪ 일괄 등록 · 내려받기」를 펼치면 세 가지가 있습니다.

| # | 기능 | 쓰임 |
|---|---|---|
| ① | **교통 CCTV 자동 수집** | 지역을 골라 교통정보센터에서 목록을 받습니다 |
| ② | **엑셀로 일괄 등록** | 양식을 받아 작성한 뒤 올립니다 |
| ③ | **현재 목록 내려받기** | 등록된 전체를 엑셀로 받습니다 |

**②와 ③은 열이 같습니다.** 받아서 고친 뒤 그대로 다시 올리는 것이 가장
빠른 편집 방법입니다.

**올리면 바로 등록되지 않습니다.** 먼저 미리보기가 나옵니다.

| 상태 | 뜻 |
|---|---|
| **신규** | 처음 보는 ID — 등록됩니다 |
| **기존** | 이미 있는 ID — **기본적으로 건너뜁니다** |
| **오류** | 값이 잘못됨 — 사유가 표시되고 등록되지 않습니다 |

기존 지점을 덮어쓰려면 **「이미 등록된 ID는 내용을 덮어씁니다」를 체크**해야
합니다. 체크하지 않으면 운영 중인 설정이 지워지지 않습니다.

> **⚠️ ①은 API 키가 있어야 합니다.** 없으면 버튼이 잠기고 안내가 뜹니다.
> **방범 CCTV는 이 방법으로 받을 수 없습니다** — 지자체 통합관제센터
> 전용망으로만 흐르며 외부 제공 창구가 없습니다.

### 5-1-C. 동영상 파일 올리기

CCTV 등록·수정 화면에서 **「동영상 파일 올리기」**로 파일을 직접 올릴 수
있습니다. 올리면 소스 종류가 「동영상 파일」로 바뀌고 경로가 자동으로
채워집니다.

- mp4 · avi · mov · mkv · webm · **최대 500MB**
- **한 지점에 한 편만** 남습니다 — 다시 올리면 이전 것이 지워집니다
- 등록이 실패하면 파일도 저장되지 않습니다

### 5-2. 탐지서비스 지정 — 3단계

「탐지 지정」 버튼을 누르면 세 서비스가 나옵니다.

```
 ☑ 침수·교통위험
     ☑ 상시 탐지
 ☑ 인파관리
     ☐ 상시 탐지
 ☐ 도로 노면 관리
     ☐ 상시 탐지
```

| 단계 | 의미 |
|---|---|
| **① 서비스 체크** | 이 서비스가 이 지점을 **쓴다** |
| **② 상시 탐지 체크** | 요청 없이도 **계속 본다** |

**서비스만 체크하고 상시를 끄면** 「선택 탐지」입니다 — 관제요원이 화면에서
지점을 골라 실행할 때만 분석합니다.

#### 도메인별 상시 탐지 주기

| 도메인 | 주기 |
|---|---|
| 침수 | 연속 (초당 약 5회) |
| 인파 | 지점당 5초 간격 |
| 노면 | 지점당 15분 |

> ### ⚠️ 상시 탐지를 바꾸면 서비스를 재시작해야 반영됩니다
> 분석 중인 프로그램을 실행 중에 바꾸면 추적 상태가 어긋나기 때문입니다.
> 저장 후 화면에 안내가 뜹니다. **시스템관리자에게 재시작을 요청하십시오.**

> ### ⚠️ 상시로 켠 지점 수만큼 서버가 힘들어집니다
> 특히 인파는 지점마다 별도 처리가 붙습니다. **여러 곳을 한꺼번에 켜지 마시고,
> 늘릴 때마다 서버 상태를 확인**하십시오.

### 5-3. ROI 설정 (S-81)

ROI는 **「영상의 어느 부분을 볼 것인가」**입니다. 서비스마다 보는 곳이 다르므로
**도메인 탭으로 나뉘어 있습니다.**

| 도메인 | 영역 | 필수 |
|---|---|---|
| 침수 | **도로 ROI** | **✅ 필수** |
| | 저지대 ROI | 선택 |
| | 차선 기준선 | 선택 |
| 인파 | **분석 영역 (보행 구역)** | 선택 |
| 인파 | 침입 금지 구역 | 선택 |
| 인파 | **배회 감시 구역** | 선택 |
| 노면 | 노면 분석 구간 | 선택 |

**그리는 방법**

1. 도메인 탭 선택
2. 「영역 종류」 선택
3. 영상을 클릭해 꼭짓점 찍기
4. **「다각형 닫기」**로 영역 완성 (선은 점 2개)
5. **「저장」**

> **⚠️ 침수는 도로 ROI가 없으면 저장되지 않습니다.** 물이 어디에 찼는지
> 판단할 기준면이 없기 때문입니다.

**인파 영역 세 가지의 쓰임**

| 영역 | 안 그리면 | 그리면 |
|---|---|---|
| 분석 영역 | 화면 전체에서 인원·밀집도 계산 | **보행 구역만** 계산 — 차도가 빠져 정확해짐 |
| 침입 금지 구역 | 침입을 탐지하지 않음 | 이 안에 들어오면 탐지 |
| 배회 감시 구역 | 화면 전체에서 배회 판정 | 이 안에 선 사람만 — 정류장 대기줄 오탐이 줄어듦 |

> **⚠️ 정지영상이 안 나오면** 소스에 문제가 있는 것입니다. 화면이 사유를
> 알려 줍니다 — 동영상은 파일 경로, HLS는 주소와 네트워크를 확인하십시오.
> (상시 탐지가 꺼져 있어도 이제 정지영상은 나옵니다.)

> **⚠️ ROI 저장도 재시작해야 탐지에 반영됩니다.**

### 5-4. CCTV 삭제

삭제하면 **탐지서비스 지정과 ROI가 함께 사라집니다.**
**과거 이벤트는 남습니다** — 사건 기록은 지점이 없어져도 보존됩니다.

> 폐지 지점은 삭제 대신 **「사용 안 함」**으로 내리는 것을 권고합니다.

## 5-4-B. ★ 지점별 보정 (S-80) — 2026-08-15 신규

**국내외 안전 기준은 전부 물리 단위**입니다 — 침수심 cm, 명/㎡, 구간 단위.
그런데 CCTV 화면에서 바로 알 수 있는 것은 면적 비율(%)·개수뿐입니다.
그 사이를 잇는 것이 **보정**입니다.

CCTV 목록의 각 행에서 **「보정」** 버튼을 누르십시오. 옆에 **완료 / 미보정**
배지가 붙어 있습니다.

### 무엇을 넣나

| 도메인 | 넣는 값 | 현장에서 하는 일 | 나오는 것 |
|---|---|---|---|
| **노면** | 담당 구간 길이(m) | **대장에서 확인** — 실측 불필요 | 건/100m |
| **인파** | 화면 4점 ↔ 실제 4점(m) | 횡단보도·보도블록 등 **직사각형 하나만 실측** | 명/㎡ |
| **침수** | [면적비, 침수심cm] 2점 이상 | 화면 안에 **수위표를 세우고** 물이 찰 때 기록 | 추정 침수심(cm) |

### 가장 쉬운 것부터

1. **노면 구간 길이** — 도로대장에 이미 있는 값입니다. 숫자 하나만 넣으면
   됩니다. 넣는 순간 「탐지 3건」이 「100m당 2건」으로 바뀌어 **지점끼리
   비교**가 됩니다. 개수만으로는 긴 구간이 항상 나빠 보입니다.
2. **인파 지면 보정** — 화면에 보이는 직사각형(횡단보도 등) 네 모서리의
   화면 좌표와 실제 크기를 넣습니다. **추가 장비가 필요 없습니다.**
   넣으면 국내외 기준(주의 3명/㎡ · 경계 4명 · 심각 5명)에 바로 연결됩니다.
3. **침수심 대응표** — 수위표 설치가 먼저입니다. 설치 후 비가 올 때
   「면적비 얼마일 때 눈금 몇 cm」를 몇 번 기록하면 만들어집니다.

### 좌표는 어떻게 넣나

`[[x1,y1],[x2,y2],[x3,y3],[x4,y4]]` 형식입니다. 화면 좌표는 왼쪽 위가
`[0,0]` 이고, 실제 좌표는 **미터** 단위로 같은 순서로 적습니다.

> 예 — 화면의 (100,300)~(500,300)~(520,420)~(80,420) 사각형이 실제로
> 가로 6m · 세로 4m 라면
> * 화면 좌표 `[[100,300],[500,300],[520,420],[80,420]]`
> * 실제 좌표 `[[0,0],[6,0],[6,4],[0,4]]`

### ⚠️ 보정하지 않으면 「미보정」으로 나옵니다

**0 이나 대충 계산한 값을 보여 주지 않습니다.** 보정 안 된 지점의
「3.2명/㎡」가 보정된 것처럼 보이면 그 화면을 믿을 수 없게 되기 때문입니다.

침수는 **관측 범위를 넘으면 「범위 초과」**로 표시됩니다. 대응표에 없는
깊이는 추정하지 않고 마지막 관측값에 묶으므로, **그 값을 그대로 믿으면
안 됩니다** — 더 깊을 수 있습니다.

### 잘못 넣으면 저장되지 않습니다

네 점이 아니거나, 세 점이 일직선이거나, 면적비가 0~1을 벗어나거나,
구간 길이가 10km를 넘으면 **사유와 함께 되돌려 줍니다.** 저장된 뒤에
발견하면 이미 늦기 때문입니다.

## 5-5. 로고·솔루션명 바꾸기 (S-85) — 시스템관리자

「설정 › 기관 정보·화면」에서 화면에 보이는 이름과 로고를 바꿉니다.

| 항목 | 어디에 나오는가 |
|---|---|
| **기관명** | 가운데 상단 · 로그인 화면 · 보고서 |
| **솔루션명** | 기관명 뒤에 이어져 표시 |
| **로고** | **좌측 상단** · 로그인 화면 |

**로고 크기가 화면에 표시됩니다** — `크기 (556px, 116px)` 형태입니다.
파일을 고르면 올리기 전에 그 파일의 크기로 바뀌므로, 잘못 고른 것을 바로
알 수 있습니다.

- 권장 크기 **(408px, 88px)** 이상 · PNG·JPG·WEBP · 최대 2MB
- 가로로 긴 형태(약 4.7 : 1)가 사이드바에 잘 맞습니다
- **배경이 비치는 PNG**를 쓰면 배경색을 바꿔도 자연스럽습니다

> **⚠️ 업로드 로고는 한 장만 쓰입니다.** 기본 로고처럼 배경 밝기에 따라
> 밝은판·어두운판이 자동으로 갈리지 않습니다. 미리보기에서 현재 배경과의
> 대비를 확인하십시오.

「기본 로고로 되돌리기」로 언제든 UrbanGuard 로고로 복귀할 수 있습니다.

## 5-6. ★ AI 모델 운영 (S-61) — 시스템관리자 · 2026-08-15 확장

화면이 세 부분입니다.

### 5-6-1. 운영 모델 지정

**상시 탐지가 실제로 쓸 모델**을 정합니다. 반영 시점이 도메인마다 다르고,
화면이 그 차이를 그대로 알려 줍니다.

| 도메인 | 반영 |
|---|---|
| **노면** | **저장 즉시** — 다음 순회부터 새 모델 |
| 침수 · 인파 | ⚠️ **저장만 되고, 서비스를 재기동해야 실제로 바뀝니다** |

> 재기동이 필요한데 「저장했습니다」로만 끝내면 **바뀐 줄 알고 관제하게**
> 됩니다. 그래서 화면에 붉은 글씨로 적어 두었습니다.

**비고**는 운영자가 적는 자리입니다. 「부산 CCTV 실사용 불가」 같은 판단은
파일이나 통계에서 자동으로 나오지 않습니다.

### 5-6-2. 모델 시험 탐지

**모델을 골라 실제 지점에 대 봅니다.** 같은 지점에 모델을 바꿔 가며 대 보면
어느 쪽이 나은지 눈으로 비교할 수 있습니다.

| 고르는 것 | 설명 |
|---|---|
| 모델 | 디스크에서 자동으로 찾은 후보 (보관소의 학습 결과 포함) |
| 대상 지점 | 실시간 CCTV 또는 등록 동영상 |
| 관측(초) | 1~30초. 그만큼 기다려야 결과가 나옵니다 |
| 임계값 | 낮출수록 더 민감해집니다 |

결과에 **미리보기 화면**이 함께 나옵니다. 탐지 상자가 그려진 실제 화면입니다.

> ### ⚠️ 시험은 운영을 건드리지 않습니다
> 결과는 **이벤트·노면 현황에 기록되지 않고**, 여기서 고른 모델이 **상시
> 탐지에 반영되지도 않습니다.** 운영에 적용하려면 위의 「운영 모델 지정」을
> 쓰십시오.

> ### 탐지 0건일 때 미리보기를 꼭 보십시오
> **「손상이 없다」와 「도로가 제대로 안 나온다」는 다릅니다.** 부산 CCTV는
> 각도에 따라 노면이 거의 안 잡히는 지점이 있고, 그럴 때 0건은 「이상 없음」이
> 아니라 「볼 수 없었음」입니다.

한 번에 하나만 돕니다. 다른 시험이 도는 중이면 버튼이 잠깁니다.

### 5-6-3. 모델 현황 표

| 상태 | 뜻 |
|---|---|
| **모델 없음** | 지정된 파일이 없습니다. **탐지가 아예 안 됩니다** |
| **탐지 실적 없음** | 모델은 도는데 아직 한 건도 못 잡았습니다 |
| **운영중** | 탐지 실적이 있습니다 |

> **「탐지 실적 없음」은 평온해서 잡을 것이 없는 경우와 구분되지 않습니다.**
> 그래서 「운영중」이라고 부르지 않습니다.

**오탐률은 관제요원이 신고한 건수 기준**입니다. 신고가 적으면 오탐이 적은 것이
아니라 **아직 모르는 것**일 수 있습니다.

## 6. 계정 관리 (S-90) — 시스템관리자

### 6-1. 계정 생성

| 항목 | 설명 |
|---|---|
| 아이디·성명·부서 | |
| 역할 | SYS / MGR / OPR |
| **담당 도메인** | **MGR에만 의미가 있습니다** |

> **관제요원(OPR)은 담당 도메인을 지정해도 전 도메인을 봅니다.** 상황실에서
> 세 가지를 모두 봐야 하기 때문입니다. 도메인 제한은 부서담당자에게만
> 적용됩니다.

**임시 비밀번호가 한 번만 표시됩니다.** 본인에게 안전하게 전달하십시오.

### 6-1-B. ★ 「로그인이 안 된다」는 문의를 받으면 (2026-08-15 신설)

**먼저 S-90 목록에서 그 계정의 상태 배지를 보십시오.** 원인이 갈립니다.

| 배지 | 뜻 | 조치 |
|---|---|---|
| **잠김** + 「실패 N회」 | 비밀번호를 여러 번 틀림 | **「잠금 해제」** — 비밀번호는 그대로 둡니다 |
| **임시 비밀번호** | 발급받고 아직 안 바꿈 | 비밀번호 변경 화면에서 바꾸도록 안내 |
| **비활성** | 사용 안 함으로 내려둠 | 「활성화」 |
| 아무 배지 없음 | 계정은 정상 | 비밀번호를 잊었다면 **「비밀번호 초기화」** |

> ### ⚠️ 잠금 해제와 비밀번호 초기화는 다릅니다
> 잠김의 대부분은 **단순 오타**입니다. 초기화하면 그 사람이 기억하고 있던
> 멀쩡한 비밀번호까지 버리게 되고, 새 임시 비밀번호를 다시 전달해야 합니다.
> **잠금만 풀면 원래 비밀번호로 바로 들어갈 수 있습니다.**

**초기화하면 잠금도 함께 풀립니다** — 새 비밀번호를 줬는데 잠겨 있으면 여전히
못 들어오기 때문입니다.

> ### 시스템관리자 본인이 못 들어가는 경우
> 화면으로는 방법이 없습니다. **정보통신 부서에 서버에서
> `urbanguard-passwd` 실행을 요청**하십시오(설치 가이드 2-6-B절).
> 그 실행은 감사 로그에 「서버 CLI」로 남습니다.

### 6-2. 퇴직·전보 처리

**계정을 삭제하지 말고 「사용 안 함」으로 내리십시오.**
삭제해도 감사 기록은 남지만, 비활성화가 더 안전합니다.

### 6-3. 감사 로그 (S-91)

| 역할 | 볼 수 있는 범위 |
|---|---|
| SYS | 전체 |
| MGR | **본인 부서만** |
| OPR | 접근 불가 |

기록되는 것 — 로그인·계정변경·**알림 요청/승인/발송**·설정변경·탐지실행·보고서
출력·**계정 잠금해제**·**오류 이력 삭제**

### 6-4. ★ 오류 관리 (S-92) — 2026-08-15 신설

**서비스에서 실제로 난 오류**가 모입니다. 화면·API 오류뿐 아니라
**상시 탐지 워처의 오류까지** 들어옵니다 — 화면에 안 보이는 고장이 여기서
드러납니다.

#### 화면 보는 법

| 영역 | 내용 |
|---|---|
| 위쪽 요약 | 미처리 **심각** 건수 · 미처리 전체 · 총 발생 횟수 · 가장 많이 난 오류 |
| 검색 | 검색어·분류·심각도·발생위치·처리여부·기간 |
| 목록 | 최근 발생 · 코드 · 심각도 · 오류명 · 위치 · **횟수** · 상태 |

**오류명을 누르면 펼쳐집니다.** 원인과 해결방법, 전체 메시지, 개발 부서 전달용
상세가 나옵니다.

> ### 「횟수」가 큰 것이 반드시 더 급한 것은 아닙니다
> 같은 오류는 한 줄로 묶여 횟수만 올라갑니다. CCTV 재접속 실패는 정상 상황에서도
> 초당 여러 번 날 수 있습니다. **심각도와 「미처리 심각」 요약을 먼저** 보십시오.

#### 조치 기록

해결했으면 **「처리완료로 표시」** 하고, **무엇을 해서 해결했는지 적어
두십시오.** 다음에 같은 오류를 만난 사람이 그 메모를 봅니다.

처리완료로 표시한 뒤 같은 오류가 또 나면 **새 줄로 생깁니다** — 조치했는데 또
났다는 사실이 가려지면 안 되기 때문입니다.

#### 삭제

**되돌릴 수 없습니다.** 지운 사실과 내용은 감사 로그(S-91)에 남습니다.
일괄 정리는 기본이 「처리완료 건 중 N일 이전」이며, 아직 조치하지 않은 오류까지
한 번에 날아가지 않도록 한 안전장치입니다.

### 6-5. ★ 오류 코드 사전 (S-93) — 2026-08-15 신설

**코드마다 원인과 해결방법을 기르는 곳**입니다. 여기 적어 둔 내용이 S-92 목록에
그대로 표시됩니다.

**현장에서 알아낸 조치 방법을 반드시 적어 두십시오.** 그것이 이 화면의 존재
이유입니다. 다시 배포해도 적어 둔 내용은 유지됩니다.

| 구분 | 삭제 |
|---|---|
| **기본** (제품 제공, 28종) | ❌ 불가 — 지워도 그 코드로 오류는 계속 쌓이고 설명만 사라집니다. 감추려면 「사용 안 함」 |
| **직접 등록** | ✅ 가능 |

`UG-SYS-001`(분류되지 않은 오류)로 같은 오류가 반복해서 쌓이면, **전용 코드를
등록하고 원인·해결방법을 적어 두십시오.**

## 7. 자주 묻는 상황

| 상황 | 확인 |
|---|---|
| 인원 수가 이상하다 | 화면에 **모의(mock) 경고**가 있는지 확인. 있으면 실제 값이 아님 |
| 노면 탐지가 항상 0건 | **모델 한계입니다.** 0건이 「손상 없음」이 아님 |
| **노면에 「균열」이 떴는데 차선이다** | **오탐입니다.** 240p 에서는 차선 도색과 균열이 구분되지 않습니다(2026-08-13 확인). 탐지 결과를 그대로 보수 지시로 쓰지 마십시오 |
| **「반영 대기」가 오래 간다** | 진행 중인 관측(15초)이 끝나면 잡힙니다. 1분 넘게 그대로면 순회가 멈춘 것이니 관리자에게 알리세요 |
| **집중 감시가 저절로 꺼졌다** | 30분 시한이거나, S-80에서 그 지점의 노면 사용이 꺼진 것입니다 |
| 상시 탐지를 켰는데 안 돎 | **재시작했습니까?** 「사용」과 「상시」가 둘 다 체크됐습니까? |
| ROI 화면에 영상이 없다 | 상시 탐지가 꺼져 있으면 영상이 들어오지 않습니다 |
| 분석 실행이 안 눌린다 | 다른 사람이 실행 중일 수 있습니다 |
| 내 요청을 내가 승인 못 한다 | **정상입니다.** 2인 승인 규칙 |
| 메뉴가 안 보인다 | 권한이 없는 메뉴는 표시되지 않습니다 |
| 노면 분석이 「연결 거부」 | 같은 카메라를 다른 서비스가 상시로 봄. 상시 지정을 줄이세요 |
| 노면 결과가 사라졌다 | 재시작하면 「미분석」로 돌아갑니다. 이벤트는 남습니다 |
| 엑셀 업로드가 안 된다 | 양식을 받아 쓰셨습니까? 머리글이 다르면 거부됩니다 |
| 교통 CCTV 수집 버튼이 잠김 | API 키 미발급 — 시스템관리자에게 문의 |
| 로그인이 자꾸 풀린다 | 시스템관리자에게 문의 (서명 키 설정 문제일 수 있음) |

## 8. ⚠️ 현재 시스템의 한계 (반드시 숙지)

| # | 한계 | 운영 시 유의 |
|---|---|---|
| 1 | **인파 검출이 모의 데이터** | 인원·위험행동 수치를 **판단 근거로 쓰지 마십시오** |
| 2 | **노면 모델이 부산 CCTV에서 탐지 0건** | 육안 확인을 병행하십시오 |
| 3 | **차량번호판 미마스킹** | 제보 사진 취급 주의 |
| 4 | **기관 통보가 자동 전송되지 않음** | 기존 절차로 직접 처리 |
| 5 | **상시 탐지 변경에 재시작 필요** | 관제 중 변경을 피하십시오 |
| 6 | 인파 관측 표본이 얇음(30초에 5장) | 영상 확인 병행 |
| 7 | **HTTPS 미적용** (개발 환경) | 관제망 외부에서 접속하지 마십시오 |
| 8 | **노면 결과가 재시작 시 사라짐** | 중요한 점검은 이벤트로 남기십시오 |
| 9 | **업로드 동영상은 마스킹하지 않습니다** | 개인정보가 담긴 영상 취급 주의 |
| 10 | 한 카메라에 여러 도메인 상시 지정 시 충돌 | 상시는 꼭 필요한 곳만 |
