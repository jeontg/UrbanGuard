## 1. 요청과 설계의 차이

| 요청 | 구현 | 왜 |
|---|---|---|
| 운영체제 선택 | 운영체제 **+ 재기동 방식** 선택 | OS만으로는 재기동 동작이 결정되지 않음 |

**운영체제는** 「어떤 방식을 고를 수 있는가」와 안내문·로그 위치를 정합니다.
**실제 동작은 감시 방식이** 정합니다.

| 운영체제 | 고를 수 있는 재기동 방식 |
|---|---|
| **리눅스** | systemd 서비스 · 감시 스크립트(serve.py) · 없음 |
| **윈도우** | 윈도우 서비스(NSSM) · 감시 스크립트(serve.py) · 없음 |

맞지 않는 조합(리눅스 + 윈도우 서비스)은 **화면에서 고를 수 없고, 서버에서도
거부**합니다. 화면이 막아도 요청은 직접 보낼 수 있기 때문입니다.

---

## 2. 재기동 동작은 어느 OS에서든 같습니다

서비스가 **종료 코드 42**로 스스로 죽고, 지켜보던 쪽이 다시 띄웁니다.

| 방식 | 되살리는 주체 | 필요한 설정 |
|---|---|---|
| systemd | `Restart=always` | `RestartPreventExitStatus`에 42를 넣으면 **안 됨** |
| 윈도우 서비스 (NSSM) | 기본 동작이 종료 시 재시작 | `nssm set <이름> AppExit Default Restart` |
| 감시 스크립트 | 코드 42를 「운영자 요청」으로 인식 | 없음 (기본 동작) |

### `systemctl restart`를 제품이 직접 실행하지 않는 이유

- **자기 자신을 죽이는 명령**이라 중간에 프로세스가 사라져 결과를 알 수 없습니다
- **권한 상승(sudo·polkit)** 이 필요해, 관제 서비스 계정에 그 권한을 줘야 합니다

종료 코드로 넘기면 추가 권한이 필요 없습니다.

## 3. 「모르겠다」와 「아니다」를 구분했습니다

이것이 이 작업의 핵심 판단입니다.

| 방식 | 감지 근거 | 표시가 없으면 |
|---|---|---|
| systemd | `INVOCATION_ID` (systemd가 **반드시** 넣음) | **아니라고 단정** |
| 감시 스크립트 | `URBANGUARD_SUPERVISED` (serve.py가 **반드시** 넣음) | **아니라고 단정** |
| 윈도우 서비스 | 표준 표시가 **없음** | **모르겠다** |

- **단정할 수 있는 방식**은 관리자 확인으로 열어 주지 않습니다. 우리가
  아니라고 아는데 사람 말을 믿고 서비스를 내리는 꼴이 됩니다
- **윈도우 서비스만** 「감시 확인」 체크박스를 받습니다. 등록 시
  `URBANGUARD_WIN_SERVICE=1`을 넣으면 이 확인도 필요 없어집니다

> systemd까지 확인을 받게 하면 **확인이 형식이 되고 정작 필요한 곳에서
> 무뎌집니다.**

## 4. 화면

### S-87 서버 운영 (`/settings/server`, 시스템관리자 전용)

- **설정값과 실제 감지값을 나란히** 표시 — 하나만 보여 주면 설정이 현실과
  어긋나 있어도 화면은 멀쩡해 보입니다
- **방식별 등록 방법·로그 위치·상태 확인 명령**을 화면에 넣었습니다

| 방식 | 로그 | 상태 확인 |
|---|---|---|
| systemd | `journalctl -u <유닛> -n 100 --no-pager` | `systemctl status <유닛>` |
| 윈도우 서비스 | 이벤트 뷰어 → Windows 로그 → 응용 프로그램 | `sc query <이름>` |
| 감시 스크립트 | `data/logs/serve.log` | (감시 스크립트 콘솔) |

이것이 없으면 운영자는 서버에 붙어 헤매게 되고, 그럴 바에는 버튼이 없는 편이
낫습니다.

### S-01 재기동 카드

「기동 방식」 한 줄이 **운영체제 · 재기동 방식** 두 줄로 바뀌었고, 감지 상태를
배지로 표시합니다 — 확인됨 / 실제와 불일치 / 관리자 확인 / 확인 불가.

## 5. OS 불일치는 알리되 막지 않습니다

납품 대상 서버를 미리 설정해 두는 일이 실제로 있습니다(리눅스 납품용으로
설정해 두고 윈도우 개발기에서 확인). 그래서 **경고만** 하고 막지 않습니다.

막는 것은 **재기동 방식이 실제와 다를 때**입니다 — 그때는 안내문이 엉뚱한
로그(journalctl)를 가리키게 되기 때문입니다.

### 시험이 잡아낸 제 설계 오류 2건

1. **방식을 고르는 그 저장에서 「감시 확인」이 떨어져** 아예 켤 수 없었습니다.
   「방식이 바뀌면 이전 확인은 무효」라는 규칙이 첫 저장에도 걸렸습니다 →
   **폼에 적힌 대로 저장하되, 확인이 필요한 방식에만** 적용하도록 고쳤습니다
2. **systemd 미감지를 「확인 불가」로 뭉뚱그려** 잘못 안내했습니다 →
   위 3절의 「단정할 수 있는 방식」 구분을 넣었습니다
