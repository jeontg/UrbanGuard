>
> **네 번째 시도까지 마쳤고, 240p 교통 CCTV 로는 노면 손상 탐지가 성립하지
> 않는다는 결론에 도달했습니다.**
>

> 「라벨링 불가」**였습니다. **사람도 못 보는 것을 모델에게 기대할 수 없습니다.**

>
> | 모드 | 판정 | 제안·문서에 쓸 표현 |

## 0. 개요

- **목적**: 기존 침수(flood)·인파관리(crowd) 도메인과 동일한 아키텍처 패턴으로 "도로 노면 관리" 기능을 신설, 대시보드 3번째 도메인으로 통합
- **범위**: AI 기반 노면 손상(포트홀·균열) 탐지 — 사용자 확인 결과 확정
- **현재 보유 자산**: 없음(신규 기획 단계) — 학습 데이터·탐지 모델 모두 미보유
- **핵심 제약**: 자산이 전무하므로 "코드 통합" 이전에 **데이터 확보·모델 학습**이 선행되어야 하며, 이 구간이 전체 일정의 병목(critical path)

## 1. 기존 아키텍처와의 대응 관계

침수 도메인(`src/tot_dashboard/flood/`)의 구조를 그대로 재사용한다. 파일 단위 대응표:

| 침수 도메인 (기존) | 역할 | 도로 노면 도메인 (신규) |
|---|---|---|
| `flood/water_segmentation.py` | YOLO11-seg로 물 영역 마스크 추출 (`models/best.pt`, conf=0.10) | `road/defect_detection.py` — YOLO(-seg 또는 -det)로 포트홀/균열 탐지 (`models/road_defect_best.pt`) |
| `flood/metrics_core.py` | ROI 교집합, tire-zone, expansion rate 등 공용 수학 | `road/metrics_core.py` — ROI(점검구간) 내 손상 개수·면적·심각도 계산 |
| `flood/alert_engine.py` | 규칙기반 5단계 알림(정상~통제권고), persistence/cooldown 스무딩 | `road/alert_engine.py` — 손상 등급 규칙(예: 경미/보수필요/긴급) |
| `flood/standalone_pipeline.py` | 단일 카메라 CLI 배치 분석 | `road/standalone_pipeline.py` — 동일 패턴 |
| `common/roi.py` | 다각형 ROI 교집합 연산(`point_in_polygons`) | 그대로 재사용(신규 모듈 불필요) |
| `common/notifier.py` | SOLAPI SMS/카카오 알림 | 그대로 재사용 |
| `scripts/roi_editor.py` | 클릭 기반 ROI 지정 → `configs/roi/<카메라>.json` | 확장 — "점검 구간" 폴리곤 타입 추가 |
| `configs/blocks.json`의 `dept: "도로관리과"`, `road_attrs` | 블록 메타데이터 | 그대로 재사용, `road_inspection` 활성 플래그만 추가 검토 |

**중요**: 침수 도메인의 `MetricsEngine.update()`가 "자체완결형(탐지+추적을 스스로 계산)"과 "외부주입형(이미 계산된 값을 받음)" 두 아키텍처로 분리되어 있는 것은(`docs/integration_plan.md` 3-1절 참조) flood 도메인 고유의 이력(3개 프로젝트 병합)에서 비롯된 것으로, 신규 도로 도메인은 이 이중 구조를 그대로 답습할 필요 없음 — 처음부터 단일 아키텍처(자체완결형 CLI + 서비스에서 재사용 가능한 엔진 클래스 1개)로 설계 권장.

## 2. 데이터 확보 전략 (병목 구간)

### 2-1. 1단계 — 공개 데이터셋 기반 프로토타입

**웹 조사 결과(2026-07-24 기준, 후속 검증 필요)** — 후보 3건:

| 데이터셋 | 규모 | 라이선스 | 비고 |
|---|---|---|---|
| Kaggle `Potholes-Detection-YOLOv8` | train 1,581 / val 396장, YOLO 포맷 기라벨링 | 검색 결과상 **CC0(퍼블릭 도메인)**으로 표기됨 | ⚠️ Kaggle 페이지 자체(JS 렌더링)를 직접 열람해 재확인하지 못함 — 실제 도입 전 페이지 직접 확인 필수 |
| Roboflow Universe 포트홀 데이터셋(다수, 예: `public.roboflow.com/object-detection/pothole` 등 2,475장 규모) | 데이터셋마다 상이 | Roboflow Universe는 **데이터셋별로 라이선스가 다름**(CC BY 4.0 등 혼재) | 사용할 특정 데이터셋을 고른 뒤 그 항목의 라이선스를 개별 확인해야 함 |
| RDD2022(6개국 도로파손, 47,420장/55,000+ 인스턴스, 종주/횡주/악어등 균열+포트홀) | 대규모, 가장 포괄적 | **공식 라이선스 문구를 이번 조사에서 확인하지 못함** — 파생 프로젝트들은 GPL-3.0으로 공개되는 경우가 있었으나 이는 그 프로젝트의 라이선스이지 데이터셋 자체의 라이선스가 아님 | 공식 소스(CRDDC'2022, `crddc2022.sekilab.global`) 또는 원 논문에서 라이선스 재확인 필요 |

- ⚠️ **추가 확인 필요**: 위 라이선스 정보는 검색엔진 요약을 근거로 하며, Kaggle 페이지는 JS 렌더링이라 직접 열람으로 재확인하지 못했습니다. **실제 데이터셋 도입 전 반드시 해당 페이지를 직접 열어 라이선스 조항을 재확인**해야 합니다.
- ⚠️ **별도 확인 필요(도로 도메인 신규 이슈 아님, 기존 프로젝트 전체 이슈)**: 이 프로젝트가 이미 사용 중인 **Ultralytics YOLOv8/YOLO11 자체가 AGPL-3.0으로 배포**됩니다. AGPL은 네트워크 서비스(SaaS)로 제공할 경우에도 소스 공개 의무가 발생할 수 있는 라이선스로, 이 대시보드처럼 FastAPI로 서비스 제공하는 형태에 해당될 수 있습니다. 상업적 배포(공공기관 납품 포함) 전 Ultralytics Enterprise License 필요 여부를 **법무팀이 확인**해야 합니다. `flood/water_segmentation.py`·`flood/object_detection.py` 등 기존 모듈에도 동일하게 해당하는 사안입니다.
- 목표: 부산·울산·경남 실제 도로 CCTV 화면에서 "탐지가 되는지 안 되는지" 최소 검증(모델 신뢰도, 오탐률 대략 파악)

### 2-2. 2단계 — 자체 데이터 수집·라벨링
- `configs/blocks.json`에 이미 등록된 도로 CCTV(초량교차로·부산역·범내골교차로 등) 프레임을 샘플링해 자체 라벨링 데이터셋 구축
- 라벨링 도구/외주 여부, 목표 이미지 수, 라벨 클래스 정의(포트홀/균열/기타 손상 구분 여부)는 **전략기획부·개발부 협의 후 결정 필요**
- CCTV 화각(원거리·저해상도)이 포트홀 탐지에 충분한 해상도인지는 실제 프레임 샘플로 조기 검증 권장(고해상도 근접 촬영이 필요하면 별도 촬영 장비/드론 검토 필요)

### 2-3. 3단계 — 파인튜닝 및 반복 개선
- 1·2단계 데이터로 YOLO 파인튜닝 → 현장 시범 운영 → 오탐/미탐 케이스 재수집 → 재학습 반복

## 3. 시스템 설계

### 3-1. 디렉터리 구조 (신규)
```
src/tot_dashboard/road/
├── defect_detection.py     # YOLO 추론 (models/road_defect_best.pt)
├── metrics_core.py          # ROI 내 손상 개수/면적/심각도 계산
├── alert_engine.py          # 등급 규칙(경미/보수필요/긴급)
├── standalone_pipeline.py   # 단일 카메라 CLI 배치 분석
└── visualization.py         # 오버레이 렌더링
```

### 3-2. 등급 체계 (안 — 확정 전 도메인 전문가 검토 필요)
침수 도메인의 5단계(정상~통제권고) 패턴을 참고한 예시이며, **실제 임계값·단계 수는 도로관리과 실무 기준에 맞춰 별도 정의 필요**:

| 등급 | 명칭(안) | 조건(안, 예시) |
|---|---|---|
| 1 | 정상 | 손상 미탐지 |
| 2 | 관찰 | 경미한 균열 탐지, 크기 소 |
| 3 | 보수 필요 | 포트홀 탐지, 또는 균열 확산 |
| 4 | 긴급 보수 | 대형 포트홀, 통행 안전 위협 |

- 침수 도메인처럼 단일 프레임 오탐을 걸러내기 위한 persistence(연속 프레임 확인) 로직 적용 권장

### 3-3. ROI(점검 구간) 확장
- `scripts/roi_editor.py`에 "점검 구간" 폴리곤 타입 추가(기존 `road_roi`/`low_point_roi`/`lane_threshold_line`과 나란히 `inspection_zone` 필드 신설)
- `common/roi.py`의 `RoiConfig`/`point_in_polygons`는 무수정 재사용

### 3-4. 서비스/대시보드 통합
- `service/main.py`에 `/api/road/*` 엔드포인트 추가(flood 엔드포인트와 동일 패턴)
- `templates/index.html`에 4번째 탭 "도로 노면 관리" 추가, `static/app.js`에 렌더링 로직 추가
- `configs/blocks.json`: 도로 손상 탐지를 활성화할 블록에 플래그 추가(안, 예: `"road_inspection": {"enabled": true}`) — 스키마 확정 후 반영

Kaggle CC0 후보와 Roboflow ODbL 후보는 실제 파일 다운로드에 로그인/계정이 필요해(제가 대신 할 수 없는 항목) 보류, 로그인 없이 받을 수 있는 RDD2022로 대체
- **작업**:

  - [x] `scripts/test_road_defect_detection.py` — 체크포인트+프레임 1장 검증 스크립트

  - [x] `scripts/prepare_rdd2022_yolo.py` — Pascal VOC XML → YOLO 포맷 변환, 4클래스 → 2클래스(pothole/crack) 매핑, train/val 분리

  - [x] 실제 CCTV 프레임 탐지 시도 — BLOCK-CHORYANG(720x480)/BLOCK-BUSANSTN(352x240)/BLOCK-BEOMNAEGOL(320x240) 3개 블록 모두, 신뢰도 임계값을 0.01까지 낮춰도 **탐지 0건**
- **완료조건**: 최소 1개 블록의 실제 CCTV 프레임에서 탐지 결과 육안 확인 — ⚠️ **미충족**. 아래 "핵심 발견" 참고

**핵심 발견 — CCTV 화각/해상도 문제로 추정(2-2절/5장 4번 항목의 우려가 실제로 확인됨)**: 같은 모델을 RDD2022 검증셋 이미지(학습 도메인 내)에 conf=0.01로 돌리면 이미지당 7~15개의 (약한) 박스가 나오는데, 동일 조건(conf=0.01)에서 실제 부산 CCTV 프레임 3장은 전부 0건입니다.

**추가 검증(사용자 결정: epoch을 늘려 재시도) — 결론 확정**: v1(15 epoch)의 가설이 "학습 부족"인지 "도메인 갭"인지 구분하기 위해, v1 체크포인트에서 이어서 35 epoch을 더 학습(계 50 epoch 상당, `scripts/train_road_defect_prototype_v2.py`, run명 `road_defect_proto_v2`)했다.
- 검증셋 성능은 실제로 개선됨: mAP50 0.193→**0.232**, mAP50-95 0.070→**0.094** (pothole 0.183, crack 0.282)
- 그러나 동일한 3개 블록 CCTV 프레임에 conf=0.01로 재시험한 결과 **여전히 3개 블록 전부 0건 탐지**(변화 없음)

즉 학습을 3배 이상 늘려 검증셋 성능이 20% 개선됐음에도 실제 CCTV에서는 신호가 전혀 나타나지 않아, **"에폭 부족" 가설은 기각되고 "도메인 갭(RDD2022의 차량 블랙박스 근접 촬영 vs 부산 교차로 CCTV의 고가·광각·저해상도 320~720px 촬영 조건 차이)" 가설이 확정적으로 지지됩니다.** Phase 3에서 학습을 더 늘리는 방향으로는 이 문제가 해결되지 않을 것으로 판단되며, **자체 CCTV 데이터 라벨링(2-2절)이 선택 사항이 아니라 필수 경로**가 되었습니다.

**추가 검증(영상 테스트, 2026-07-31) — "카메라 각도" 가설도 부분 기각, 문제는 더 근본적**: 실제 도로 CCTV와는 완전히 다른 조건(스마트폰으로 위에서 아래로 약 130cm 거리에서 근접 촬영한 포트홀 영상 10개, Mendeley Data "Pothole Videos", CC BY, `data/datasets/pothole_video_mendeley/samples/`)에 v2(50 epoch) 모델을 conf=0.01까지 낮춰 시험했다. **이번에도 10개 전부 0건 탐지.** 프레임 자체는 육안으로 포트홀이 뚜렷하게 보임(문서에 첨부된 검증 스크린샷 참고).

- 부산 CCTV(원거리·광각·저해상도)와 이 근접 클로즈업 영상은 촬영 조건이 정반대에 가까운데도 둘 다 0건이라는 것은, "카메라 각도/해상도"만의 문제가 아니라 **RDD2022 특유의 "도로 한 구간을 보여주는 일반적인 사진" 구도 자체에 모델이 과적합돼, 그 구도에서 벗어난 모든 입력(원거리든 극근접이든)에 거의 반응하지 않는 것**으로 보인다.
- 결론적으로 Phase 3(자체 데이터 라벨링)의 필요성은 더 명확해졌다 — **실제 배포 환경(부산 CCTV)과 촬영 조건이 일치하는 데이터로 학습하지 않으면, 어떤 공개 데이터셋·어떤 학습량으로도 해결되지 않을 가능성이 높다.**

## 4-B. AI 탐지 실행 기능 — 이중 모드 (2026-08-03 구현)

관리자가 **기존 영상**과 **실시간 CCTV** 중 골라 실제 모델 추론을 실행할 수 있게 했습니다. 인파 도메인의 provider 전환 패턴과 동일한 구조입니다.

| 모드 | 대상 | 표본 방식 | 용도 |
|---|---|---|---|
| **기존 영상** | 확보한 영상 12종 (Mendeley 포트홀 10 + 침수 2, **CC BY**) | 파일 전체를 균등 간격 12장 | 재현 가능 — 검증·시연 |
| **실시간 CCTV** | `blocks.json`의 HLS 스트림 7개 지점 | **15초 관측** 창에서 표본 추출 | 현장 실시간 점검 |

### 실시간 모드의 15초 관측 (사용자 요청 반영)

프레임 몇 장만 즉시 받으면 **그 순간 지나가던 차량·그림자에 결과가 좌우**됩니다. 그래서 일정 시간 관측하며 나눠 표본을 뽑습니다(`CCTV_DURATION_SEC = 15.0`).

- **벽시계 시간 기준**으로 창을 관리합니다 — HLS는 버퍼 구간을 실시간보다 빠르게 디코딩할 수 있어, 프레임 수만 세면 실제 경과와 어긋납니다
- 15초 관측은 blocking I/O이므로 `run_in_threadpool`로 넘겨 이벤트 루프를 막지 않습니다
- API의 `duration_sec`로 조정 가능(1~60초 제한 — 요청을 그 시간만큼 붙잡으므로 상한 필요)

**⚠️ 실측에서 드러난 두 가지**

1. **표본 장수가 예상보다 적습니다** — 1초 간격이면 15장을 기대했으나 실측 **3~4장**이었습니다. HLS 프레임 획득 자체가 느려서이며, 로직 오류는 아닙니다. UI에도 "표본 장수는 스트림 속도에 따라 달라진다"고 명시했습니다
2. **전체 응답은 15초가 아니라 약 25초입니다** — 관측 15초 + 모델 추론 약 10초. 화면에 "20~30초 소요"로 안내했습니다

→ 만약 **전체 시간을 15초로 묶어야** 한다면 관측 창을 줄여야 합니다(예: 관측 8초 + 추론 7초). 현재는 **관측 시간을 15초로** 해석해 구현했습니다.

### CCTV 팝업 (사용자 요청 반영)

실시간 모드에서 「분석 실행」을 누르면 **해당 지점 CCTV가 팝업으로 함께 표출**됩니다(기존 실시간 모달 재사용). 15초 동안 무엇을 관측 중인지 눈으로 확인할 수 있습니다.

- 분석 완료 시 팝업 제목이 `지점명 · 분석 완료 — 손상 N건`으로 갱신됩니다
- **자동으로 닫지 않습니다** — 방금 무엇을 봤는지 확인할 기회를 없애지 않기 위함

### 구현

| 파일 | 역할 |
|---|---|
| `road/live_analyzer.py` (신규) | `RoadDefectAnalyzer` — 두 모드 통합 진입점, 등급 산정 |
| `service/main.py` | `GET /api/road-analysis/targets`, `POST /api/road-analysis/run` |
| `index.html`·`app.js`·`styles.css` | 관리자 선택 UI (모드 전환 + 대상 선택 + 실행) |

- 모델은 **최초 요청 시 지연 로드** — 모델 파일이 없어도 대시보드는 정상 기동

- 동시 요청은 락으로 직렬화(추론 충돌 방지)
