## 0. 결론 먼저

○ **통합 상황판 우측에 「서비스 상태」 카드와 재기동 버튼을 붙였습니다.**
  실제로 눌러 프로세스가 죽고 다시 뜨는 것까지 확인했습니다(6절)

○ **⚠️ 앞으로 서비스는 `scripts/serve.py` 로 띄워야 합니다.**
  맨 uvicorn 으로 띄우면 버튼이 스스로 잠깁니다 — 되살릴 것이 없기 때문입니다

○ 이 버튼은 **`.env` 를 고친 뒤에만** 필요합니다. 화면에서 바꾸는 설정
  (지점·ROI·임계값·알림규칙·AI모델)은 예전처럼 재기동 없이 바로 반영됩니다

---

## 1. 왜 만들었나

`.env` 는 프로세스가 뜰 때 **한 번만** 읽습니다. 기상청 API 키를 넣거나 바꾸면
재기동해야 반영되는데, 지금까지는 서버에 붙어 명령을 쳐야 했습니다. 관제센터
운영자에게 그걸 시킬 수는 없습니다.

---

## 2. 가장 중요한 발견 — 그냥 죽이면 되살아나지 않습니다

구현 전에 확인한 사실입니다.

| 확인한 것 | 결과 |
|---|---|
| `scripts/serve.py` 의 종료 처리 | **종료 코드 0 = 「정상 종료」 → 되살리지 않음** |
| 당시 실제 기동 방식 | 감시 없이 맨 uvicorn (`.claude/launch.json`) |

**순진하게 만들었으면 이 버튼은 재기동이 아니라 영구 종료였습니다.**
밤사이 서비스가 내려가 있던 **2026-08-12 사고**가 정확히 그 모습이었습니다
(`scripts/serve.py` 머리말).

## 3. 세 겹으로 막았습니다

### ① 되살릴 사람이 있을 때만 눌립니다

감시 기동(`serve.py`)이 자식 프로세스에 `URBANGUARD_SUPERVISED=1` 을 심습니다.
이 표시가 없으면 버튼이 잠기고 **이유를 화면에 그대로 띄웁니다.**

> 감시 기동으로 떠 있지 않아 재기동할 수 없습니다. 지금 프로세스를 내리면
> **되살릴 것이 없습니다.** `python scripts/serve.py --port <포트>` 로 띄우면
> 이 버튼을 쓸 수 있습니다.

조용히 회색으로만 두면 「왜 안 눌리지」로 끝나고, 운영자는 결국 서버에 직접
붙습니다.

### ② 시스템관리자만 보입니다

권한은 **`SETTINGS_SYS` × `EXECUTE`** 입니다. 이 조합은 시스템관리자만
가집니다(MGR·OPR 은 `SETTINGS_SYS` 가 빈 집합). **자원을 새로 만들지
않았습니다** — 재기동은 「시스템 설정을 실제로 적용하는 행위」라 기존 자원의
EXECUTE 와 뜻이 맞습니다.

`core/guard.py` 규칙표에도 등록했습니다. 이 시스템은 **규칙 미등록 API 를 기본
차단**하므로, 등록하지 않으면 시스템관리자조차 못 씁니다.

### ③ 확인창에 무엇이 멎는지 숫자로 보여 줍니다

```
서비스를 재기동합니다.

· 상시 탐지(3개 동작 중)가 10~30초 동안 멎습니다
· 집중 감시(S-44)를 켜 두셨다면 함께 꺼집니다
· 화면을 보고 있는 다른 근무자도 잠시 끊깁니다

설정 파일을 고친 것이 아니라면 재기동할 이유가 없습니다. 진행할까요?
```

숫자로 보여 주지 않으면 **「새로고침 같은 것」으로 읽힙니다.**

## 4. 전용 종료 코드 42

| 코드 | 감시 프로세스의 반응 | 왜 안 되나 |
|---|---|---|
| `0` | 정상 종료로 보고 **안 되살림** | 재기동이 아니라 종료가 됨 |
| 아무 비정상 코드 | 세그폴트와 구분 안 됨 | 백오프(5초→120초)가 붙고, 연속 실패로 세어 결국 「20회 실패」로 감시가 멈춤 |
| **`42`** | **백오프 없이 즉시 재기동, 실패로 세지 않음** | — |

상수(`RESTART_EXIT_CODE`, `SUPERVISED_ENV`)는 `core/service_control.py` 가
원본이고, `serve.py` 는 **패키지 없이 단독 실행돼야 해서**(패키지가 깨져도
서비스는 띄워야 함) 값을 복제해 뒀습니다. 한쪽만 고치면 재기동이 조용히
깨지므로 **두 값이 같은지 시험으로 묶어 뒀습니다.**

## 5. 그 밖의 설계 판단

- **감사 로그를 먼저 커밋하고 죽습니다** — 죽은 뒤에는 아무것도 남길 수
  없습니다. 남는 값: 가동 시간, 멎힌 워처 수, 누가, 어디서
- **워커를 정리하고 죽습니다** — 종료 경로(`lifespan`)와 같은 함수
  (`_shutdown_workers`)를 씁니다. 정리 없이 죽이면 스트림 연결과 임시 파일이
  남습니다. 정리에 실패해도 재기동은 진행합니다 — 정리하려다 못 죽으면
  「눌렀는데 아무 일도 안 일어난다」가 됩니다
- **두 번 눌러도 한 번만** 실행됩니다
- **다시 뜰 때까지 화면이 확인해 주고** 자동 새로고침합니다(2초 간격, 최대
  60초). 확인해 주지 않으면 운영자는 하얀 화면을 보고 자기가 서비스를
  망가뜨렸다고 생각합니다. 옛 프로세스가 아직 응답하는 동안 「다 됐다」고 하지
  않도록 **가동 시간이 짧아진 것을 보고** 판단합니다

## 9. 기동 방법 변경 (운영 반영 필요)

```bash
python scripts/serve.py --host 127.0.0.1 --port 8033
```

`.claude/launch.json` 에 `urbanguard-8033-supervised` 항목을 추가했습니다.
기존 맨 uvicorn 항목도 남겨 두었으나, **그쪽으로 띄우면 재기동 버튼이
잠깁니다.**

> ⚠️ `serve.py` 는 여전히 임시 방편입니다. 서버가 재부팅되면 함께 죽습니다.
> 운영 납품에서는 **Windows 서비스(NSSM 등)나 작업 스케줄러**로 등록해야
> 하며, 그때 종료 코드 42 를 재기동으로 처리하도록 설정해야 이 버튼이
> 계속 동작합니다.
