# 도로 노면 관리 — 「노면 현황」·「AI 탐지 실행」 화면 분리

앤시정보기술(주) · 전략기획부 · 2026-08-24

---

## 1. 배경

○ 사용자 문의: "도로 노면 관리의 노면 현황과 AI 탐지 실행의 차이는
　무엇인가요?"

○ 확인 결과: 왼쪽 메뉴에는 「노면 현황(S-40)」·「AI 탐지 실행(S-41)」
　두 항목으로 나뉘어 있었지만, 실제로는 **`/road`·`/road/detect` 두
　주소가 정확히 같은 화면(탭)을 열고 있었다** — 메뉴상 두 기능이지만
　화면은 하나뿐이라, 어느 메뉴로 들어가든 실시간 관제·지점별 현황·AI
　탐지 실행·학습영상 업로드가 전부 한 화면에 뒤섞여 나왔다.

○ 사용자 요청: 두 화면으로 실제로 나누되, **다른 메뉴·기능과의 연계는
　그대로 동작**하게 해 달라(예: 실시간 CCTV 미리보기, 사건 보고서,
　지점별 카드에서 바로 분석 실행 등).

---

## 2. 설계 — 어떻게 나눴나

○ 침수·교통위험이 이미 같은 패턴(하나의 페이지 안에서 **탭만 나누고**
　모달·JS·데이터는 전부 공유)으로 분리돼 있어, 같은 방식을 그대로
　따랐다. 완전히 별도 페이지로 쪼개는 대신 **탭을 하나 더 만들어
　구획을 옮기는** 낮은 위험의 방법을 택했다 — 모달(`livemodal` 등)·
　전역 변수(`window.INITIAL_BLOCKS`)·API 호출 로직을 전혀 건드리지
　않아, 연계 기능이 저절로 유지된다.

○ 기능을 실제 성격에 따라 재배치

| 새 탭 | 담는 것 | 근거 |
|---|---|---|
| **노면 현황**(`tab-road`, `/road`) | 실시간 관제(집중 감시)·지점별 관측 이력·지점별 노면 상태 목록 | 시스템이 **자동으로**(15분 상시 순회) 쌓은 결과를 **보러 가는** 화면 |
| **AI 탐지 실행**(`tab-road-detect`, `/road/detect`) | 학습 영상 업로드·AI 손상 탐지 실행(기존 영상/실시간 CCTV 선택) | 사람이 대상을 **직접 골라 그 자리에서 즉시 실행**하는 화면 |

○ `service/main.py::legacy_dashboard()` — `/road/detect`가 그동안
　`/road` 접두사 검사에 걸려 항상 같은 탭으로 떨어지던 것을, `/road/
　detect`를 **먼저** 확인하도록 순서를 바꿔 별도 탭(`road-detect`)을
　열도록 수정. 왼쪽 메뉴 강조(`active`)도 `road-detect` 항목에
　정확히 붙도록 매핑 추가(예전엔 두 메뉴 다 눌러도 「노면 현황」만
　강조됐다).
○ `service/templates/index.html` — 탭 버튼 "도로 노면 관리" 1개를
　"노면 현황"·"AI 탐지 실행" 2개로 나누고, 기존 `<section id="tab-
　road">`의 내용을 성격에 따라 두 섹션으로 재배치.

## 3. 연계 기능이 그대로 동작하는 이유

○ 두 탭이 **같은 문서(DOM)** 안에 있어, 실시간 CCTV 모달(`livemodal`)·
　사건 보고서 모달(`reportmodal`)·`window.INITIAL_BLOCKS` 등 공유
　자원을 그대로 쓴다 — 별도 페이지로 쪼갰다면 이 전부를 양쪽에
　복제해야 했다.
○ 초기화 호출(`loadRoadList()`·`loadRoadAnalysis()`·`loadRoadLive()`·
　`renderRoadUploadForm()`)은 원래도 **탭 구분 없이 페이지 로드 시
　한 번에 전부 실행**되던 구조라(각 함수가 자기 담당 DOM 요소만
　채운다), 탭을 나누어도 JS 쪽은 손댈 필요가 없었다.
○ "노면 현황" 카드의 「▶ 분석 실행」 버튼(그 자리에서 바로 AI 탐지를
　돌리는 지름길, "AI 탐지 실행 탭으로 옮겨 다시 고르는 수고를
　없앤다"는 기존 설계 의도)도 함수 자체를 옮기지 않아 그대로 남는다.

## 4. 검증

○ 신규 자동 시험 3건 추가(`tests/service/test_main.py`), 전부 통과
　－ `/road`·`/road/detect`가 서로 다른 `INITIAL_TAB`을 열고, 왼쪽
　　메뉴 강조도 각자 자기 항목에만 붙는지
　－ "노면 현황" 탭에 AI 탐지 실행 구획이 안 섞여 있는지
　－ 화면 분리 후에도 4개 초기화 호출이 app.js에 그대로 남아 있는지
○ 전체 회귀 `pytest tests -q` — **1,621건 통과, 3건 skip**(기존과
　동일, 신규 결함 없음)
○ 실제 브라우저로 확인
　－ `/road` → "노면 현황" 탭 활성화, 실시간 관제·지점별 목록만 표시
　－ `/road/detect` → "AI 탐지 실행" 탭 활성화, 학습영상 업로드·AI
　　탐지 실행 도구만 표시
　－ 왼쪽 메뉴에서 두 항목이 각자 자기 화면에서만 강조됨(`aria-
　　current`)
　－ 연계 기능 실측: "노면 현황"의 「▶ 실시간」 버튼 → 실시간 CCTV
　　모달 정상 오픈, 「▶ 분석 실행」·「📄 보고서」 버튼 정상 연결,
　　"AI 탐지 실행"의 실시간 CCTV 모드 대상 목록도 실제 카메라
　　목록과 정상 연동
○ `flood_t` 무변경(39건)

## 5. 추가 수정 — "가진 영상에서 프레임 뽑기"의 위치 재검토

○ 화면 분리 직후 사용자가 스크린샷을 보고 재차 확인: "AI 탐지 실행"
　탭에 "가진 영상에서 프레임 뽑기"(`road-train`)가 있는 게 맞는지

○ 재검토 결과 — **이 기능은 탐지를 실행하는 것이 아니라 학습 데이터를
　모으는 것**이다("영상 전체에서 프레임을 뽑아 마스킹 후 저장"). 탐지
　실행(`road-analysis`, 대상을 골라 즉시 AI 추론)과는 성격이 다르다.
　1절 초안에서 "AI 관련 도구"라는 느슨한 기준으로 함께 묶었던 것이
　잘못이었다.

○ 마침 "노면 현황" 탭의 실시간 관제 패널 안에 **같은 성격의 기능**
　（"학습 데이터 자동 수집" 현황 — 상시 순회 중 자동으로 프레임을
　모으는 기능)이 이미 있어, 수동 프레임 추출 도구를 그 옆으로 옮겼다.
　이제 "AI 탐지 실행" 탭은 **탐지 실행 전용**으로, "노면 현황" 탭은
　**현황 열람 + 학습 데이터 수집(자동+수동)**으로 명확히 갈린다.

○ 검증 — 신규 시험 1건 추가(정확히 이 배치를 확인하는 시험으로
　기존 시험도 함께 강화), 전체 회귀 **1,622건 통과**. 브라우저 실측으로
　"AI 탐지 실행" 탭에 프레임 추출 폼이 사라지고 "노면 현황" 탭의 자동
　수집 현황 바로 아래 나타남을 확인.
