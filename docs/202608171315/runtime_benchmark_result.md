## 0. 결론 먼저

○ **OpenVINO가 중앙값 기준 7.2배, ONNX Runtime이 2.0배**입니다
  (침수 분할 모델, 96회 추론)

○ **결과는 완전히 동일합니다.** 검출 개수 27/27·114/114 일치,
  **IoU 1.0000**, **신뢰도 차이 0.0000**. 정확도를 잃지 않고 속도만 얻습니다

○ ⚠️ **OpenVINO는 예열이 필요합니다.** 첫 2회차 약 950ms → 3회차부터
  70~76ms. 기동 시 예열 추론을 넣지 않으면 초기에 느립니다

○ ⚠️ **PyTorch가 가장 안정적입니다**(최악/중앙 1.4배). ONNX는 4.2배,
  OpenVINO는 16.8배 — 다만 OpenVINO의 편차는 **전부 예열 구간**이며
  예열 후 최악값은 101ms입니다

○ **권고: OpenVINO 1순위(Intel 확정 시) · ONNX 기본·이식용.** 납품 서버가
  AMD이거나 배포판이 다르면 ONNX가 안전한 기본값입니다

## 4. 결과 동일성 — 가장 중요한 확인

**빨라져도 답이 달라지면 쓸 수 없습니다.** IoU로 짝을 지어 비교했습니다.

| 모델 | PyTorch | OpenVINO | 짝지어진 상자 | 최저 IoU | 최대 신뢰도 차이 |
|---|---|---|---|---|---|
| 침수 분할 | 27개 | 27개 | **27개** | **1.0000** | **0.0000** |
| 마스킹 검출 | 114개 | 114개 | **114개** | **1.0000** | **0.0000** |

ONNX Runtime도 동일합니다 — 검출 개수 6/6 일치, 좌표 최대 차이 **0.00px**,
신뢰도 최대 차이 **0.0000**.

> **정확도 손실이 없습니다.** 「빠른 대신 덜 정확한」 절충이 아니라,
> **같은 답을 더 빨리** 내는 것입니다.

## 5. 작업 중 발견한 함정 3가지

**실제 도입 시 그대로 겪을 문제들**이라 기록합니다.

### ① `task` 메타데이터 유실 — 가장 위험

첫 측정에서 침수 모델이 **1.10배**로 나오고 결과 일치가 **0/6**이었습니다.

원인은 **ONNX 파일이 task 정보를 잃어 `segment` 모델이 `detect`로 로드**된
것이었습니다. 분할 모델의 출력에는 마스크 계수 32개가 붙는데, 검출로 읽으면
**그 계수를 클래스 점수로 해석**합니다.

**증상** — 신뢰도가 **1.0을 넘고**(1.874, 2.198), 상자가 프레임마다 **300개**
나옵니다.

```
프레임0: pt=1개 [0.404]   onnx=300개 [1.874, 1.608, ...]
프레임3: pt=4개 [0.593]   onnx=300개 [2.198, 2.010, ...]
```

**대책** — 로드할 때 `task`를 **반드시 명시**하고, 양쪽 task가 같은지
확인한 뒤에만 측정합니다.

> ⚠️ **결과 일치 검증을 넣지 않았다면 1.10배라는 틀린 숫자를 그대로
> 보고했을 것입니다.** 속도만 재는 벤치마크는 위험합니다.

### ② 내장 GPU 커널 컴파일 시도

3자 측정 중 한 회차가 **499.86초**를 기록했습니다. 같은 시각 작업 폴더에
OpenVINO의 **커널 컴파일 오류 로그**가 생성돼 있었습니다.

```
!!!KERNEL HEADER ERRORS FOUND!!!
Error in CISA routine with name: kernel
  Input V38 = [256, 260) intersects with V37 = [256, 260)
```

재측정에서는 재현되지 않았습니다. **장치를 CPU로 명시적으로 고정**해
내장 GPU 경로를 타지 않게 해야 합니다.

### ③ 비교 방법 자체의 함정

처음에는 **신뢰도 내림차순으로 정렬해 같은 자리끼리** 비교했습니다.
그 결과 OpenVINO가 「좌표 최대 590.54px 차이」로 나왔습니다.

**실제로는 완전히 같은 상자였습니다.** 신뢰도가 동일한 상자 둘의 정렬
순서가 뒤집히면, 자리로 비교할 때 수백 px 차이로 보입니다.

**IoU로 짝을 지어** 다시 보니 IoU 1.0000·신뢰도 차이 0.0000이었습니다.

> **모델 비교는 「자리」가 아니라 「짝」으로 해야 합니다.**
> 계획 B(모델 후보 비교)에서도 이 방식을 써야 합니다.

## 6. 운영 반영 시 필요한 것

| # | 항목 | 이유 |
|---|---|---|
| 1 | **기동 시 예열 추론** | OpenVINO 첫 2회차가 약 950ms. 예열 없이는 초기 감시가 느림 |
| 2 | **장치 CPU 고정** | 내장 GPU 커널 컴파일 시도 방지 |
| 3 | **`task` 명시 로드** | 분할 모델이 검출로 로드되는 사고 방지 |
| 4 | `model_registry` **확장자 인식 추가** | 현재 `.pt` 고정 — `.onnx`·OpenVINO 디렉터리 미인식 |
| 5 | **런타임 선택을 설정으로** | 납품 서버가 Intel이 아닐 수 있음 |
| 6 | **결과 동일성 시험을 회귀에 추가** | 모델·런타임 교체 때마다 자동 확인 |
