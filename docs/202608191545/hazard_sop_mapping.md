## 1. 무엇이 문제였나

SOP 를 고르는 코드는 `core/sop.py` 의 **한 줄**이 전부였습니다.

```python
steps = steps_for(db, event.domain, event.level)
```

**「도메인 × 등급」 두 축**뿐입니다. 그래서 이렇게 됩니다.

| 위험유형 | 지금 나오는 SOP |
|---|---|
| 침수 | (침수 · 경계) 체크리스트 |
| **지하차도 침수** | **똑같음** |
| **배수로 침수** | **똑같음** |

★ **지하차도 침수와 배수로 침수는 조치가 다릅니다.** 지하차도는 물이 고이면
빠져나갈 곳이 없어 **차량 진입 차단이 최우선**이고, 배수로는 배수·역류 조치입니다.

### 발주처 요구이기도 합니다

경남 제안요청서 **SFR-012** 원문입니다.

> 「단계별 SOP 를 자동으로 **도, 시·군별로** 제시」

`hazard_sop_map.zone_id` 가 그 「도, 시·군별」입니다. **그 축이 통째로 없었습니다.**

### 표는 있는데 아무도 못 채웠습니다

`hazard_sop_map` 표는 2026-08-18 에 만들어 뒀습니다. 그런데 **읽는 코드도
화면도 없어 0행**이었습니다. 표만 있으면 아무도 채우지 못하고, 채워지지
않으면 있으나 마나입니다.

> **잇는 값은 오늘 오전에 준비됐습니다** — `events.hazard_type_code` 를
> 채우는 코드가 없어 늘 비어 있던 것을 고쳤고, 과거 31건도 백필했습니다.
> **지금이 붙이기 가장 쉬운 때**였던 이유입니다.

## 2. ★ 핵심 판단 — 「더한다, 갈아치우지 않는다」

**세분류는 대분류의 조치를 포함하고 더 있습니다.** 지하차도 침수도 침수라서
「영상으로 현장 확인」·「차량 진입 차단 검토」는 그대로 필요합니다.

실측 결과입니다.

```
일반 침수 경계:     4단계
지하차도 침수 경계: 5단계
   - 영상으로 현장 확인            ← 공통, 그대로
   - 상황 일지 기록                ← 공통, 그대로
   - 소관 부서 통보                ← 공통, 그대로
   - 차량 진입 차단 검토           ← 침수, 그대로
   - 지하차도 진입 차단 우선 검토  ← ★ 더해짐
```

⚠️ **갈아치우게 만들면, 매핑을 한 줄만 넣어 둔 순간 공통 단계가 통째로
사라집니다.** 「영상으로 현장 확인」이 빠진 체크리스트가 되는 것입니다.
**그건 지금보다 나쁩니다.**

### 비어 있으면 지금과 완전히 같습니다

⚠️ **여기가 이 작업에서 가장 조심한 부분입니다.** 매핑을 읽기 시작하는 순간,
잘못 만들면 **매핑이 없는 이벤트에 SOP 가 하나도 안 뜨는** 상태가 됩니다.

`test_매핑이_비면_기존_동작_그대로다` 로 못박았습니다. 이 시험이 깨지면
매핑을 넣는 순간이 아니라 **넣지 않은 모든 기관**에서 SOP 가 달라집니다.

## 3. 다른 곳의 방식을 그대로 따랐습니다

`sop.py` 의 `DEFAULT_STEPS`·`seed_builtin` 규칙을 복사했습니다.

| 규칙 | 적용 |
|---|---|
| **목록은 코드에, 심기는 `seed_builtin` 에** | `DEFAULT_HAZARD_STEPS` · `seed_hazard_sop()` |
| **덮어쓰지 않는다** | 이미 있으면 건드리지 않음 |
| **지운 것은 되살리지 않는다** | 지운 행 복구 안 함 |
| **`builtin=True` 표시** | 「기관 매뉴얼로 교체 필요」가 화면에 드러남 |
| **기동 시 1회 시드** | `main.py` 의 SOP 시드 바로 옆 |

★ **두 번 돌려도 `(0, 0)`** 임을 시험으로 확인했습니다.

### 넣은 기본값 5건

기존 `DEFAULT_STEPS` 와 같은 원칙입니다 — **이 시스템이 실제로 할 수 있는
행위에서만** 뽑았고, 「○○조에 따라」 같은 법조문은 **일부러 넣지 않았습니다.**
틀린 조문이 기본값으로 박히면 대장 전체가 틀린 근거로 채워집니다.

| 위험유형 | 등급 | 단계 |
|---|---|---|
| 지하차도 침수 | 경계 | 지하차도 진입 차단 **우선** 검토 |
| 지하차도 침수 | 심각 | **차도 내 차량 잔류 확인** |
| 배수로 침수 | 경계 | 배수 상태와 **역류 여부** 확인 |
| 배회 | 경계 | **동일 인물 반복** 여부 확인 |
| 노면 파손 | 경계 | 차로 위치와 크기 기록 |

> ⚠️ **구역(`zone_id`) 기본값은 넣지 않았습니다.** 기관 지형에 따라 다른데
> **지어내면 틀린 값이 기본으로 박힙니다.** 화면에서 기관이 정합니다.

## 4. ⚠️ 트릭을 하나 썼습니다 — 밝혀 둡니다

매핑 전용 단계는 `sop_steps.domain` 에 **위험유형 코드**(`flood_underpass`)를
넣었습니다.

`domain='flood'` 로 두면 **기본 매칭에 걸려 「침수」 전체에 지하차도 단계가
붙습니다.** 도메인 목록에 없는 값이면 기본 매칭이 자연히 비껴가므로 그 성질을
썼습니다.

★ 이 단계들은 **오직 매핑을 통해서만** 나옵니다. 코드 주석과 시험
(`test_매핑전용_단계는_기본매칭에_걸리지_않는다`)으로 못박았습니다.

> **읽는 사람이 「왜 domain 에 위험유형이 들어 있지?」 하고 멈출 자리**라
> 숨기지 않고 적습니다.

### 화면 설계

- **메뉴는 S-86 바로 옆**에 뒀습니다 — 단계를 **만드는 곳**과 **붙이는 곳**이
  떨어져 있으면 매번 헤맵니다. 권한도 `R.SOP` 로 동일합니다
- ⚠️ **이 화면은 단계를 만들지 않습니다.** 단계는 S-86 에서 만들고, 여기서는
  **어디에 붙일지만** 정합니다. 두 화면이 같은 일을 하면 어디서 고쳐야 하는지
  아무도 모르게 됩니다
- 화면 상단에 **「더합니다·갈아치우지 않습니다」**와 **「연결이 없으면 지금과
  같습니다」**를 적었습니다 — 갈아치우는 줄 알면 기관이 무서워서 못 씁니다
- 같은 조합 중복 입력은 **저장 전에 막습니다** — 안 막으면 유일 제약에 걸려
  500 이 납니다

## 7. 남은 제약

| # | 항목 | 왜 |
|---|---|---|
| 1 | **`zone_id`(도·시군별)를 아직 못 씁니다** | **구역 0행**입니다. 경남 SFR-012 의 「도, 시·군별」을 쓰려면 구역 등록이 선행돼야 합니다. **화면이 그 사실을 그대로 표시합니다** |
| 2 | **세분류를 탐지기가 알려 주지 않습니다** | 이벤트는 대분류(`flood`)만 채웁니다. 지하차도/배수로 구분은 **탐지 쪽 작업**입니다(대장 4-11). 그전까지 세분류 단계는 **화면에서 손으로 붙일 때만** 나옵니다 |
| 3 | 기본값 5건은 **어느 기관의 매뉴얼도 아닙니다** | 뼈대입니다. 도입 기관의 실제 매뉴얼로 교체해야 하고, 화면이 그렇게 표시합니다 |

> ★ **2번이 이 기능의 값어치를 정합니다.** 지금은 「구조는 갖췄고 손으로
> 붙일 수 있다」까지입니다. **자동으로 세분류가 붙으려면 탐지기가 먼저**입니다.

**기존 폴더 `flood_t` 는 건드리지 않았습니다.**
