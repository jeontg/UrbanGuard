# ROI 화면 표시·실제 판정 해상도 불일치 수정

앤시정보기술(주) · 전략기획부 · 2026-08-23

---

## 1. 배경

○ 사용자가 실사용 화면을 직접 캡처해 제보
　－ ROI 설정 화면(S-81, 「도봉지하차도 출구」/SEOUL-1042)의 「그리기」
　　패널은 도로 ROI 2개·저지대 ROI 1개·차선 기준선 설정됨을 표시
　－ 그런데 같은 화면의 「정지영상」에는 그려진 다각형이 전혀 보이지
　　않음 — "설정은 됐다는데 화면에는 없다"

○ 원인 확인 과정에서 **같은 근본 원인이 실제 판정 로직에도 있는 것**을
　추가로 발견해 함께 수정함(사용자 요청: "다른 CCTV들의 ROI에도 문제를
　찾아서 수정해 주세요")

---

## 2. 근본 원인

○ ROI는 **저장할 때 화면에 뜬 정지영상의 픽셀 좌표**로 저장된다
　（예: 1920×1080 화면에서 그리면 좌표도 그 기준）

○ 그런데 **이 좌표를 실제로 쓰는 세 곳 모두, "저장 당시 해상도"와
　"지금 쓰는 화면/프레임의 실제 해상도"가 다를 수 있다는 점을 반영하지
　않고 좌표를 그대로 썼다**

| 소비처 | 문제 |
|---|---|
| ROI 설정 화면(S-81) 정지영상 미리보기 | 지금 뜬 정지영상 해상도로 SVG 캔버스를 잡으면서, 좌표는 저장 당시 해상도 그대로 그림 → 두 해상도가 다르면 다각형이 캔버스 밖으로 나가 안 보임 |
| 침수 위험도 판정(`FloodMetricsEngine`/오프라인 분석기) | 도로·저지대 ROI를 마스크로 만들 때, 저장 해상도를 실제 물 세그멘테이션 프레임 해상도로 보정하지 않음 → 두 해상도가 다른 지점은 도로 ROI가 엉뚱한 자리를 가리켜 물 면적 비율이 조용히 낮게 나올 수 있었음 |
| 인파관리 분석/침입/배회 구역 | 위와 같은 이유로 동일 결함 |

○ 왜 두 해상도가 달라지나
　－ 실사용 CCTV 스트림은 화질이 시점에 따라 달라질 수 있고, ROI를
　　처음 그릴 때와 지금 뜬 화면이 다른 경로로 캡처됐을 수 있음
　－ **DB 전수 스캔 결과, ROI가 있는 31개 지점 중 9건(초량교차로·
　　광복로·광복로1, 각 3개 도메인)에서 저장 해상도 ≠ 실측 해상도 확인**
　－ ⚠ 왜 이 9건만 달라졌는지(스트림 화질이 실제로 바뀐 것인지,
　　캘리브레이션 때 다른 소스를 썼는지)는 **확인하지 못했습니다**

○ 이미 같은 유형의 결함을 교통·노면 도메인에서는 2026-08-22에 발견해
　`common/roi.py`의 `scale_polygons()`(비례 보정 함수)로 고쳐 두었으나,
　**침수·인파·화면 표시 세 곳은 그때 함께 고치지 못하고 남아 있었다**

## 3. 수정 내용

### 3-1. ROI 설정 화면(S-81) — 표시 보정

○ `service/templates/camera_roi.html`
　－ 저장 당시 해상도(`roi.frame_width`/`frame_height`)를 화면에 함께
　　실어, 지금 뜬 정지영상의 실제 해상도(`img.naturalWidth`)와 다르면
　　**화면에 로드되는 순간 좌표를 비례 보정**
　－ 해상도가 같거나 저장 해상도 정보가 없으면 원본 좌표를 그대로
　　씀(기존 동작 100% 보존)
　－ 보정된 좌표로 저장하면 그 시점부터는 DB의 저장 해상도도 갱신되어
　　다음부터는 자연히 일치함(자가 치유)

### 3-2. 침수 판정 — 실제 위험도 계산 보정

○ `flood/metrics_core.py`(`RoiMaskCache`)
　－ 도로·저지대 ROI로 마스크를 만들기 전에, 저장 해상도 → 실제 물
　　세그멘테이션 프레임 해상도로 `scale_polygons()` 적용
　－ 차선 기준선도 동일하게 보정
○ `flood/flood_metrics_engine.py`(실시간 경로), `flood/standalone_pipeline.py`
　（S-23 오프라인 분석）양쪽 모두 보정된 좌표를 쓰도록 수정
　－ 저지대 위험 인원 판정(`point_in_polygons`)도 마스크와 같은
　　보정본을 쓰도록 통일 — 마스크만 고치고 이 판정만 어긋나는 절반짜리
　　수정을 방지

### 3-3. 인파관리 — 분석/침입/배회 구역 보정

○ `crowd/live_analyzer.py`(`CrowdLiveAnalyzer`)
　－ `analysis_roi`·`intrusion_roi`·`loiter_roi`를 분석기 자신의 처리
　　해상도로 보정 후 사용(교통·노면과 동일한 방식)

### 3-4. 안내 문구 정정

○ `service/templates/camera_roi.html`의 "저장해도 서비스를 재시작해야
　탐지에 반영됩니다" 문구가 **도메인과 무관하게 고정**돼 있어, 이미
　즉시 반영되는 침수·교통·노면에도 잘못된 안내를 하고 있었음
　－ 저장 API가 실제로 반환하는 도메인별 안내와 일치하도록 조건부로
　　수정(인파만 재시작 필요, 나머지는 즉시 반영)

## 6. 추가(21:44) — "차선 기준선" 명칭을 "침수 경계선"으로 변경

○ 사용자 문의: "차선(주행 차로)이 여러 개면 침수 시 대부분 동시에
　잠기지 않나요? 그럼 이 선이 무슨 의미가 있나요?"

○ 확인 결과 — **애초에 차선(1차로/2차로)을 구분하는 선이 아니었음**
　－ `RoiConfig`는 카메라 1대당 이 선을 **1개만** 저장함(차선별로 여러
　　개 두는 구조가 아님)
　－ `flood/alert_engine.py`의 4단계(「위험」) 경보 규칙을 보면, 물
　　면적 비율(`water_area_ratio`)과 **무관하게** 이 선에 물이 닿기만
　　해도 단독으로 "위험" 등급을 올림 — 도로 전체의 20%가 잠겨야 나오는
　　경보와 같은 등급을 국지적인 접촉만으로 즉시 발동
　－ 즉 실제 정체는 "차선 구분"이 아니라 **"이 지점까지 물이 오면
　　이미 위험하다"고 보는 특정 위험 지점(트립와이어)** — 지하차도
　　진입부처럼 국지적으로만 물이 고이는 초기 단계에서, 면적 비율
　　기준으로는 아직 안 잡히는 위험을 조기에 잡기 위한 장치
