# 교통위험만 상시 지정한 카메라가 처리되지 않던 결함 수정

앤시정보기술(주) · 전략기획부 · 2026-08-23

---

## 1. 배경

○ 사용자 제보: CCTV 관리(S-80)에서 「범내골교차로」의 **교통위험만**
　「사용+상시」로 켜고(침수는 계속 「미사용」) 서비스를 재기동한 뒤
　교통위험 실시간 관제 화면을 확인하니 **그 지점이 안 보임**

○ 이 문제를 조사하던 중, "다른 CCTV들의 ROI 문제도 찾아 달라"는 이전
　요청에서 발견한 사실(카메라 39개소 중 절반 이상이 「탐지 지정
　꺼짐+ROI만 보관」 상태)과 연결되어, **더 근본적인 구조 결함**을
　확인했다.

---

## 2. 근본 원인

○ 상시 처리 루프(``PipelineRunner``, 실질적으로 전체 시스템에서
　CCTV 프레임을 실제로 읽어 판정을 도는 **유일한 루프**)의 대상
　목록이 그동안 **침수(flood) 도메인의 상시 지정 하나만** 보고
　있었다(``core/cameras.py::continuous_blocks(db, "flood")``).

○ 즉 **침수가 「미사용」인 카메라는 이 루프에 아예 올라가지 않는다.**
　교통위험 판정(``TrafficBehaviorTracker``)도 이 루프 안에서
　계산되므로, 침수가 꺼진 카메라는 교통위험을 아무리 「상시」로 켜도
　**애초에 처리될 기회 자체가 없었다.** ``/api/risk``(실시간 관제
　화면이 보는 API)는 이 루프의 결과만 돌려주므로, 화면에도 당연히
　나타날 수 없었다.

○ 부수적으로 확인된 위험 요소 — 「탐지 지정이 꺼져도 ROI는 지워지지
　않고 보관된다」는 기존 설계(운영자의 작업물 보호 목적) 때문에,
　**침수를 명시적으로 꺼 둔 카메라도 예전에 그려 둔 침수 ROI를 여전히
　갖고 있을 수 있다.** 이번 수정으로 처리 루프의 대상 범위를 넓히면서
　이 조합(침수 미사용 + 침수 ROI 보관)을 그대로 두면, **꺼 둔 침수
　판정이 보관된 옛 ROI로 조용히 다시 돌기 시작해 뜻하지 않은 침수
　알림까지 나갈 위험**이 있어, 이 부분도 함께 막았다.

## 3. 수정 내용

### 3-1. 처리 대상을 침수·교통위험 합집합으로 확장

○ `core/cameras.py`에 `continuous_blocks_any(db, domains)` 신설 —
　주어진 도메인 중 **하나라도** 상시 지정된 카메라를 중복 없이 합쳐
　블록 목록으로 만든다.
○ `service/main.py::_load_blocks()`, `service/runner.py::_desired_blocks()`
　（동적 재구성 — 재기동 없이 워커를 추가·제거하는 로직）양쪽 모두
　`continuous_blocks(db, "flood")` → `continuous_blocks_any(db,
　("flood", "traffic"))`로 교체.

### 3-2. 「지정 여부」와 「ROI 보관 여부」를 명확히 분리

○ `core/cameras.py::to_block_dict()`에 `flood_enabled` 플래그 신설 —
　**침수 도메인이 실제로 「사용」 지정돼 있는지만** 본다(ROI가 있는지와
　무관).
○ `service/runner.py::_block_loop()` — 침수 판정 실행(`_update_flood()`
　호출, ROI 재조회)을 전부 `flood_enabled`로 게이트. 침수가 미사용인
　카메라는 옛 ROI가 남아 있어도 물 세그멘테이션을 절대 돌리지 않는다.
○ `service/runner.py::water_backend_status()`(``/api/health``의 침수
　세그멘테이션 현황) — 「지점 수」·「적재된 모델 수」를 **실제로 침수가
　도는 블록만** 세도록 수정. 교통위험만 상시인 블록이 섞여 숫자가
　부풀지 않게 했다.

### 3-3. 화면·안내문 정합성

○ `service/main.py::flood_cameras()`(``/flood``·``/traffic`` 화면이
　함께 쓰는 「사용 지정 전체」 목록) — 침수 **또는** 교통위험 중
　하나라도 「사용」이면 포함하도록 확장. 교통위험만 사용으로 지정한
　카메라도 「선택(비상시)」 카드로라도 뜰 수 있게 했다.
○ `service/static/app.js::selectiveCard()` — 항상 "침수 ROI 미설정"
　이라고만 말하던 경고문을 침수·교통 ROI 중 하나라도 있으면 숨기도록
　일반화(교통위험 전용 카메라에 잘못된 문구가 뜨던 것 수정).
○ `service/routes_cameras.py`의 탐지 지정 저장 안내문 3곳 — 그동안
　**교통위험은 언급조차 없었다.** 이제 실제로 재기동 없이 반영되므로
　"교통위험 상시 탐지에 곧바로 반영됩니다" 문구를 침수·노면과 나란히
　추가.

## 4. 검증

○ 신규 자동 시험 6건 추가, 전부 통과
　－ `tests/core/test_continuous_blocks_union.py`(4건) — 교통위험만
　　상시여도 대상에 포함, 침수 ROI가 보관돼 있어도 `flood_enabled`는
　　거짓, 두 도메인 다 상시여도 블록 중복 없음, 둘 다 아니면 제외
　－ `tests/flood/test_flood_disabled_skips_update.py`(2건) —
　　`flood_enabled=False`면 `_update_flood()`를 절대 안 부름(회귀
　　방지: `flood_enabled=True`는 여전히 매 틱 부름)
○ 전체 회귀 `pytest tests -q` — **1,618건 통과, 3건 skip**(기존과
　동일, 신규 결함 없음)
○ 실제 서비스로 재현·확인
　－ 수정 전: `/api/health`의 `continuous.flood.targets`가 6개
　　（범내골교차로 미포함）
　－ 수정 후: **8개로 증가**, `/api/risk`에 범내골교차로가
　　`water_available: false`(침수 미실행, 정상)로 등장, `n_vehicles`
　　등 교통 지표는 정상 계산됨
　－ 브라우저로 직접 확인: **교통위험 탭에는 범내골교차로가 뜨고,
　　침수 탭에는 안 뜬다**(의도한 대로 도메인별로 정확히 분리됨)
○ `flood_t` 무변경(39건 그대로)

　수정과 무관하게 사람의 확인이 필요
