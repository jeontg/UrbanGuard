1. **외부 연계 규격을 하나도 확보하지 못했습니다** — 통합플랫폼·112·119·CBS·차단시설

3. **실제 알림 발송이 되지 않습니다** — SOLAPI 실발송 검증 미완

## 5. 기술 기반

### 5-1. DB (PostgreSQL 17.7)

| 테이블 | 용도 |
|---|---|
| `users` / `user_domains` | 계정·역할·담당 도메인 |
| `events` / `event_actions` | **이벤트와 조치 이력** (관제의 중심) |
| `notifications` | 통보 요청·승인·발송 |
| `facility_controls` | 시설물 제어 시도 (성공·실패 모두) |
| `citizen_reports` | 현장 제보 |
| `audit_logs` | 감사 추적 |
| `app_settings` | 화면에서 바꾸는 운영 설정 |
| **`cameras`** | **CCTV 지점 원장** (기존 `blocks.json` 대체) |
| **`camera_domains`** | **지점 × 탐지서비스 — 사용 여부와 상시 탐지 스위치** |
| **`camera_rois`** | **지점 × 탐지서비스별 관심영역** |

## 7. 정직하게 남기는 한계

### 7-1. 실환경 검증이 안 된 것

- **AI 모델 3종 모두 부산 실환경 미검증**입니다. 침수 모델은 해외 데이터로 학습해 val F1 0.9392를 냈지만 부산 실침수 영상으로 확인하지 못했습니다
- **도로 노면 모델은 탐지 0건**입니다. 해외 공개데이터 3회(RDD2022·Mendeley·Zenodo)가 모두 실패했고, 현장 제보(S-43)로 부산 데이터를 쌓는 것이 현재 유일한 경로입니다
- **인파 검출기 기본값이 mock**입니다. 실검출 전환은 화면에서 가능하나 부산 CCTV 실영상 검증이 선행돼야 합니다

### 7-2. 화면은 있으나 실제로 동작하지 않는 것

| 화면 | 상태 |
|---|---|
| 시설물 제어 | 모든 시설 **「미연계」** — 명령이 기록만 되고 전달되지 않음 |
| 기관 통보(112·119) | **기록만** — 실제 전송 안 됨 |
| 알림 발송 | **발송 차단 모드** — 승인해도 문자가 나가지 않음 |
| 강수·하천 | **모의값(sine)** — 실측 API 미연동 |
| **인파 검출** | **모의(mock) 소스** — 인원·위험행동이 실제 영상값이 아님 |
| **노면 탐지** | 모델은 도나 **부산 CCTV에서 탐지 0건** (도메인 갭) |
| **교통정보 API 수집** | 키 미발급 — 화면에서 버튼이 잠겨 있음 |
| 노면 탐지 결과 | **메모리 저장** — 재시작하면 「미분석」로 |

이 상태를 화면마다 고정 문구로 표시했습니다. **동작하는 것처럼 보이는 것이 가장 위험**하기 때문입니다.

### 7-3. 실측 검증 현황

08-12 갱신에서 수행한 실서버 검증입니다. 상세는 `test_plan_report.md` 3절.

| 확인한 것 | 결과 |

### 7-4. 상표

**솔루션명 `UrbanGuard` 는 특허청 정식 상표 조회를 거치지 않았습니다.** 웹 검색상 국내 소프트웨어 업계 충돌은 확인되지 않았으나, 대외 공표·인쇄물 사용 전 키프리스 42류 조회가 필요합니다. 그전까지는 **내부 명칭**으로만 취급해 주세요.

## 8. 1차 납품 범위 결정이 필요합니다

화면 34개 중 26개가 됐지만, **어디까지를 1차 납품으로 볼지 정해지지 않았습니다.**

제 판단으로는 **지금 상태가 「시범운영 가능한 최소 제품」**에 해당합니다.

- 인증·권한·감사추적 완비
- 탐지 → 이벤트 → 조치 → 통보 흐름 완결
- 지자체 자체 운영(지점·ROI·임계값) 가능

다만 시범운영에 들어가려면 **최소한 아래 셋은 필요**합니다.

1. **SOLAPI 실발송 검증** — 알림이 실제로 나가야 의미가 있습니다
2. **KMA 인증키** — 강수가 모의값이면 위험도 판정이 실제와 무관합니다
3. **배포 환경 결정** — 망분리 여부에 따라 연계 방식이 전부 달라집니다
