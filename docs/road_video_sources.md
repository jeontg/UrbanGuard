## 2. 권장 진행 순서 (v2)

**먼저 SVRDD 로 판별합니다.** 승인 절차가 없어 오늘 착수할 수 있고, 결과에 따라
뒤 단계가 갈립니다.

1. **SVRDD 확보 → 변환 → 빠른 판별 학습 → 부산 CCTV 검증** ← 착수 중 (08-12)
   ```
   python scripts/prepare_svrdd_yolo.py
   python scripts/train_svrdd.py
   python scripts/eval_svrdd_on_cctv.py --model <best.pt>
   ```
2. 판별 결과에 따라 갈림
   - **신호가 잡히면** → AI Hub 협의 진행(3·4순위 대량 데이터로 성능 확보)
   - **또 0건이면** → 데이터로는 해결되지 않는다는 뜻. **노면 전용 촬영**
     (차량 탑재·저각 설치) 도입 검토로 넘어갑니다
3. 병행: AI Hub **상업적 이용 조건 확인** — 결과와 무관하게 미리 확인해 두어야
   합니다(협의에 시간이 걸립니다)
4. 병행: 공공데이터포털 CCTV 목록으로 실시간 모드 지점 확대
5. 병행: 담당자 보유 영상을 **S-44 「가진 영상에서 프레임 뽑기」** 로 투입
   — 현장 촬영·블랙박스 영상이 있으면 부산 실환경 데이터로 가장 값집니다

### ⚠️ 학습 환경 제약 (2026-08-12 확인)

현재 개발 장비는 **GPU 가 없습니다** (`torch 2.13.0+cpu`, CPU 16코어).

- 8,000장 × 1024px 전량 학습은 CPU 로 **며칠짜리** 작업입니다
- 그래서 `train_svrdd.py` 의 기본값을 **빠른 판별**(표본 25% · 640px · 12에폭)로
  두었습니다 — 성능 수치가 아니라 「신호가 잡히는가」만 봅니다
- 실사용 수준의 모델을 만들려면 **GPU 도입 또는 학습 외주**가 필요합니다.
  1차 납품 범위를 정할 때 함께 판단해야 할 사안입니다

## 2-1. SVRDD 시험 결과 (2026-08-13) — **실시간 CCTV 모드는 여기서 접습니다**

**결론 — 더 학습할수록 부산 CCTV에서는 나빠졌습니다.** 자기 도메인 성능은
올랐는데(mAP50 0.168 → 0.269) 부산 CCTV의 **오탐은 12건에서 43건으로 늘고
신뢰도까지 높아졌습니다.** 전형적인 도메인 과적합입니다.

| 조건 | RDD2022 (v1·v2) | SVRDD 10에폭 | **SVRDD 14에폭** |
|---|---|---|---|
| 자기 도메인 mAP50 | 0.193 / 0.23 | 0.168 | **0.269** (미수렴) |
| 부산 CCTV conf 0.25 | **0건** | 12건 / 6장 | **43건 / 16장** |
| 그 탐지의 정체 | — | 전부 차선 도색 | **전부 차선 도색** |
| 최고 신뢰도 | — | 0.45 | **0.59** |
| 포트홀 (conf 0.25) | 0건 | 0건 | **0건** |

- 학습 조건: 학습셋 40%(2,400장) · 640px · 14에폭 · CPU 총 **18시간**
- 탐지 16장 중 **15장이 같은 지점(재송삼익)** 입니다. 그 지점 화면을 가로지르는
  구조물과 차선이 균열로 읽힙니다
- 자기 도메인(SVRDD val)에서는 **실제 균열을 잡습니다** — 학습은 정상입니다

**왜 더 나빠졌나** — 45° 부감을 학습할수록 「도로 근경의 가늘고 긴 선」에
민감해집니다. 240p 에서는 **차선 도색과 균열이 물리적으로 구분되지 않으므로**,
민감해질수록 차선을 더 확신 있게 신고하게 됩니다.

**운영 관점에서 이건 0건보다 나쁩니다.** 아무것도 못 잡는 모델은 운영자가
「아직 안 된다」고 알지만, 차선을 균열로 신고하는 모델은 **한 번 겪으면 그 뒤로
아무도 결과를 믿지 않습니다.**

### 판정

- **실시간 CCTV 모드(240p)** — ✗ **데이터·학습으로 해결되지 않습니다.** 세 번의
  시도(RDD2022 v1·v2, SVRDD)가 모두 실패했고, 마지막은 더 학습할수록 나빠졌습니다.
  적합도 평가에서 8곳 중 7곳이 「라벨링 불가」로 나온 것과 같은 결론입니다
- **기존 영상 모드(고해상도)** — **판정 보류.** 시험할 자료가 없습니다. 보유한
  것은 초근접 촬영(Mendeley, 9/10 탐지 0건 — 또 다른 도메인)과 침수 영상
  (노면이 물에 잠겨 손상이 보이지 않음)뿐입니다.
  **손상이 보이는 주행·순찰 영상**이 있으면 S-44 업로드로 바로 판정할 수 있습니다

**재현 방법**
```
python scripts/eval_svrdd_on_cctv.py \
    --model data/datasets/svrdd/runs/svrdd_quick/weights/best.pt
```
⚠️ 탐지 **건수만 보고 판단하지 마십시오.** 반드시 표본 이미지를 눈으로 확인해야
합니다 — 이번 두 차례 모두 건수는 「신호」처럼 보였지만 전부 오탐이었습니다.

## 3. ⚠️ 데이터 확보만으로 해결되지 않는 문제

**CCTV 시점(고가 10m·광각·240p) 공개 데이터셋은 이번 조사에서도 찾지 못했습니다.**
조사한 모든 데이터셋이 차량 탑재 아니면 드론입니다. SVRDD 의 45° 부감이 가장
가깝지만 그래도 **차량 지붕 높이(~2.5m)** 입니다.

그리고 이건 데이터만의 문제가 아닙니다. 2026-08-12 적합도 평가
(`scripts/assess_road_label_feasibility.py`) 결과, 등록된 노면 지정 CCTV
**8곳 중 7곳이 「불가」**였습니다 — 짧은 변 240px 에서는 손상이 몇 픽셀이라
**사람도 라벨 박스를 그을 수 없습니다.** 사람이 못 보는 것을 모델에게
기대할 수는 없습니다.

| 모드 | 전망 |
|---|---|
| **「기존 영상」 모드** (업로드 영상 분석) | 이번 데이터셋들로 **실용 수준까지 갈 수 있음** |
| **「실시간 CCTV」 모드** | 해상도가 물리적 한계 — **데이터로 해결되지 않음** |

→ 실시간 모드까지 실용화하려면 **노면 전용 촬영 수단**(차량 탑재 카메라, 저각
설치)의 도입 검토가 병행되어야 합니다
(`docs/road_surface_management_plan.md` 3-3절).

→ 그 전까지 실시간 CCTV 모드는 **「점검이 필요한 지점을 좁히는 용도」**로
한정해 제안하는 것이 정직합니다. 「CCTV 로 포트홀을 자동 탐지한다」고 쓰면
현장에서 성립하지 않습니다.
