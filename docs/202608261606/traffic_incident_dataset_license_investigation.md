> 목적: 교통위험 미보유 탐지 기능 추가 계획(Phase 7)의 「데이터 출처는 지금
> 단정하지 않는다」 원칙에 따라, 실제 데이터셋을 채택하기 전에 후보와
> 라이선스를 먼저 조사한다. `docs/yolo_license_alternatives.md`의 조사

> 작성 기준일: 2026-08-26. 라이선스 정보는 이 시점의 웹 조사 결과이며,

## 0. 결론 요약

- **어느 데이터셋도 이번 회차에 채택하지 않았습니다.** 조사만 했습니다 —
  실제 도입은 법무 검토와 사용자 결정이 선행돼야 합니다(계획 문서
  §Phase 7 확정 사항).
- **화재·연기**는 후보가 여럿이고 그중 **D-Fire가 CC0(퍼블릭 도메인급)로
  가장 안전**해 보입니다 — 다만 원저작물(수집 당시 SNS·언론 영상 여부)
  까지는 이번 조사로 확인하지 못했습니다.
- **낙하물(도로 잔해)**은 화재·연기보다 후보가 훨씬 적고, **검색으로 찾은
  라이선스 표기(CC0)를 직접 원본 페이지에서 확인하지 못했습니다** —
  Kaggle 페이지가 자바스크립트 렌더링이라 이번 조사 도구로 라이선스
  탭을 직접 못 열었습니다. **채택 전 반드시 재확인이 필요합니다.**
- **합성(synthetic) 데이터로 우회하는 대안도 있습니다** — HazardNet
  논문(§3)이 실제 사진 대신 벽돌·상자·바위를 고속도로 장면에 합성해
  넣는 방식을 씁니다. 라이선스 문제 자체를 피할 수 있어 매력적이나,
  우리 부산 CCTV 화각·화질과의 도메인 갭은 별도로 검증해야 합니다
  (`docs/road_surface_management_plan.md`에서 겪은 것과 같은 함정).

가 늘 강조하는 원칙과 동일).

## 2. ⚠️ FLAME1의 "GNU GPL" 표기 — 법무 확인 필요

데이터셋에 **소프트웨어 라이선스**(GPL)가 붙어 있는 것은 이례적입니다.
가능한 해석 두 가지:
1. 데이터셋을 다루는 **코드**(전처리 스크립트 등)에 GPL이 붙어 있고
   데이터 자체는 별도 조건일 수 있음
2. 배포자가 실제로 데이터셋 전체를 GPL로 선언했을 수 있음(그렇다면
   GPL의 카피레프트 조항이 이 데이터로 학습한 모델에 어떻게 적용되는지
   해석이 필요 — Ultralytics AGPL 검토(`docs/yolo_license_alternatives.md`
   §2 "가중치가 파생물인지")와 같은 부류의 미해결 쟁점)

→ **FLAME1은 채택 후보에서 일단 제외**하고, 필요해지면 원 배포처에서
라이선스 문구를 직접 확인 후 법무 검토를 받으십시오.

## 4. 대안 — 합성(synthetic) 데이터로 우회

[출처: arXiv 2303.07547 "HazardNet: Road Debris Detection by Augmentation
of Synthetic Models" (CVPR 2023 워크숍)]

실제 사진을 수집·배포받는 대신, **벽돌·종이 상자·바위** 같은 대표
잔해 물체를 고속도로 장면에 **합성으로 끼워 넣어** 학습 데이터를 만드는
접근입니다.

| 항목 | 내용 |
|---|---|
| 장점 | 원저작물 라이선스 문제 자체가 없음(합성 소스는 자체 제작 3D 모델) — 법무 검토 부담이 가장 낮음 |
| 단점 | 합성 이미지와 실제 CCTV 화질·화각의 도메인 갭 — 노면 손상(Phase 2)에서 겪은 「공개 데이터셋 학습 → 부산 CCTV 완전 실패」 사례(`docs/road_surface_management_plan.md`)가 재현될 위험 |
| 적용 판단 | **이번 회차에서 채택 여부를 정하지 않습니다.** 실제 낙하물 데이터 확보가 어려울 경우의 차선책으로만 기록해 둡니다 |

## 6. 권고 진행 순서

1. **[선행] 화재·연기 — D-Fire 원문 라이선스 재확인** — `github.com/gaiasd/DFireDataset`
   README를 직접 열어 CC0 표기와 원저작물 수집 경위(자체 촬영인지 SNS
   수집인지)를 확인
2. **[선행] 낙하물 — 후보 3건 원문 재확인** — 특히 Kaggle "Road Issues
   Detection Dataset"의 라이선스 탭을 실제로 열어 CC0 여부 확정
3. **법무 검토** — 확정 후보의 라이선스가 공공기관 납품물 학습 데이터로
   적합한지, FLAME1류의 GPL 표기 데이터는 배제할지 확인
4. **소규모 파일럿** — `scripts/extract_traffic_incident_frames.py`로
   확정 데이터셋 일부를 변환해 `scripts/train_traffic_incident_yolo.py`
   로 시험 학습 → 부산 CCTV 실측(노면 손상에서 겪은 도메인 갭이
   재현되는지 먼저 확인)
5. **본 채택 및 `detectable=True` 전환** — 시험 학습 성능이 충분히
   검증된 뒤에만(`core/vocabulary.py`의 `traffic_debris`·
   `traffic_fire_smoke`)

## 7. 법무 확인 필요 사항

1. **CC0 데이터셋도 원저작물 권리가 정리됐는지** — `docs/flood_water_dataset_workflow.md`
   가 겪은 Mendeley 사례("CC BY 4.0은 포장에만 적용, 원저작물은 SNS
   게시물이라 별도")와 같은 함정이 화재·낙하물 데이터셋에도 있을 수
   있습니다
2. **FLAME1의 GPL 표기가 실제로 데이터셋 전체에 적용되는지** — 적용된다면
   그 데이터로 학습한 모델이 GPL 파생물로 간주되는지(확정된 법률 해석
   아님)
3. **CCTV로 촬영된 화재·사고 현장에 특정인이 식별 가능하게 나올 경우의
   개인정보 문제** — 인파 도메인에서 이미 다루는 마스킹 절차
   (`core/image_mask.py`)를 낙하물·화재연기 학습 데이터에도 적용해야
   하는지
4. **공공기관 납품 계약상 학습 데이터 출처 명시 의무** — 제안서·산출물에
   데이터셋 출처를 어떻게 표기해야 하는지
