## 0. 결론 먼저

○ **한 소스가 한 도메인에만 쓰이지 않습니다.** ITS·TOPIS는 이미 침수·교통위험
　·도로 노면 **3개 도메인에 동시에** 쓰이고 있습니다(카메라 하나 = 도로를
　찍고, 그 도로가 침수도 되고 정체도 되고 파손도 됩니다).

○ **4개 도메인 중 3개는 이미 최선의 소스를 쓰고 있습니다.** 교통위험·침수·
　도로 노면 전부 ITS/TOPIS가 정답이거나 정답에 가장 가깝고, 새로 찾은 후보는
　"보강"이지 "교체"가 아닙니다.

○ **인파관리만 지금 국내에 마땅한 소스가 없어 해외(TfL)로 보강**하는
　상황입니다 — 지난 조사 그대로입니다.

○ **도로 노면은 "적합한 CCTV가 없다"가 이미 결론입니다.** 억지로 후보를
　고르지 않았습니다 — 이유는 2절 참고.

| 도메인 | 최적 소스 | 상태 |
|---|---|---|
| 침수 | **ITS/TOPIS**(현재 쓰는 지하차도·저지대 교차로 지점) + 홍수통제소 하천 CCTV(보강, 확인 필요) | 이미 최선 사용 중 |
| 교통위험 | **ITS/TOPIS** | 이미 최선 사용 중 — 목적 자체가 일치 |
| 인파관리 | **TfL JamCams**(해외) — 국내는 구조적으로 없음 | 이번에 신규 확보(`scripts/collect_tfl_frames.py`) |
| 도로 노면 | **없음** — CCTV 화각 자체가 이 문제에 안 맞음(결론 확정) | 대안: 근접 촬영 영상(대시캠형) |

## 1. 도메인별 상세

### 1-1. 침수 — ITS/TOPIS(주력) + 홍수통제소 하천 CCTV(보강 후보)

**왜 ITS/TOPIS가 최적인가**: 침수 판정은 "도로 위에 물이 찼는가"를 보는
것이라, 애초에 도로를 향한 카메라가 필요합니다. 지금 상시 탐지 중인 9개
지점(`configs/blocks.json`)이 전부 ITS/TOPIS 소스이고, 그중 SEOUL-1042
「도봉지하차도 출구」처럼 **지하차도·저지대 교차로**를 고른 것도 이미
침수 위험이 큰 지점을 겨냥한 선택입니다. **바꿀 이유가 없습니다.**

**보강 후보 — 홍수통제소 하천 CCTV(수위관측용)**

| 소스 | 성격 | 확인 필요 사항 |
|---|---|---|
| 한강·금강·낙동강·영산강 홍수통제소(`hrfco.go.kr` 등) 「수위관측 CCTV」 | 하천 수위를 직접 보는 카메라 — 강 자체의 범람 여부에 특화 | ⚠ 페이지에 "오픈 API" 메뉴가 있으나 CCTV 영상 자체의 API 규격은 확인하지 못함. 이미 `HRFCO_API_KEY`(`.env.example`)로 **수위 숫자 API는 연동 대상으로 잡혀 있음** — 영상까지 되는지는 한강홍수통제소(02-590-9999) 문의 필요 |
| 한국수자원공사 「기타수계 실시간 CCTV」(공공데이터포털) | 부안댐·보령댐·장흥댐·수어댐 각 2개 지점(총 8개) | ⚠ **파일 다운로드 방식이고 최초 30초만 제공** — 상시 모니터링용이 아니라 참고용. 커버 지역도 우리 사업권역(부울경)과 거리가 있음 |

**판단**: 하천 CCTV는 "강물이 넘치는가"를 보는 것이고, 우리 침수 도메인은
"도로가 잠기는가"를 봅니다 — **성격이 미묘하게 다릅니다.** 상류 하천
수위가 급격히 오르는 것을 **선행 경고 신호**로 참고하는 용도로는 의미가
있으나, 도로 침수 탐지 모델 자체의 학습 데이터로 쓰기엔 화각이 다릅니다.
우선순위는 낮게 둡니다.

### 1-2. 교통위험 — ITS/TOPIS

**추가 조사가 필요 없는 도메인입니다.** ITS/TOPIS는 애초에 "교통 소통정보용"
으로 만들어진 카메라라 목적이 완전히 일치합니다. 지금 교통위험 상시 탐지
9개 지점 전부 이 소스이고, 차량 검출(YOLO11s)·정체·정지차량 판정에 그대로
씁니다. **더 찾을 필요가 없는 유일한 도메인입니다.**

참고로 해외의 TfL JamCams·NYC DOT도 원래 교통 카메라라 국내 소스와 성격이
같습니다 — 다만 굳이 해외 것을 쓸 이유가 없습니다(국내 커버리지가 이미
충분).

### 1-3. 인파관리 — TfL JamCams(신규 확보)

**국내는 구조적으로 막혀 있습니다** — 방범·다중이용시설 CCTV(광장·역사·
상점가)는 「개인정보 보호법」 제25조상 지자체 CCTV통합관제센터 전용망
안에서만 흐르고 외부 제공 창구가 없습니다. 국내에서 그나마 가까운 것은
해양수산부 해수욕장 CCTV(계절 한정, API 개방 여부 미확인)뿐이었습니다.

그래서 이번 회차에 **런던 TfL JamCams**를 실제로 연동했습니다
(`scripts/collect_tfl_frames.py`, `TFL_APP_KEY` 발급·적용 완료). 890개
지점 중 Piccadilly Circus·Oxford St처럼 **보행자가 실제로 몰리는 지점**을
확인했고, 실제 수집까지 검증했습니다.

⚠ **런던 CCTV라 부산과 화각·인종·조도가 다릅니다** — 도로 손상 탐지가
겪은 도메인 갭이 재현될 위험이 있어, **학습 데이터 다양성 보강용**이지
주력 데이터가 될 수 없습니다. 인파관리는 현재 mock 모드로 운영 중이라
(`docs/202608250759/detection_tech_stack.md`), 이 데이터가 **처음으로
확보하는 실사용 이미지**라는 데 의미가 있습니다.

### 1-4. 도로 노면 — 적합한 CCTV가 없습니다 (이미 결론 확정)

**억지로 후보를 고르지 않았습니다.** `docs/road_surface_management_plan.md`
가 이미 4회 실측으로 확정한 결론이 있습니다 — **어떤 CCTV를 갖다 써도
안 됩니다.** 이유는 도메인 자체의 문제입니다:

- CCTV는 **고가·광각·저해상도(240~720px)** 로 도로 "전체"를 봅니다
- 균열·포트홀은 **가까이서, 좁은 화각으로 봐야** 보입니다
- 더 학습할수록(RDD2022 15→50에폭, SVRDD 10→14에폭) 부산 CCTV 오탐이
  **오히려 늘었습니다**(3.6배) — 각도를 학습할수록 "도로 위 가는 선"에
  민감해져 **차선 도색을 균열로 착각**하는 정반대 효과가 났습니다
- **정반대 조건**(스마트폰 근접 촬영 포트홀 영상)에서도 시험해봤지만
  똑같이 0건 — CCTV든 아니든 "화각" 자체가 근본 원인임을 재확인했습니다

**그래서 필요한 건 CCTV가 아니라 "근접 촬영 영상"입니다.** 이미 확보한
자체 후보(RDD2022·SVRDD)도 그런 방향(차량 블랙박스·주행 영상)입니다.
오픈 CCTV 조사로 이 문제를 풀 수 없다는 것이 이번 조사로도 재확인됐습니다.

지금 상시 순회(ITS/TOPIS, 7개 지점, 15분 주기)는 **"점검이 필요한 지점을
좁히는 참고 자료"** 로만 쓰고 있고, 화면에도 그렇게 안내돼 있습니다 —
이 용도로는 지금 쓰는 소스로 충분하며 바꿀 이유가 없습니다.

## 4. TfL JamCams 안에서 다른 3개 도메인에 쓸 지점이 있는가 (2026-08-25 추가 조사)

사용자 질문 — "TfL JamCams 중에서 다른 탐지(교통·침수·도로노면)에 활용
가능한 CCTV가 있나요?"에 대해, **890개 지점 전체 목록을 실제로 내려받아
지점명·화각 설명을 직접 분석**했습니다(추측이 아니라 실측).

### 4-1. 교통위험 — 사실상 전부 해당

TfL JamCams는 **애초에 전부 교통 카메라**입니다. 사용 가능한 844개
지점 전부가 차량 검출·정체·정지차량 판정에 그대로 쓸 수 있는 화각입니다.
4개 도메인 중 **가장 자연스럽게 맞는 도메인**입니다 — 다만 §1-2에서 이미
정리했듯, 국내 ITS/TOPIS가 이미 충분해 실익은 낮습니다(학습 데이터
다양성 보강 정도).

### 4-2. 침수 — 지하차도·터널 지점 27개 확인

지점명·화각 설명에서 "underpass"·"tunnel"·"low bridge" 등 정밀 키워드로
걸러 **실제로 27개 지점**을 확인했습니다. 한국의 「지하차도」에 해당하는
구조물입니다:

| 지점 | 위치 설명 |
|---|---|
| A406 Abbey Road Underpass | 지하차도 진입부 |
| Croydon Underpass(2개 카메라) | 지하차도 진입부 남/북 |
| Blackwall Tunnel(북·남 진입부 다수) | 템스강 하저터널 진입부 |
| Rotherhithe Tunnel(진입부·차단기 다수) | 템스강 하저터널 |
| Hanger Lane Tunnel(A40) | 터널 진입부 |
| Tolworth Underpass | 지하차도 |
| Stag Lane underpass | 지하차도 |
| Limehouse Tunnel(동·서) | 터널 |

추가로 **템스강변 도로(Embankment) 4개 지점**(Chelsea Embankment 등)도
확인했습니다 — 강물 수위 상승이 도로에 영향을 주는 장면을 볼 수 있는
자리입니다.

**판단**: 국내 지하차도와 구조적으로 같은 장면(터널·지하차도 진입부)을
**평상시(맑은 날) 기준으로** 확보할 수 있어, "이 구조물이 정상일 때 어떻게
보이는가"를 학습 데이터에 다양하게 추가하는 데 의미가 있습니다. 다만
**런던에 실제 폭우가 오는 순간을 포착해야 침수 장면 자체를 얻습니다** —
평상시 이미지만으로는 배경(네거티브) 샘플로서의 가치가 큽니다(침수
모델이 배경 샘플 부족으로 오탐이 났던 경험 — `docs/flood_water_dataset_workflow.md`
참고).

### 4-3. 도로 노면 — 여전히 부적합 (실측으로 재확인)

실제로 지하차도 카메라 2곳의 이미지를 내려받아 해상도를 확인했습니다:

| 지점 | 실측 해상도 |
|---|---|
| A406 Abbey Road Underpass | **352×288** |
| A40 Hanger Lane Tunnel | **352×288** |
| Croydon Underpass | **352×288** |

890개 중 262개(31%)는 화각 설명에 "ZOOM"이 붙어 있어 더 좁게 확대해
찍지만, **줌은 화면 구도만 바꿀 뿐 실제 픽셀 해상도는 그대로 352×288로
고정**돼 있습니다. 이는 부산 CCTV(240~720px)보다 오히려 낮은 편입니다.

**판단**: §1-4의 결론이 TfL에도 그대로 적용됩니다 — **해상도·화각
문제는 카메라를 바꾼다고 풀리지 않습니다.** 도로 노면 도메인에는
TfL도 대안이 되지 못합니다.

### 4-4. 종합

| 도메인 | TfL 활용 가능 지점 | 실익 |
|---|---|---|
| 교통위험 | 844개 전부 | 낮음(국내 소스로 충분) |
| 침수 | 27개(지하차도·터널) + 4개(강변도로) | **있음** — 배경 샘플 다양성 보강 |
| 도로 노면 | 0개 | **없음** — 해상도 문제 실측으로 재확인 |
