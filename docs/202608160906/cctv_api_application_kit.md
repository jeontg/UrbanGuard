## 0. 먼저 알아야 할 것 — 신청 창구가 둘로 갈립니다

공공데이터포털(data.go.kr)의 **「국토교통부_CCTV 화상자료」는 `LINK` 유형**입니다.
LINK 유형은 포털이 데이터를 직접 주지 않고 **제공기관 사이트로 넘깁니다.**
따라서 포털에서 「활용신청」을 눌러도 그것만으로 인증키가 나오지 않습니다.

| 경로 | 무엇을 하는 곳 | 결과 |
|---|---|---|
| **① its.go.kr** (권장) | 회원가입 → 마이페이지 → **인증키 발급현황 → 인증키 신청** | **실제 인증키** |
| ② data.go.kr 15040466 | 활용신청(개발·운영 자동승인·무료) | 활용 이력 · 제공기관 안내 |

**①이 실제로 키를 받는 경로입니다.** ②는 공공데이터 활용 실적으로 남으므로
제안서에 「공공데이터 활용」을 쓸 계획이면 함께 해 두면 좋습니다.

> ⚠️ **확인 못 한 것**: ITS 인증키 신청 화면의 **정확한 입력 항목과 승인
> 소요시간**은 로그인해야 보여 확인하지 못했습니다. 아래 3절 문안은 공공데이터
> 신청서에 공통으로 들어가는 항목 기준으로 준비한 것이며, 실제 화면의 항목명이
> 다를 수 있습니다.

## 1. 활용목적 범위 — **실증과 학습을 모두 명시합니다** (2026-08-16 결정)

활용목적에 **① 탐지 기능 실증**과 **② 자체 학습 데이터 구축**을 **둘 다** 적습니다.

**왜 둘 다인가.** 목적을 좁게 적어 두고 나중에 학습에 쓰면 **목적 외 이용**이
됩니다. 목적 변경 신청을 다시 하는 것보다, 처음부터 실제로 할 일을 그대로
적는 편이 정확합니다.

> **발주처 질문 9번과는 별개입니다.** 질문 9번은 「**지자체 관제 CCTV**를 AI
> 학습에 써도 되는가」이고, 이번 신청은 **국토부가 공개하는 교통 CCTV**입니다.
> 제공 주체도 근거도 다르므로, 이번 결정이 질문 9번을 앞질러 정하는 것이
> **아닙니다.** 질문 9번은 그대로 미회신 상태로 둡니다.

**대신 감수할 것.** 학습 목적을 적으면 심사가 더 볼 수 있습니다. 그래서 3-2
문안에 **보호조치(차량번호판·보행자 비식별, 외부 미반출, 목적 달성 후 파기)를
함께 적어** 심사자가 판단할 재료를 먼저 제시합니다.

## 3. 활용목적 문안 (그대로 붙여 쓰시면 됩니다)

### 3-1. 짧은 문안 (100자 내외 칸용)

```
지자체 도시안전 관제 솔루션(UrbanGuard)의 침수·인파·도로노면 자동탐지 기능
실증과 탐지모델 자체 학습데이터 구축을 위해 교통 CCTV 실시간 영상을
활용하고자 합니다.
```

### 3-2. 상세 문안 (긴 칸용)

```
1. 활용 시스템
   앤시정보기술(주)가 개발 중인 지자체 도시안전 통합관제 솔루션
   'UrbanGuard'입니다. 지방자치단체 관제센터에 설치되는 온프레미스
   웹 서비스로, 도로 침수·인파 밀집·도로 노면 상태를 CCTV 영상에서
   자동으로 판별해 담당자에게 알리는 것을 목적으로 합니다.

2. 활용 방법 (1) — 실시간 탐지 실증
   교통 CCTV 실시간 스트리밍(HLS) 영상을 수신하여 화면 내 위험 상황을
   자동 분석하고, 그 결과를 관제 화면에 표출합니다. 영상 자체를 재배포하거나
   외부에 공개하지 않으며, 분석 결과(위험도·발생시각·지점)만 시스템 내부에
   기록합니다.

3. 활용 방법 (2) — 탐지모델 학습데이터 구축
   탐지 정확도 개선을 위해 수신 영상에서 정지 프레임을 추출하여 자체
   학습데이터로 활용합니다. 국내 도로 환경(노면 표시, 배수구 형태, 강우 시
   반사 등)을 반영한 데이터가 없으면 실사용 수준의 정확도를 확보하기
   어렵기 때문입니다.

   보호조치
   - 학습 프레임에서 차량번호판과 보행자 얼굴은 비식별 처리합니다.
   - 학습 데이터는 사내 폐쇄망에 보관하며 외부로 반출하지 않습니다.
   - 목적 달성 후 파기하며, 파기 시점은 이용약관과 제공기관 지침을
     따릅니다.
   - 원본 영상은 저장하지 않고, 분석·학습에 필요한 프레임만 취득합니다.

4. 활용 지역
   부산광역시·울산광역시·경상남도를 우선 대상으로 하며, 사업 확대 시
   타 시·도로 넓힐 계획입니다.

5. 현재 단계
   솔루션 개발 및 기능 실증 단계입니다. 지점별 영상 품질(해상도)에 따라
   탐지 정확도가 달라지므로, 실제 적용 가능한 지점을 선별하기 위해
   API 활용이 필요합니다.
```

> **학습 목적을 뺀 문안이 필요할 때**(제공기관이 학습 활용을 제한하는 것으로
> 확인되는 경우) 위 3번 항목 전체를 지우고 번호만 당기면 됩니다.

## 4. 키를 받은 다음 — 우리 쪽 절차

### 4-1. 시스템에 넣기

`D:\dev-PoC\UrbanGuard\.env` 에 아래 한 줄을 넣고 서비스를 재시작합니다.

```
ITS_API_KEY=발급받은_인증키
```

### 4-2. 바로 확인 — 고해상도 지점이 실제로 있는가

```bash
python scripts/probe_cctv_resolution.py --region seoul --limit 40 --csv seoul.csv
```

`--region` 에 쓸 수 있는 값(17개 시도):
`busan` `ulsan` `gyeongnam` `seoul` `incheon` `gyeonggi` `gangwon`
`chungbuk` `chungnam` `daejeon` `sejong` `jeonbuk` `jeonnam` `gwangju`
`gyeongbuk` `daegu` `jeju`

**이 결과가 이번 신청의 핵심 판단 근거입니다.** 지금 등록된 부산 7개소는
실측 결과 **전부 SD(최고 720×480, 대부분 320×240)** 였습니다. 다른 지역에
HD 이상 지점이 실제로 있는지가 확인되어야 「고해상도 기반」이라는 제안이
성립합니다.

### 4-3. 화면에서 등록

S-80 CCTV 관리 → **① 교통 CCTV 자동 수집** → 지역과 **최소 해상도**(기본
HD 이상) 선택 → 불러오기 → 확인 후 등록.

## 6. 확인하지 못한 사항

| # | 내용 | 확인 방법 |
|---|---|---|
| 1 | ITS 인증키 신청 화면의 **정확한 입력 항목** | 로그인 후 확인 |
| 2 | ITS **승인 소요시간·일일 호출 제한** | 신청 화면 안내 확인 |
| 3 | `cctvresolution` 필드의 **값 표기 형식** | 키 발급 후 실제 응답 확인 |
| 4 | 영상의 **2차 활용·재배포 제한 조건** | 이용약관 확인 — **제안서 작성 전 필수** |
| 5 | **학습 활용을 약관이 허용하는지** | 이용약관 확인 — **접수 전에 확인** |

> 6-4·6-5는 특히 중요합니다. 관제 화면에 실시간 표출하는 것, 분석 결과를
> 저장·보고하는 것, 프레임을 추출해 학습에 쓰는 것은 **허용 범위가 각각 다를
> 수 있습니다.** 6-5에서 제한이 확인되면 3-2 문안의 3번 항목을 빼고 접수하되,
> 그 경우 **학습 목적 사용은 별도 승인 전까지 하지 않습니다.**
