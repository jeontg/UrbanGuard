# 왼쪽 메뉴 기능별 재분류 + 교통위험 판정 임계값 설정 화면 신설

## 1. 배경

○ 사용자가 왼쪽 메뉴 스크린샷을 보며 "기능별로 재분류해 달라"고 요청.
　코드(`core/auth.py::menu_for()`) 확인 결과 "설정" 그룹 1개에 12개
　항목, "관리자" 그룹에 6개 항목이 뒤섞여 있었음.

○ 뒤이어 "메뉴 명명도 기능과 일치하는지 검사해 달라"는 요청에 각 화면의
　실제 라우트 코드를 대조해 **이름과 실제 범위가 어긋나는 항목 2건**을
　발견:
　－ "위험도 임계값(S-82)"·"알림 규칙(S-83)" — 이름은 도메인 전체
　　같지만 코드에 `domain=Domain.FLOOD`로 고정된 **침수 전용** 화면
　－ "AI 모델(S-84)"·"AI 모델·침수(S-84)" — **화면번호가 중복**되고,
　　메뉴 이름이 각 화면 자체 제목과도 다르며, 다른 그룹의 "AI 모델
　　운영(S-61)"과도 이름이 겹침

○ 확인을 거쳐 범위 확정: 도메인 전용 설정은 그 도메인 그룹으로 이동,
　침수 외 3개 도메인(교통위험·인파관리·도로 노면 관리)에도 도메인
　설정 항목 추가, 교통위험은 대응할 기존 화면이 없어 **판정 임계값까지
　편집 가능한 신규 화면**을 만들기로 확정, 관리자 그룹도 기능별로 분할.

## 2. 최종 메뉴 구조 (11개 → 15개 그룹)

```
관제 · 이벤트 · 침수(+위험도 임계값·알림 규칙) · 교통위험(+위험도 임계값
신규·위험등급 관리) · 인파관리(+위험등급 관리) · 도로 노면 관리(+위험등급
관리) · 대응 · 알림·통보 · 분석(통계·성과 리포트만) · 카메라·지점 관리
(신설) · SOP 관리(신설) · AI 모델 관리(신설, 3개 화면 통합) · 시스템·기관
관리(신설) · 계정·감사(신설) · 오류·증거 관리(신설)
```

○ 도메인 전용 화면(코드에 domain 하드핀)은 그 도메인 그룹 안으로,
　여러 도메인이 함께 쓰는 화면(위험등급 관리 S-95)은 **관련된 모든
　도메인 그룹에 링크를 추가**하면서 원래 자리(카메라·지점 관리)에도
　남김 — 같은 화면이 여러 그룹에 나타나는 것은 의도된 설계(사용자가
　어느 경로로 들어오든 자기 도메인 설정을 찾을 수 있게).
○ 권한 게이트는 모든 항목이 원래 쓰던 `ok(resource, action, domain)`
　호출을 그대로 재사용 — 새로 바뀐 것은 없음, 재배치만 함.
○ 이름 정정: "AI 모델(S-84)" → "AI 모델 설정 · 물 세그멘테이션(S-84)",
　"AI 모델·침수(S-84)" → "AI 모델 설정 · 침수 파이프라인(S-84)" — 각
　화면 자체의 제목에 맞춤.

## 3. 신규 기능 — 교통위험 판정 임계값 설정 화면

○ 그동안 `traffic_weather/agents/semantic_agent.py`에 강수·속도저하·
　정지차량 임계값이 **파이썬 코드 리터럴로 고정**돼 있어 화면에서
　바꿀 수 없었음. 침수의 `risk_config.yaml`(S-82)과 대칭이 되도록
　`configs/traffic_risk_config.yaml`로 빼내고, **기존 제네릭 YAML
　편집 화면 인프라를 그대로 재사용**(`routes_config.py`의 `SCREENS`
　딕셔너리에 항목 하나 추가 — 새 라우트 코드 0줄).

○ 편집 가능 10개 값: 속도저하 임계값 2개, 대기열·정지차량 임계값 3개,
　위험 점수 가중치 3개, 점수 환산 상한 2개. 전부 기존 하드코딩 값을
　그대로 기본값으로 옮겨 **동작 변화 없음**을 보장.
○ 날씨 강도 구간 조합 로직(범주형)은 이번 범위에서 제외 — 침수 설정의
　`weights`/`grade_bins`가 읽기전용인 것과 같은 원칙.
○ 저장하면 침수와 동일하게 "재시작이 필요합니다" 안내(기존 공용
　저장 핸들러가 자동 처리).
