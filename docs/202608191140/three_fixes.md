## 1. ① 모델 선택 미소비 — 지목한 결함은 없었습니다

### 먼저 정정합니다

제가 대장에 올렸던 항목이 **낡은 분석에 기대고 있었습니다.** 오늘 코드로
다시 확인한 결과입니다.

| 대장에 적었던 것 | 실제 |
|---|---|
| 「침수·인파가 설정을 안 읽는다」 | **침수는 `runner.py:99` 가 읽습니다** |
| | **인파 마스킹은 `image_mask.py:78` 이 읽습니다** |
| | 인파 **계수**는 파일 경로로 고르는 구조가 아니고, **화면이 그렇게 안내합니다** |
| 「침수 기본이 아직 AGPL」 | `water_config.yaml` 의 `models/best.pt` 는 **쓰이지 않습니다.** S-61 선택이 이깁니다 |

★ **화면은 이미 사실을 말하고 있었습니다.** 「침수는 재기동 필요」·「인파
계수는 안 바뀜」이 `model_ops.APPLY_NOTE` 에 그대로 적혀 있습니다.

### ★★ 그런데 확인하다 더 나쁜 것이 나왔습니다

기동 로그에 이런 줄이 있었습니다.

```
[runner] water segmentation model load failed (...flood_lraspp_384_v2/best.pt):
         ERROR ... references types outside the supported Ultralytics checkpoint format
```

운영 중인 서비스의 `/api/health` 를 열어 보니 이랬습니다.

```json
{ "backend": "ultralytics",
  "license": "AGPL-3.0 (Ultralytics)",
  "model_path": ".../flood_lraspp_384_v2/best.pt",
  "models_loaded": 0,
  "blocks": 3 }
```

⚠️ **3개 지점 전부에서 침수 세그멘테이션이 안 돌고 있었습니다.**

그런데 화면에는 모델 경로가 떠 있었고, **라이선스 표기까지 틀렸습니다** —
torchvision 파일을 `AGPL-3.0` 으로 표시했습니다. 라이선스는 **납품 검토에
그대로 들어가는 값**입니다.

### 왜 이렇게 됐나

**백엔드(로더)와 모델 파일이 따로 정해지는 구조**였습니다.

| | 어디서 정해지나 | 값 |
|---|---|---|
| 백엔드 | `configs` / 환경변수 | `ultralytics` |
| 모델 파일 | **S-61 화면** | torchvision 체크포인트 |

둘이 어긋나면 적재가 **조용히 실패**하고 `None` 이 됩니다. 그리고
**맑은 날에는 어느 쪽이든 탐지 0이라 눈으로는 구분되지 않습니다.**

### 어떻게 고쳤나

**① 백엔드를 파일에서 판별합니다** (`water_backend: "auto"`)

`{"arch": ..., "model": <state_dict>}` 꼴이면 torchvision, 아니면 ultralytics.
판별이 틀릴 수 있으니 **반대쪽도 한 번 더 시도**합니다 — 두 번째까지 실패해야
「못 연다」고 말할 자격이 생깁니다.

★ **사람이 두 곳을 맞춰 두어야 하는 구조 자체를 없앴습니다.**

**② 요청값이 아니라 실제로 열린 것을 보고합니다**

| 필드 | 뜻 |
|---|---|
| `backend` | 설정에 적힌 것 |
| `effective_backend` | **실제로 열린 것** |
| `license` | **실제로 열린 쪽** 기준 (못 열면 「확인 불가」) |
| `ok` | 「돌고 있는가」를 **한 값으로** 답합니다 |
| `warning` | 「탐지 0건이 침수 없음을 뜻하지 않습니다」 |

> `ok` 를 둔 이유 — 화면이 표를 훑어 스스로 판단하게 두면, 판단이 빠진
> 화면에서 조용히 지나갑니다.

### 확인

```json
{ "backend": "auto", "effective_backend": "torchvision",
  "license": "BSD (torchvision)", "models_loaded": 3, "blocks": 3, "ok": true }
```

시험 **7건** 추가 (`tests/flood/test_water_backend_honesty.py`).

## 2. ② DB 설계서 — v8

### 무엇이 문제였나

v7 이후 여러 회차에 걸쳐 표가 늘었는데 **설계서가 따라오지 못했습니다.**
대조해 보니 **모델 33개 표 중 17개가 없었습니다.** 절반이 넘습니다.

⚠️ **납품 산출물이 실제 스키마의 절반만 담고 있었습니다.**

### 작업 중 더 나온 것

표 이름을 다 채운 뒤 **컬럼까지 대조**했더니 16개가 더 빠져 있었습니다.

- **`shift_handovers` 표 전체** — 이름은 있었는데 명세가 없었습니다
- `cameras` 의 `sido` · `sigungu` · `bearing_deg` · `tilt_deg` · `fov_deg` · `purpose`

★ **표 이름만 맞고 컬럼이 빠지면 더 나쁩니다** — 있는 줄 알고 넘어갑니다.

### 채운 것

| 묶음 | 표 |
|---|---|
| 어휘 3 | `risk_levels` · `hazard_types` · `level_thresholds` |
| 관계 5 | `zones` · `sensors` · `camera_links` · `camera_sensors` · `camera_zones` |
| 대응 절차 3 | `hazard_sop_map` · `sop_steps` · `event_sop_checks` |
| 기록 4 | `event_evidence` · `video_disclosures` · `crowd_observations` · `detection_feedback` |
| 화면 2 | `multiview_layouts` · `user_prefs` |
| 보완 1 | `shift_handovers` |

**컬럼 목록만 적지 않았습니다.** 왜 그렇게 만들었는지를 함께 적었습니다 —
`auto` 를 왜 두었는지, 「모르겠다」를 왜 선택지로 두었는지, `ltree` 를 왜
안 썼는지.

**미해결도 그대로 적었습니다** — `hazard_sop_map` 은 표만 있고 읽는 코드가
없습니다(3-24절). 설계서가 「있다」고만 적으면 다음 사람이 동작한다고 믿습니다.

### ★ 다시 뒤처지지 않게 시험으로 막았습니다

`tests/core/test_db_spec_current.py` — **기계가 대조합니다.**

| 시험 | 보는 것 |
|---|---|
| 표 | 모델의 모든 표가 설계서에 있는가 |
| **컬럼** | 모든 컬럼 이름이 설계서에 있는가 |
| 마이그레이션 | revision 이 적혀 있는가 |
| 표 개수 | 본문에 숫자가 적혀 있는가 |

> **왜 시험인가** — 표를 추가할 때 문서를 같이 고치는 것은 잊기 쉽고,
> **잊어도 아무 일도 안 일어납니다.** 그래서 절반이 빠질 때까지 아무도
> 몰랐습니다. 「나중에 문서 정리」가 실제로는 오지 않는다는 것을 겪었습니다.

⚠️ **이 시험이 보지 못하는 것** — 이름이 적혀 있는지만 봅니다. 설명이 맞는지는
사람이 봐야 합니다.

## 3. ③ `hazard_type_code` 채우기

### 무엇이 문제였나

이 칸을 **채우는 곳이 없었습니다.** 유형 어휘 11행을 만들어 두고 이벤트가
그것을 가리키지 않았습니다. 확인해 보니 **31건 전부** 비어 있었습니다.

⚠️ 비어 있어도 **아무 일도 안 일어납니다.** 화면은 도메인으로 잘 돌아갑니다.
유형 기준으로 묶으려 할 때가 되어서야 드러나고, **그때는 늦습니다.**

### 어떻게 고쳤나

**새 이벤트** — `record_detection` 이 도메인에서 도출해 채웁니다.

> `event_type` 은 「침수·교통위험」 같은 **화면 문구**라 코드로 쓸 수
> 없었습니다. 그래서 `domain` 에서 도출합니다.

**과거 31건** — 마이그레이션 `b3e5f1a72c04` 로 채웠습니다. 비어 있는 것만
채우고, **이미 값이 있으면 건드리지 않습니다.**

### ★ 채운 것은 「대분류」까지입니다

도메인에서 알 수 있는 것이 거기까지입니다. **「지하차도 침수」인지 「배수로
침수」인지는 지나간 이벤트로는 알 수 없습니다.**

> ⚠️ **아는 척해서 세분류를 찍으면 안 됩니다.** 그 값으로 SOP 가 갈리는데,
> **틀린 절차를 안내하는 것은 절차가 없는 것보다 나쁩니다.**

이 한계를 시험으로도 못박았습니다 — 나중에 누군가 「세분류도 도메인에서
채우자」고 하면 안 되기 때문입니다.

### 그 밖에 지킨 것

- **어휘에 없는 코드는 버립니다** — 모르는 코드를 저장하면 유형별로 묶을 때
  **어디에도 안 속하는 이벤트**가 되어 조용히 통계에서 빠집니다
- **갱신 시에는 덮지 않습니다** — 이미 붙은 세분류를 다음 탐지가 대분류로
  덮으면 정보가 줄어듭니다
- **DB 를 매번 조회하지 않습니다** — 탐지 한 번마다 질의를 더하면 상시
  탐지에서 비용이 쌓입니다

시험 **10건** 추가.

### downgrade 를 비워 둔 이유

되돌리려면 「이 마이그레이션이 채운 것」과 「그 뒤에 새로 들어온 것」을
구분해야 하는데 **구분할 근거가 없습니다.** 전부 비우면 새 이벤트의 값까지
지웁니다. 채운 값은 도메인에서 언제든 다시 도출할 수 있으므로 **되돌리지
않는 편이 안전합니다.**
