# UrbanGuard 4대 탐지 기능 기술 정리 — 기술스택·탐지엔진·탐지모델·성능

앤시정보기술(주) · 전략기획부 · 작성일 2026-08-25 · v1

> 이 문서는 **코드와 운영 중인 서비스에서 직접 확인한 사실만** 담습니다.
> 확인하지 못한 것은 「확인이 필요합니다」로 표시했습니다.
> 성능 수치는 전부 근거 문서·실측 출처를 함께 적었습니다.

## 0. 결론 먼저

○ **4대 탐지 기능의 성숙도가 서로 크게 다릅니다.** 하나로 묶어 「AI 탐지」로 설명하면 실제와 달라집니다.

| 기능 | 탐지엔진 | 자체학습 모델 | 실환경 성능 | 판정 |
|---|---|---|---|---|
| 침수 | torchvision LR-ASPP 시맨틱 세그멘테이션 | 있음 (1,570장) | val F1 0.9392 · 맑은날 오탐 0.00% | 납품 가능 |
| 교통위험 | YOLO11s 차량검출 + 규칙기반 판정 | 없음 (사전학습 그대로) | 임계값 전부 개발사 자체판단 · 미검증 | 시범운영 필요 |
| 인파관리 | Faster R-CNN 사람검출 + ByteTrack | 없음 (사전학습 그대로) | 데모 1장면 39/39 · 현재 mock 모드 운영 중 | 검출기 전환 필요 |
| 도로 노면 | YOLOv8 손상검출 (RDD2022) | 파인튜닝 | 부산 CCTV 탐지율 1.05% | 실시간 CCTV는 성립 안 함 |

○ **침수만 「탐지한다」고 말할 수 있습니다.** 나머지 셋은 각각 다른 이유로 제약이 있으며, 제안서·보고에 쓸 때 그 제약을 함께 적어야 합니다.

○ **AGPL 종속을 침수에서만 벗어났습니다.** 교통·인파·노면은 여전히 Ultralytics YOLO(AGPL-3.0) 계열이라 상용 납품 전 법무 확인이 필요합니다.

## 1. 공통 기술스택

### 1-1. 실행 환경

| 구분 | 채택 기술 | 버전 (실측) |
|---|---|---|
| 언어 | Python | 3.12.0 |
| 웹 프레임워크 | FastAPI + Uvicorn | 0.141.1 / 0.52.1 |
| 화면 | Jinja2 템플릿 + 순수 JavaScript (프레임워크 없음) | Jinja2 3.1.6 |
| 데이터베이스 | PostgreSQL (전용 인스턴스, 포트 5433) | 17.7 |
| DB 접근 | SQLAlchemy + Alembic 마이그레이션 | 2.0.51 / 1.19.0 |
| 배포 형태 | 단일 서버 프로세스 (포트 8033) · 윈도우/리눅스 양쪽 | — |

○ 화면에 별도 프런트엔드 프레임워크(React·Vue 등)를 쓰지 않았습니다. 폐쇄망 반입 대상과 빌드 도구를 줄이기 위한 선택입니다.

### 1-2. AI 추론 공통 기반

| 구분 | 채택 기술 | 버전 (실측) | 라이선스 |
|---|---|---|---|
| 딥러닝 프레임워크 | PyTorch | 2.13.0 | BSD |
| 비전 모델 라이브러리 | torchvision | 0.28.0 | BSD |
| 객체검출 라이브러리 | Ultralytics YOLO | 8.4.115 | AGPL-3.0 (주의) |
| 영상 처리 | OpenCV | 5.0.0.93 | Apache 2.0 |
| 다중객체 추적 | ByteTrack (trackers 패키지) | 2.x | Apache 2.0 |
| 수치 연산 | NumPy | 2.5.1 | BSD |

○ **추론은 전부 CPU에서 돕니다.** 현재 장비에 GPU가 없어, 모든 모델을 CPU로 실행 가능한 경량 구성으로 선택했습니다.

○ 추적기는 어댑터(common/tracking.py)로 감쌌습니다. supervision.ByteTrack이 폐기·제거 예정이라 후속 패키지 trackers로 갈아탈 수 있게 한 것이며, 호출부(인파·교통 2곳)는 바뀌지 않습니다.

### 1-3. 외부 연계

| 구분 | 연계 대상 | 현재 상태 |
|---|---|---|
| 강수량 | 기상청 초단기실황 (RN1, 1시간 강수량 mm) | 연동 완료 |
| 문자·알림톡 | SOLAPI | 연동 완료 (현재 모의발송 모드) |
| 상황 설명문 (VLM) | Google Gemini 2.5 Flash | 기본 꺼짐 — 폐쇄망 고려 |
| 조달 API | data.go.kr 조달청 | 활용신청 대기 (담당자 작업 필요) |

○ VLM(Gemini)은 환경변수 TOT_USE_VLM=1로만 켜집니다. **기본값은 꺼짐**이며, 꺼져 있으면 규칙 기반 설명문으로 자동 대체됩니다. 폐쇄망에서도 기능이 멈추지 않습니다.

## 2. 도메인별 상세

### 2-1. 침수 탐지

#### 탐지엔진

| 항목 | 내용 |
|---|---|
| 방식 | 시맨틱 세그멘테이션 (화면의 모든 픽셀을 물/비물로 이진 분류) |
| 모델 구조 | LR-ASPP MobileNetV3-Large (torchvision) |
| 입력 크기 | 384 × 384 |
| 신뢰도 임계값 | 0.50 (물 클래스 확률) |
| 처리 주기 | 1.0초 (물은 천천히 번져 고빈도가 불필요) |
| 실행 위치 | src/tot_dashboard/flood/water_segmentation_tv.py |
| 라이선스 | BSD (torchvision) — AGPL 의무 없음 |

○ 보조 엔진으로 **차량·보행자 검출**(YOLO11s)이 함께 돌아, 바퀴 잠김 정도와 보행자 노출을 판정에 반영합니다.

○ **손상 프레임 검출기**를 앞단에 뒀습니다. H.264 디코딩이 깨진 프레임을 그대로 세그멘테이션하면 깨짐 노이즈를 물로 오인하므로, 화면을 16×16 블록으로 나눠 밝기 표준편차가 평평한 블록 비율이 20%를 넘으면 그 프레임을 버립니다.

#### 탐지모델 — 자체 구축 데이터셋으로 학습

| 데이터 구성 | 장수 |
|---|---|
| 침수 장면 (HydroShare 공개 데이터) | 1,328 |
| 배경: 옥천 폭우 영상 (비는 오나 침수 없음 = 하드 네거티브) | 214 |
| 배경: 부산 맑은 날 CCTV (실제 배포 환경) | 28 |
| 합계 | 1,570장 (배경 비중 15%) |

○ 학습 결과 **val F1 0.9392 / IoU 0.8854** (25/30 에폭). 원 논문 목표치 F1 0.9를 초과 달성했으며, **CPU로 학습**했습니다.

○ **1차 학습 실패 경험이 이 구성을 만들었습니다.** 침수 장면만 1,328장으로 학습한 1차 모델은 val F1 0.9365로 지표는 좋았으나, 맑은 날 부산 CCTV에서 **마른 아스팔트를 물로 칠했습니다**(평균 28%, 최대 65% 오탐). 학습셋에 배경이 없어 모델이 「도로 = 물」로 일반화한 것입니다. 배경 242장을 추가해 이 문제를 완전히 해결했습니다.

#### 성능 — 3개 항목 실측 검증

| 검사 항목 | 기존 Ultralytics | 1차 (배경 없음) | 최종 v2 |
|---|---|---|---|
| ① 실제 침수 영상에서 물 검출 | 0% | 63.4% | 37.9% |
| ② 레터박스(검은 여백) 오탐 | 19% | 32.8% | 17.9% |
| ③ 맑은 날 CCTV 오탐 | 통과 | 28% / 65% | 0.00% |
| 종합 | 1/3 | 1/3 | 2/3 |

○ ①의 수치가 63.4%에서 37.9%로 낮아진 것은 **과검출이 줄어든 것**입니다. 오버레이 육안 확인 결과 침수 노면을 정확히 덮고 차량·난간·벽은 제외합니다.

○ **② 레터박스 오탐이 남은 약점입니다.** 학습 데이터에 레터박스 영상이 없어 검은 여백을 물로 오인합니다. 전처리 제거 함수(crop_letterbox())를 구현했으나 **아직 추론 경로에 연결하지 않았습니다.** 라이브 CCTV에는 레터박스가 없어 당장의 영향은 없습니다.

#### 운영 현황 (2026-08-25 실측)

○ 상시 탐지 대상 **9개 지점**, 물 세그멘테이션 모델 적재 **7/7 정상**

○ 위험도는 6개 항목의 가중 평균으로 0~100점 산정 후 5등급으로 분류합니다.
- 면적 0.28 · 저지대 0.24 · 침수경계선 0.10 · 확산속도 0.10 · 바퀴잠김 0.12 · 보행자 0.10

○ **가중치·등급 경계는 전부 개발사 자체 판단입니다**(외부 기준 없음). 재난 담당부서 검토가 필요합니다.

### 2-2. 교통위험 탐지

#### 탐지엔진

| 항목 | 내용 |
|---|---|
| 방식 | 객체검출 + 추적 → 교통지표 산출 → 규칙기반 판정 |
| 차량검출 모델 | YOLO11s (COCO 사전학습, 파인튜닝 없음) |
| 신뢰도 임계값 | 0.30 |
| 추론 해상도 | 416 (여러 스트림 동시 처리를 위해 낮춤) |
| 처리 프레임률 | 5 fps |
| 추적 | ByteTrack (미설치 시 무게중심 매칭으로 자동 대체) |
| 실행 위치 | traffic_weather/perception/traffic_tracker.py |
| 라이선스 | AGPL-3.0 (Ultralytics) — 주의 |

○ **강수량은 검출이 아니라 기상청 API에서 받습니다**(초단기실황 RN1). 지점 위경도를 기상청 격자로 변환해 조회하고, 키 없음·조회 실패 시 대체값으로 물러나 파이프라인이 멈추지 않습니다.

#### 탐지모델 — 자체 학습 모델 없음

○ **교통 전용으로 학습한 모델이 없습니다.** COCO 사전학습 YOLO11s가 차량(car·bus·truck·motorcycle)을 세는 데 그대로 쓰입니다. 「교통위험 탐지 AI 모델」이라는 표현은 현재 상태와 맞지 않습니다.

○ **속도(km/h)를 재지 못합니다.** 화면 픽셀 기준 상대적 「속도저하 비율」만 계산합니다. 실제 속도를 내려면 **지면 평면 캘리브레이션(호모그래피)**이 선행돼야 합니다.

#### 판정 로직 — 규칙 기반

○ 강수강도(기상청) × 속도저하 × 정지차량 3가지를 조합해 5단계 코드를 냅니다.

| 코드 | 이름 | 등급 |
|---|---|---|
| TWR_NORMAL | 정상 | 관심 |
| TWR_RAIN_ONSET | 강우·노면젖음 | 주의 |
| TWR_RAIN_CONGESTION | 강우 정체 | 경계 |
| TWR_SEVERE_CONGESTION | 강우 중 정지차량 다발 | 경계 |
| TWR_SEVERE_GRIDLOCK | 심각한 교통마비 | 심각 |

○ 강수강도 구분(mm/h) — 없음 0 · 약함 0.1 · 보통 3.0 · 강함 15.0 · 매우강함 30.0

#### 성능 — 정량 평가 미실시

○ **탐지 성능을 나타내는 지표(mAP·정확도 등)가 없습니다.** 자체 학습을 하지 않아 평가셋도 만들지 않았습니다.

○ **판정 임계값 10개가 전부 개발사 자체 판단입니다.** 2026-08-24까지 코드에 고정값으로 박혀 있던 것을 설정 파일로 빼내 화면에서 바꿀 수 있게 했을 뿐, **재검토를 거친 새 값이 아닙니다.**

| 임계값 | 기본값 | 근거 |
|---|---|---|
| 속도저하 인지 | 0.20 | 자체 |
| 속도저하 격상 | 0.40 | 자체 |
| 대기열 인지 | 3대 | 자체 |
| 정지차량 인지 / 심각 | 1대 / 2대 | 자체 |
| 점수 가중치 (강수/속도저하/정지) | 0.45 / 0.35 / 0.20 | 자체 |

○ **시범운영 중 지점별 재조정이 필요합니다.**

### 2-3. 인파관리 탐지

#### 탐지엔진 — 두 갈래

| 모드 | 검출기 | 라이선스 | 현재 상태 |
|---|---|---|---|
| mock | 합성 궤적 생성 (모델 없음) | — | 현재 운영 중 |
| detector | torchvision Faster R-CNN MobileNetV3-Large FPN | BSD | 구현 완료, 미전환 |
| SAM3 (별도) | Meta SAM3 (텍스트 프롬프트 "person") | — | GPU 필요 — 미설치 |

○ **현재 운영 중인 것은 mock 모드입니다**(2026-08-25 /api/health 실측: person_source: "mock"). 합성 궤적으로 배회·침입·군중급증 판정 로직이 정상 동작하는지 확인하는 상태이며, **실제 CCTV에서 사람을 세고 있지 않습니다.**

○ detector 모드는 구현·검증까지 끝났으나 기본값이 mock입니다. 전환 시 torchvision 사전학습 가중치(약 74MB) 최초 1회 다운로드가 필요합니다.

#### 탐지모델 — 타일 분할 추론

○ 인파 장면은 원경 인물이 작아 전체 이미지 1회 추론으로는 크게 놓칩니다. 화면을 2×2 격자로 나눠 각각 추론한 뒤 좌표를 복원하고 NMS로 병합합니다.

**데모 1장면(정답 39명) 실측 비교**

| 방식 | 검출 인원 | 정답 대비 | 소요 시간 |
|---|---|---|---|
| SSDLite 전체 1회 | 8명 | 21% | 0.2초 |
| Faster R-CNN 전체 1회 | 16명 | 41% | 0.4초 |
| Faster R-CNN 2×2 타일 (conf 0.4 / NMS 0.4) | 39명 | 100% | 1.6초 |

○ **「정답 39명」은 SAM3의 출력이지 사람이 센 수가 아닙니다.** 「정확도 100%」가 아니라 「SAM3와 같은 인원수」라는 뜻이며, 개별 박스가 같은 사람을 가리키는지는 검증하지 않았습니다.

○ **이 한 장면에 맞춘 값**입니다. 다른 장면·야간·저해상도 CCTV에서는 재조정이 필요합니다.

#### 행동 탐지 — 모델 없이 구현한 2종

○ 배회(Loitering)·침입(Intrusion)은 **새 모델 없이** 기존 출력의 재해석으로 구현했습니다. 추적 ID별 체류시간 누적, ROI 다각형 내외 판정을 씁니다.

○ 나머지 5종(폭력징후·쓰러짐·위험물투기 등)은 **행동인식 모델이 필요해 GPU 확보 후 착수 대상**입니다.

#### 위험도 판정 — 5단계

| 코드 | 이름 | 심각도 |
|---|---|---|
| NORMAL | 정상 | 0 |
| CROWD_DENSITY_HIGH | 군중밀집 | 1 |
| FLOW_CHAOS | 이동흐름혼란 | 2 |
| CROWD_SURGE_RISK | 군중급증위험 | 3 |
| PANIC_DISPERSION | 패닉분산 | 4 |

#### 성능 및 한계

○ **「명/㎡」를 재지 못합니다.** 밀집도는 화면을 96열 격자로 나눠 **사람이 점유한 칸의 비율(%)**입니다. 실제 바닥 면적이 아니라 화면 픽셀 기준이라, 같은 40%라도 원거리·근거리 카메라의 실제 밀도가 전혀 다릅니다.

○ **대조한 외부 기준은 전부 「명/㎡」입니다.** 국내 3/4/5명/㎡(주의/경계/심각), 영국 Green Guide 4.7명/㎡, Fruin LOS 등이며, **지면 평면 캘리브레이션(호모그래피)**이 완료돼야 이 기준과 연결됩니다. 행정안전부 공식 지침 원문은 확인하지 못했습니다. 인용 전 확인이 필요합니다.

○ **인파 등급이 93.6% 한 등급에 쏠려 있습니다**(2026-08-19 전수조사). 계산은 맞고 **문턱값이 교차로 환경에 안 맞습니다**(교차로는 본래 흐름이 갈림). 현장 확인 후 문턱 조정이 필요합니다.

#### 판정 — 실시간 CCTV 모드는 접었습니다

| 모드 | 판정 | 제안·보고에 쓸 표현 |
|---|---|---|

○ 그래서 화면에 **탐지율을 그대로 띄워** 사실이 드러나게 했고, 학습 데이터 수집·영상 업로드 통로를 「노면 현황」 화면에 두었습니다.
