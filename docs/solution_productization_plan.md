### ⚠️ v6 의 가장 중요한 결론 — 노면 실시간 CCTV 모드

SVRDD(CC BY 4.0, 45° 부감) 데이터로 네 번째 학습까지 마쳤습니다.
**더 학습할수록 부산 CCTV 에서는 나빠졌습니다.**

- 자기 도메인 mAP50 0.168 → **0.269** (상승)
- 부산 CCTV 오탐 12건 → **43건** (증가), 최고 신뢰도 0.45 → **0.59**
- 탐지 내용은 **전부 차선 도색** — 240p 에서는 차선과 균열이 구분되지 않음

**제안 문구를 조정해야 합니다.** 「CCTV로 포트홀을 자동 탐지」는 현장에서
성립하지 않습니다. **「점검이 필요한 지점을 좁히는 참고 자료」**로 한정하는 것이
정직하고 심사에서도 방어됩니다. 실용화하려면 **노면 전용 촬영**(차량 탑재·저각
설치) 도입이 필요하며, 이는 장비 예산 사안입니다.

## 5. 결정이 필요한 사항 (v3 갱신)

> 아래 1~4번은 **2단계(제품 기반 구축) 착수를 막고 있는 결정**입니다. 이것부터 정해야 개발이 진행됩니다.

1. **DB 선택** — PostgreSQL / TimescaleDB(시계열 특화, 코드 주석의 원래 구상) / SQLite(소규모 지자체용). 지자체 인프라 제약 확인 필요
2. **인증 방식** — 자체 로그인 / 지자체 기존 SSO 연계 / 망분리 환경 전제 여부
3. **배포 환경** — 지자체 자체 서버 / 클라우드 / 온프레미스 어플라이언스 (GPU 필요 여부와 직결)
4. **솔루션 공식 명칭·브랜딩** — 제안서·UI에 사용할 정식 명칭 (P0-5 기관명 분리와 함께 처리)

5. **노면 관리 모듈 포함 여부** — 3-3절 판단 참고. 포함한다면 ① 국내 학습 데이터(AI Hub 등) 확보와 ② 근접 촬영장비 예산이 모두 필요
6. **인파관리 GPU 서버** — 현재 CPU 검출기로 배회·침입 2종은 동작합니다. 폭력·쓰러짐·투기 3종(행동인식 모델)을 넣으려면 GPU 필요. 미확보 시 **2종으로 범위 한정 후 로드맵 명시**를 권합니다
7. **KMA_SERVICE_KEY 발급 시점** — 실측 강수 연동뿐 아니라 **침수 학습데이터 자동수집(우기 대비)**의 전제. 우기 전에 확보하지 못하면 P0-6 검증이 1년 지연될 수 있음
8. **라이선스 잔여 확인** — 도로 도메인은 아직 AGPL 모델을 씁니다(P0-8). 그 전까지 납품·시연이 있다면 법무 확인 필요. CC BY 4.0 데이터셋 **출처 표시 의무** 이행 방법도 정해야 합니다
