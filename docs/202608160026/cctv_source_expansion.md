## 0. 결론 먼저

**부산 밖으로 넓히는 것은 기관을 새로 뚫는 문제가 아니라 좌표 사각형을 바꾸는
문제입니다.** 이미 붙여 둔 국가교통정보센터(ITS) OpenAPI가 전국을 담당하기
때문에, 지역 프리셋만 늘리면 17개 시도 어디든 같은 방식으로 받습니다. 이번에
**3개 → 17개로 확장**했습니다.

**해상도는 사정이 다릅니다. 공개 문서 어디에도 나와 있지 않습니다.** ITS 응답에
`cctvresolution` 항목이 있지만 값의 표기 형식조차 공개 명세에서 확인하지
못했습니다. 그래서 **표기를 믿지 않고 실제로 한 프레임을 받아 재는 도구**를
만들었습니다.

## 1. 지금 붙어 있는 것

| 항목 | 내용 |
|---|---|
| 연계처 | 국가교통정보센터(ITS) OpenAPI 1곳 |
| 대상 | **교통 소통정보용** CCTV (실시간 스트리밍 `cctvType=1`) |
| 지역 | 부산·울산·경남 3개 → **17개 시도로 확장** |
| 상태 | ⚠️ **API 키 미발급** — 기능은 완성, 실제 수집은 잠겨 있음 |

> ⚠️ **방범 CCTV는 이 경로로 받을 수 없습니다.** 지자체 CCTV통합관제센터
> 전용망으로만 흐르고 외부 제공 창구가 없습니다. 연계하려면 발주 기관과의
> 별도 협의가 필요합니다.

## 2. 확보처 후보

### 2-1. 바로 쓸 수 있는 것

| # | 기관·서비스 | 범위 | 심의 | 확인한 근거 |
|---|---|---|---|---|
| 1 | **국토교통부 CCTV 화상자료** (ITS) | 전국 고속도로·주요 간선도로 | **개발·운영 모두 자동승인 · 무료** | [공공데이터포털 15040466](https://www.data.go.kr/data/15040466/openapi.do) |
| 2 | **경찰청 교통 CCTV 영상정보** (UTIC) | 도시부 교통관제 | 개발 자동승인 / **운영 심의승인** · 무료 | [공공데이터포털 15148511](https://www.data.go.kr/data/15148511/openapi.do) |

**1번이 가장 빠른 길입니다.** 심의가 없어 신청 즉시 키가 나오므로, 사내 결정
사항 4번(「교통정보센터 API 키 발급」)은 사실상 **결정할 것이 없고 신청만 하면
되는 사안**입니다.

### 2-2. 도메인별로 검토할 것

| 도메인 | 후보 | 성격 | 상태 |
|---|---|---|---|
| **침수** | 홍수정보시스템 **수위관측 CCTV** | 하천 수위 지점 영상 | 웹 서비스 확인 · **API 제공 여부 미확인** |
| **침수** | 한국수자원공사 수계별 실시간 CCTV | 댐·보 방류, 하천 수위 | **파일데이터**로 등록 — 실시간 연계 방식 확인 필요 |
| **인파** | 지자체 관광지 공개 CCTV (제주 등) | 해수욕장·명소 | 웹 페이지 제공 · **공개 API 아님** |
| **노면** | 한국도로공사 고속도로 공공데이터 | 고속도로 | 포털 접속 실패(timeout) — **재확인 필요** |

> **미확인 항목을 확인된 것처럼 쓰지 않았습니다.** 위 4건은 서비스 존재는
> 확인했지만 **기계 연계(API) 가능 여부를 확인하지 못했습니다.** 제안서에
> 넣으려면 각 기관에 직접 문의해 확인해야 합니다.

### 2-3. 쓸 수 없는 것

| 대상 | 이유 |
|---|---|
| 지자체 방범 CCTV | 전용망 · 외부 제공 창구 없음 (개인정보 보호법 제25조 관련) |
| 민간 CCTV 모음 사이트 | 재배포 권한 불명 — **상용 제품에 넣으면 안 됩니다** |
| 전국CCTV표준데이터 | **설치 위치 목록**일 뿐 영상 스트림이 아님 |

## 3. 해상도 — 왜 실측인가

### 3-1. 문서로는 알 수 없습니다

세 곳(ITS 개발자포털·공공데이터포털 두 건)을 확인했지만 **해상도 규격이 어디에도
없습니다.** 개발자포털(`openapi.its.go.kr`)은 조사 환경에서 접속이
거부되었고(ECONNREFUSED), 포털 상세 페이지에는 응답 항목 명세가 실려 있지
않습니다.

### 3-2. 그래서 재는 도구를 만들었습니다

`scripts/probe_cctv_resolution.py` — 스트림을 실제로 열어 **받은 프레임 배열의
모양**을 재고 등급(UHD/FHD/HD/SD)으로 정리합니다.

```bash
python scripts/probe_cctv_resolution.py --region seoul --limit 30 --csv seoul.csv
```

설계상 두 가지를 지켰습니다.

- **컨테이너가 신고한 값(`CAP_PROP_*`)이 아니라 디코딩 결과를 씁니다.**
  신고값은 실제와 어긋나는 일이 있습니다.
- **접속 실패도 결과 한 줄로 남깁니다.** 「목록에는 있는데 안 열리는 지점」이
  실제로 많고, 모른 채 등록하면 상시 탐지가 조용히 비어 버립니다.

### 3-3. 화면에서 거르기

S-80 자동 수집에 **최소 해상도** 선택을 넣었습니다(제한 없음 / HD 이상 /
FHD 이상). 기본값은 HD 이상입니다.

단, **표기가 비어 있는 지점은 걸러도 남깁니다.** 표기 없음을 0으로 취급하면
실제로는 FHD인 지점까지 조용히 사라지기 때문입니다. 모르는 것은 모르는 채로
두고, 실측으로 판정합니다.

## 4. 이번에 고친 것

| 대상 | 내용 |
|---|---|
| `core/cctv_sources.py` | 지역 프리셋 3 → **17개 시도** |
| `core/cctv_sources.py` | `parse_resolution()` · `min_height` 거르기 · 해상도순 정렬 |
| `service/routes_cameras.py` | 수집 시 최소 해상도 지정 · 0건일 때 원인 안내 |
| `templates/cameras.html` | 최소 해상도 선택 상자 |
| `scripts/probe_cctv_resolution.py` | **신규** — 실제 해상도 측정 |
| `tests/test_cctv_sources.py` | **신규** — 22건 |

> ⚠️ 지역 경계는 **행정경계가 아니라 여유를 둔 사각형**입니다. 이웃 시도가
> 섞여 들어오고 해안은 바다도 포함합니다. 후보를 좁히는 용도이지 경계 판정용이
> 아닙니다.
