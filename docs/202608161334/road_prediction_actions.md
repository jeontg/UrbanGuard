| | 서울시 실무 기준 | 우리 현재 |
|---|---|---|
| 균열 | **균열률 CR (%)** — 면적 비율 | 건/100m — **개수 밀도** |

**그리고 희망적인 사실도 있습니다.** 매뉴얼이 이렇게 적고 있습니다 —

로드스캐너도 결국 **노면 이미지**로 균열률을 냅니다. 원리가 우리와 같습니다.

## 1. ① 노면 12지점 구간 길이 입력 준비 ✅

**작업지시서(엑셀)를 만들었습니다** — `노면_구간길이_실측_작업지시서.xlsx`

- 대상 **12개소** 전량 (ID·지점명·지역·좌표·지도 링크·분석 방식)
- 채워 넣을 칸을 노란색으로 표시
- 「작성 안내」 시트에 측정 정의·방법·입력 위치·판정 기준

**측정 정의를 분명히 했습니다** — 도로대장의 구간 길이가 아니라
**「카메라가 실제로 관측하는 범위」** 입니다. 대장 구간이 화면보다 길면
그대로 쓰면 안 됩니다.

### ⚠️ 확인이 필요한 것

**`SEOUL-126 (남산)하얏트`가 3개 도메인 전부 「사용 + 상시」** 로 되어
있습니다. 등록할 때는 인파만 켜고 상시는 껐는데, 이후에 바뀐 상태입니다.

- 인파용 FHD 관광지 지점이라 **노면 대상이 맞는지 의문**입니다
- 노면 대상이 아니면 구간 길이 입력도 불필요 → **11개소**가 됩니다
- 침수·노면 상시가 켜져 있어 **CPU를 쓰고 있습니다**

작업지시서 비고란에 표시해 두었습니다.

## 2. ② 기상청 API 연계 ✅ 코드 완성

`core/weather_sources.py` — **초단기실황 조회.** 시험 18건 통과.

| 항목 | 내용 |
|---|---|
| 서비스 | 기상청_단기예보 조회서비스 (`getUltraSrtNcst`) |
| 신청 | 공공데이터포털 · **개발·운영 모두 자동승인 · 무료** |
| 한도 | 개발계정 10,000회/일 |
| 키 설정 | `.env` 의 `KMA_API_KEY` |

### 확인한 것

- **격자 변환이 정확합니다** — 서울시청이 기상청 공개 예시와 같은 `(60, 127)`
- **발표 시각 보정** — 정시 관측이 약 40분 뒤 올라오므로, 그 전이면 한 시간 전 것을 봅니다
- **`resultCode` 를 따로 봅니다** — 기상청은 오류도 HTTP 200 으로 줍니다
- **키가 없으면 안내만 하고 서비스는 계속 돕니다**

### ⚠️ 이 API로 채울 수 없는 것

논문 입력 5종 중 **적설·초상온도가 없습니다.** 초단기실황 오퍼레이션 자체에
없어서, 채우려면 **종관/방재기상관측(ASOS/AWS)** 을 따로 붙여야 합니다.

`missing_for_prediction()` 이 **못 채운 항목을 이름으로 돌려줍니다** —
「다 받았다」고 착각하지 않게 하려는 것입니다.

## 3. ④ 서울시 매뉴얼 원문 분석 ✅ **가장 큰 수확**

`서울특별시 도로포장 유지관리 매뉴얼` (2018. 4. 30, 67쪽) 본문 확보.

### 3-1. 조사 체계 — 2018년에 매년 전수조사로 바꿨습니다

| 항목 | 내용 |
|---|---|
| **포장표면 조사** | **매년 전수조사** (2018년 개선. 그 전은 3년 주기) |
| 조사 연장 | **6,606 km/년** (개선 전 2,202 km/년) |
| 포장하부 조사 | 3년 주기 (함몰 위험도에 따라 변경) |
| 일상 점검 | 수시 |
| 분석 일정 | 당해 5월~익년 4월 조사 → **익년 6월까지 분석** → 보수대상·공법 선정 |

> **직전 조사서에서 「2~3년 주기가 일반적」이라고 썼는데, 서울시는 이미
> 매년 전수조사로 바꿨습니다.** 그 문장은 일반론이었고, 서울 기준으로는
> 갱신이 필요합니다.

### 3-2. 조사 장비

| 장비 | 측정 항목 |
|---|---|
| **로드스캐너** | 균열·소성변형·평탄성 |
| 다채널 GPR | 포장하부 동공·지반 이완 |
| FWD | 포장지지력 |
| 소음측정 / 투수시험 / BPT | 기능성 조사 |

### 3-3. ★ 서울형 Decision Tree — 보수공법 결정 기준

**균열률(CR)과 소성변형(RD)의 구간 조합**으로 공법이 정해집니다.

| CR 구간 | RD 구간 | 공법(예) |
|---|---|---|
| ≤ 8% | ≤ 8mm | 박층 덧씌우기 |
| 8~15% | 8~15mm | 50mm 절삭 및 채우기 / 50mm 절삭·재포장 |
| 15~20% | 15~20mm | 70~100mm 절삭·재포장 |
| > 20% | > 15mm | 120~150mm 절삭·재포장 |

- **IRI 기준**: 자동차전용도로 **6 m/km**, 그 외 **8 m/km**
- **예방포장**: IRI 양호 + CR ≤ 8%. 거북등 균열률 **5% 초과 → 패칭**
- 선형균열 3% 기준으로 분기

### 3-4. 그래서 우리는 무엇을 해야 하나

**「건/100m」를 「균열률 %」로 바꾸는 것이 실무 기준과 연결되는 길입니다.**

| 지금 | 필요한 것 |
|---|---|
| 균열을 **박스로 세어** 개수를 냄 | 균열을 **영역으로 잡아** 면적 비율을 냄 |
| 탐지(detection) 모델 | **분할(segmentation)** 모델 |

침수 도메인이 이미 물 영역을 분할해 면적비를 내고 있습니다. **같은 방식을
노면에 적용할 수 있습니다.**

> ⚠️ 다만 **소성변형(RD)과 평탄성(IRI)은 CCTV로 못 잽니다.** 서울형 DT를
> 완전히 채우려면 로드스캐너가 필요합니다. 우리가 채울 수 있는 것은
> **CR 축뿐**이며, 이것을 제안서에 분명히 밝혀야 합니다.

## 4. ⑤ 논문 원문 ✅ 본문 확보

**김도완·전진호·김담륭 (2019), 한국방재학회**

| 항목 | 내용 |
|---|---|
| 회귀식 | `Y = ε₀ + β₁x₁ + … + β₈x₈` (Table 7에 절편·계수·p값) |
| 데이터 | **서울시 2009~2017년** 포트홀 발생 데이터 |
| 변수 선정 | 역학적 접근 → 교통량·평균주행속도·SPI 3종 / 확률적 접근(탐색적 요인분석) → 기상 5종 |
| 정확도 | 포트홀 R² 69.73% · 지반침하·함몰 R² 72.49% |
| 오차 | RMSE·MSE·MAE·MAPE (0.132~0.135) |

### ⚠️ 확인 못 한 것

- **교차검증 여부가 명시돼 있지 않습니다**
- **표본 수가 기재돼 있지 않습니다**

> R² 70% 대는 **학습 데이터에 대한 설명력**일 수 있습니다. 교차검증이
> 없다면 실제 예측 성능은 이보다 낮을 수 있으므로, **제안서에 이 수치를
> 「예측 정확도」로 인용하는 것은 위험합니다.**

**입력 변수에 SPI가 들어간다는 점도 중요합니다.** 예측하려면 SPI를 먼저
알아야 하는데, SPI는 로드스캐너 조사 결과입니다.

## 6. ③ 부산·경남 PMS ❌ **확인 실패**

**두 차례 조사했으나 부산시·경상남도의 PMS 구축 현황을 확인하지
못했습니다.** 확인된 것은 「부산시 도로건설·관리계획(2021~2025)」과
「부산광역시 도로정비 기본계획」 문서의 존재뿐입니다.

**직접 문의가 필요합니다.**

### 문의 문안 (그대로 쓰실 수 있습니다)

```
제목: 도로포장관리시스템(PMS) 운영 현황 문의

안녕하십니까. 앤시정보기술(주) 전략기획부입니다.

부울경 지역 지자체를 대상으로 CCTV 영상 기반 도로 노면 상태 모니터링
솔루션을 개발하고 있으며, 기존 포장관리 체계와의 연계 가능성을 검토하기
위해 아래 사항을 문의드립니다.

1. 도로포장관리시스템(PMS) 운영 여부와, 운영 중이라면 시스템 명칭
2. 포장상태 조사 주기와 조사 방식 (로드스캐너 등 장비 조사 / 육안조사)
3. 사용 중인 포장상태 지수 (SPI, PCI, 자체 지수 등)와 등급 구간
4. 보수공법 결정 기준 (균열률·소성변형·평탄성 임계값)
5. 포장상태 조사 결과 데이터의 외부 연계 가능 여부

※ 위 정보는 솔루션의 판정 기준을 기관 운영 기준과 맞추기 위한 것이며,
   확보한 자료는 해당 목적 외에 사용하지 않습니다.
```

**문의처** — 부산광역시 도로관리 담당부서 / 경상남도 도로 담당부서
(정확한 부서명은 확인 필요)
