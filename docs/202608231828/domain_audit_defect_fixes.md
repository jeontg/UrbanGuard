# 4개 도메인 전수 점검 — 발견 결함 전체 수정

앤시정보기술(주) · 2026-08-23

## 1. 배경

○ 요청: 침수·교통위험·인파관리·도로 노면 관리 **4개 도메인**에 대해 「메뉴들
  간에, 메뉴 안 기능들 간에 문제가 없는지」 전수 점검 → 이어서 **발견된 모든
  결함을 수정**

○ 점검 방법: 5개 영역(메뉴·권한 / 카메라·ROI / 모델 관리 / 이벤트·알림 /
  화면 렌더링)을 코드 기반으로 병렬 조사하고, 규모가 큰 2건은 별도 설계 검토를
  거침

○ 확인된 성격: **화면이 실제와 다른 것을 말하는 결함**과, **설정이 저장은
  되지만 실제 로직에 반영되지 않는 결함**이 다수

## 3. 특히 중요한 수정 세 가지

### 3-1. 부서담당자 권한이 담당 도메인으로 제한되지 않던 문제 [치명]

○ `core/roles.py` 가 `SETTINGS_OPS` 를 `DOMAIN_SCOPED` 로 선언해 두었는데,
  이 자원을 쓰는 **모든 라우트가 `domain=` 을 넘기지 않아** 검사가 통째로
  건너뛰어지고 있었음

○ 결과: 인파 담당 부서담당자가 침수·교통·도로의 CCTV 등록/삭제, ROI, 위험도
  임계값, 알림 규칙까지 열람·수정 가능

○ 조치: `routes_cameras.py`·`routes_levels.py`·`routes_config.py` 전반에
  도메인 스코프 적용. 자원 성격에 따라 세 가지 기준을 구분
  - 메타데이터 수정 → 담당 도메인이 **하나라도** 겹치면 허용
  - ROI·임계값 → 그 **도메인 담당자만**
  - 카메라 삭제 → 걸친 도메인 **전부**가 담당일 때만(공용 카메라 보호)
  - 지역 일괄 해지·인접관계 재계산 등 전역 작업 → **시스템관리자 전용**

⚠ 이 결함이 오래 남아 있던 이유: **부서담당자(MGR) 역할 계정을 만드는
  시험이 저장소 전체에 하나도 없었음**(`grep -rn "Role.MGR.value" tests/`
  결과 0건). 신규 시험 21건을 추가해 막음

### 3-2. 저장한 ROI가 실제 판정에 쓰이지 않던 문제 [치명]

| 도메인 | 증상 | 조치 |
|---|---|---|
| 침수 | 웹 편집기는 DB에 저장하는데 판정 엔진은 레거시 파일만 읽음 | `load_roi_for_camera()` 신설(DB 우선·파일 폴백), 판정 루프가 변경을 감지해 **재기동 없이** 갈아 끼움 |
| 교통위험 | `congestion_roi` 를 **필수로 강제**하면서 판정은 화면 전체를 씀 | 정체 판정 집계에 ROI 필터 적용 |
| 노면 | `analysis_roi` 를 아무도 읽지 않음 | 손상 탐지 결과에 ROI 필터 적용 |

○ 설계 원칙 두 가지를 지킴
  - **프레임을 마스킹·크롭하지 않는다** — 탐지는 원본 전체에 돌리고 결과만
    기하학적으로 거른다(인위적 경계를 모델이 오탐할 위험 회피)
  - **추적은 전체 프레임 대상으로 유지** — ROI를 드나들 때 트랙이 끊기면
    속도가 0이 된다. `last_objects` 도 거르지 않는다(침수 판정이 이 목록으로
    물-차량 접촉을 보므로, 거르면 침수가 회귀)

### 3-3. 카메라 상시 지정이 재기동 전까지 반영되지 않던 문제 [치명]

○ 노면 워처는 이미 `config_rev` 를 구독하고 있었으나 **침수만 빠져 있었음** —
  화면에는 「상시」로 뜨는데 실제로는 아무도 그 지점을 보지 않는 상태

○ 조치: `PipelineRunner` 에 수퍼바이저 스레드를 두어 추가된 지점은 워커를
  띄우고 제외된 지점은 정지·정리

○ **실측 확인**(2026-08-23, 라이브 서비스): 상시 지정 해제 → `targets` 6→5,
  복구 → 5→6. 재기동 없이 반영됨. 러너 로그에도 재조정 내역이 남음

⚠ 이미 상시 중인 지점을 제외하면 시계열 추적 상태가 사라짐 — 노면이 이미 지고
  있는 동일한 트레이드오프이며, 「설정과 동작이 일치해야 한다」를 위해 감수

## 5. 남은 한계 (⚠ 확인이 필요합니다)

○ **노면 ROI 효과는 지금 검증할 수 없음** — 현재 노면 모델이 부산 CCTV에서
  실측 탐지 0건(RDD2022 도메인 갭)이라, 필터 로직은 단위시험으로만 보장.
  실제 효과는 모델 교체 후 재확인 필요

○ **ROI 좌표 보정은 종횡비가 같은 경우로 한정** — 레터박스·크롭이 섞이면
  부정확. 2차 과제

○ **손상 박스가 ROI 경계에 걸치면 중심점 기준으로 통째 제외** — 실사용에서
  경계 누락이 문제로 확인되면 겹침비율 방식으로 개선(2차 과제)

○ **기존에 저장된 ROI 폴리곤의 타당성은 미검증** — 저장 시 「3점 이상」만
  강제하고 실제로 도로 위 정상 영역인지는 검사하지 않음. 운영 반영 전
  면적 비율이 비정상적으로 작은 카메라를 골라 재작도 요청 권고

○ **교통 속도 추정(`speed_line`)은 이번 범위 밖** — 차량 카운팅·정체 판정까지

○ **이미 상시 중인 지점의 부가 설정(rain/river/source) 변경은 즉시 반영 대상
  아님** — 추적 상태 손실을 피하기 위한 의도적 범위 제한

○ **`/settings/blocks`(레거시 YAML 감시지점 관리)** — 라우터에 등록조차 되지
  않은 죽은 코드로 확인. 삭제 권고하나 별도 정리 과제로 분리
