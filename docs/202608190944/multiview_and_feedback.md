## 2. ⚠️ S-05 를 정지화면으로 만든 이유

**실시간 HLS 영상이 아니라 4초마다 갱신되는 정지화면**입니다.
타협이 아니라 **우리 제약에서 나온 결론**입니다.

### 이유 ① 망분리 — 발견한 사실

작업 중에 확인했습니다.

> `src/tot_dashboard/service/templates/index.html:153`
> `<script src="https://cdn.jsdelivr.net/npm/hls.js@1.5.13/…">`

**기존 화면이 hls.js 를 CDN 에서 불러옵니다.** 폐쇄망 납품에서 그대로
깨집니다. 경남 제안요청서 **PER-009** 가 「외부 네트워크 연결 없이도 정상
동작」을 요구하는데 정면으로 어긋납니다.

**여기서 같은 빚을 지지 않았습니다.** 새 화면은 외부 스크립트를 쓰지 않습니다.

> ★ **2026-08-19 추가 — 기존 `index.html` 의 CDN 의존도 고쳤습니다.**
> 처음에는 범위 밖으로 두었으나 확인 요청에 「A(로컬 반입)」로 답을
> 받았습니다. 12절 참고.

### 이유 ② 비식별

`core/snapshot.py` 는 **사람 영역 마스킹을 이미 적용**합니다. 다분할 화면은
여러 명이 동시에 보는 자리라 마스킹이 더 중요합니다.

⚠️ 마스킹은 **실패할 수 있고**, 실패해도 영상은 나옵니다. 그래서 타일에
**「마스킹 실패」 배지**를 띄웁니다 — 가리지 못한 사실이 화면까지 가야 합니다.

### 그래서 이렇게 만들었습니다

| 항목 | 결정 |
|---|---|
| 갱신 주기 | **4초** (서버 캐시 수명과 맞춤) |
| 분할 | **4 / 9 / 16** |
| 서버 부하 | 지점별 **4초 캐시** — 16칸이 같은 지점을 봐도 원본은 한 번만 |

> ⚠️ **통상 사양은 64~128채널**입니다(202608172039 조사).
> **실측 없이 늘리지 않았습니다** — 숫자를 키우는 것은 쉽고 되돌리는 것은
> 어렵습니다.

## 4. S-07 이 하는 일

### 판정 4종

| 판정 | 사유 필수 | 비고 |
|---|---|---|
| 실제 상황 | | |
| **오탐** | **필수** | 무엇을 잘못 봤는지가 모델 개선의 알맹이 |
| 판단 보류 | | 「모르겠다」가 정직한 답인 경우가 실제로 있음 |
| **미탐 신고** | **필수** | 붙일 이벤트가 없어 지점·시각·유형을 직접 적음 |

> ⚠️ **억지로 둘 중 하나를 고르게 하면 사람은 아무거나 찍습니다.**
> 「판단 보류」가 그래서 있습니다.

### 판정 대기는 **종결된 것만**

진행 중인 사건을 두고 오탐이냐 묻는 것은 **순서가 틀렸습니다.**
관제요원은 지금 대응해야 합니다.

### 판정을 고쳐 쓰지 않고 쌓습니다

「처음엔 오탐이라 했다가 정탐으로 바꿨다」는 **사실 자체가 모델 평가에 필요한
정보**입니다. 화면은 최신 판정만 보여 주되 이력은 남습니다.

### 오탐률 계산에서 뺀 것

**판단 보류와 미탐을 분모에서 뺐습니다.** 판단 보류는 정탐도 오탐도 아니고,
미탐은 애초에 이벤트가 없어 분모가 다릅니다 — 섞으면 숫자가 무슨 뜻인지
아무도 모르게 됩니다.

> ⚠️ **판정이 하나도 없으면 오탐률을 만들지 않습니다.** 0% 는 「오탐이 없다」로
> 읽히는데 실제로는 「아직 아무도 안 봤다」입니다. 화면에 「—」로 둡니다.

### ⚠️ 판정 ≠ 학습

`used_for_training` 칸이 따로 있고, 화면에 「학습 반영 / 대기」로 보입니다.
**한 번 잘못 찍은 클릭이 모델을 바꾸면 안 됩니다.**

### 왜 이번엔 고쳤나

| 이유 | |
|---|---|
| 1 | **「간헐」이 아니었습니다** — 4회 중 2회 실패, 소규모 실행에서도 재현 |

> **범위 밖이라는 판단은 유지합니다.** 다만 회귀를 계속 막고 있어 고쳤고,

### 어떻게 고쳤나

| 방법 | 판단 |
|---|---|
| 마이크로초로 늘리기 | ✗ **확률을 낮출 뿐 없애지 못함** |
| **겹치면 번호 붙이기** | **✓ 확실함** |
| 내용 같으면 생략 | ✗ 「같은 값을 두 번 저장」과 구분이 안 됨 |

`KEEP_BACKUPS` 정리 정렬이 **여전히 시간순인지도** 함께 확인했습니다 —
기준 시각이 고정폭이라 `…_123` < `…_123-1` < `…_124` 로 순서가 유지됩니다.

**시계를 고정한 시험**으로 못박았습니다. 실행 속도에 기대면 빠른 장비에서만
