## 0. 결론 먼저

○ **셋을 같은 무게로 다루면 안 됩니다.** 하나는 관문, 하나는 차별점,
  하나는 지금 하면 손해입니다

| 기술 | 판단 | 한 줄 이유 |
|---|---|---|
| **VLM** | **선택이 아니라 관문** | RFP가 명시 요구 · 안 하면 이 계열 사업이 막힘 |
| **Urban Ontology** | **가장 값어치 있는 투자** | 요구는 없지만 **요구를 충족시키는 수단** · 비용 최저 |
| **GraphDB** | **지금은 도입 보류** | 요구 없음 + PostgreSQL 단일 원칙 위배 + 폐쇄망 부담 |

○ ⚠️ **30B VLM을 우리가 직접 하는 것은 불가능합니다.** 경남 사양이
  **NPU 서버 12대 × NPU 카드 8장**입니다. 우리 개발기는 **i7-1360P CPU 한 대**입니다

○ ★ **우리가 유리한 이유는 「그래프를 채울 내용이 이미 있다」는 것입니다.**
  SOP·이벤트 이력·반출대장·오류 사전을 가진 회사는 많지 않습니다

## 1. 근거 ① — RFP 4건 전수 검색

확보한 원문 4건(경남·울산·서울시·KLID)의 **본문과 표 전체**에서 검색했습니다.

| 검색어 | 경남 | 울산 | 서울 | KLID |
|---|---|---|---|---|
| 온톨로지 · 지식그래프 · 시맨틱 | 0 | 0 | 0 | 0 |
| RDF · SPARQL · Knowledge Graph | 0 | 0 | 0 | 0 |
| NGSI · FIWARE · CityGML | 0 | 0 | 0 | 0 |
| 그래프DB | 0 | 0 | 0 | 0 |

**발주처는 이 용어들을 쓰지 않습니다.**

반대로 VLM은 **요구를 넘어 평가 항목**입니다.

| 위치 | 원문 |
|---|---|
| 경남 SFR-004 | 「서버당 **300채널 이상**의 CCTV 영상을 **VLM 모델을 통해 분석**하여 … 자연어 텍스트로 상황을 묘사」 |
| 경남 SFR-010 | 「**DETR 기반 정밀 탐지와 Zero-shot 기반 범용 인지**를 선택 또는 병행」 |
| 경남 SFR-011 | 「**30B(300억 개) 이상** 수준의 VLM 모델을 기본 제공」 |
| 경남 SFR-012 | 「내부 규정·매뉴얼·과거 처리 이력을 **RAG(검색 증강 생성) 방식으로 학습**하여 … **근거 문서를 함께 제시**」 |
| 서울 SFR-006·007 | 「**폐쇄망 전용 생성형 VLM 모델** 선정 및 도입」「VLM 기반 상황 맥락 분석」 |
| **서울 기술평가 항목** | 「생성형AI 성능 확보 및 **환각현상을 줄이기 위한 RAG 기술 적용전략 제시**」 |

> 마지막 줄이 중요합니다. **RAG 전략이 점수로 매겨집니다.**

## 2. 근거 ② — PostgreSQL 설치본 실사 (2026-08-18)

`.tools/pgsql/share/extension/` 을 직접 확인했습니다.

| 확장 | 있음? | trusted? |
|---|---|---|
| `age` (그래프) | **없음** | — |
| `vector` (RAG 임베딩) | **없음** | — |
| `postgis` · `timescaledb` | **없음** | — |
| `ltree` (계층) | **있음** | **trusted = true** |
| `cube` | 있음 | trusted = true |
| `intarray` · `pg_trgm` | 있음 | trusted = true |
| `earthdistance` | 있음 | **없음 → superuser 필요** |

### 이 실사가 바꾼 것

앞선 회차(`202608171820`)에서 **`earthdistance` 가 superuser를 요구해 막혔다**고
적었습니다. 그때 확장 도입을 접었는데, 이번에 보니

> **`ltree` 는 trusted 입니다.** `urbanguard` 계정으로 `CREATE EXTENSION ltree` 가
> 됩니다. **계층 구조는 추가 권한 없이 지금 쓸 수 있습니다.**

반면 `vector` 는 아예 파일이 없어 **바이너리 추가 설치**가 필요합니다.
폐쇄망 납품에서 설치 대상이 하나 느는 문제입니다.

## 3. VLM — 하되, 우리가 할 몫을 정확히 자릅니다

### 3-1. 하드웨어 현실

| 항목 | 경남 RFP 요구 | 우리 현재 |
|---|---|---|
| 분석 서버 | **NPU 서버 12대** (ECR-003) | i7-1360P CPU **1대** |
| NPU 카드 | 서버당 **8장** | 없음 |
| VLM 규모 | **30B 이상** (SFR-011) | 없음 |
| 채널 | 서버당 **300채널 이상** (SFR-004) | 상시 7지점 |
| 망 | **완전 폐쇄망** (PER-009) | 개발망 |

**30B는 우리 몫이 아닙니다.** 하드웨어·인증과 함께 파트너가 가져갑니다.

### 3-2. 우리가 할 자리

VLM이 뱉는 것은 **자연어 문장 하나**입니다. 경남 SFR-004의 예시가 그렇습니다.

> 「00장소 00시00분, **산불 1건 감지**」

그 문장을 **어떤 이벤트 스키마로 받아, 어떤 화면에 앉히고, 어떤 SOP·통보로
연결하는가** — 이것이 응용 계층이고, **우리가 이미 잘하는 일**입니다.

| 우리 자산 | VLM과 붙는 지점 |
|---|---|
| 이벤트 모델 (`events`) | VLM 출력을 이벤트로 승격 |
| 디지털 SOP (S-86) | 위험도 판정 → 단계 자동 제시 |
| 알림·통보 (S-50·51) | 등급별 전파 대상 자동 지정 |
| 이벤트 상세 (S-03) | 자연어 요약 + 근거 표시 |

### 3-3. 현실적인 시작

**2~8B급 소형 VLM으로 「상황 요약」만** 먼저 붙입니다. GPU 1장이면 됩니다.
30B가 필요한 순간은 **입찰에 실제로 들어갈 때**이고, 그때는 파트너와 함께입니다.

> ⚠️ 소형 VLM으로 시험했다는 사실을 **30B 보유로 포장하면 안 됩니다.**
> 제안서에는 「응용 계층 검증 완료, 모델은 컨소시엄 조달」로 적어야 합니다.

## 4. Urban Ontology — 요구는 없지만 요구를 충족시킵니다

### 4-1. 이름만 없을 뿐, RFP 곳곳이 관계 모델을 요구합니다

| RFP 원문 | 실제로 필요한 것 |
|---|---|
| 경남 기대효과: 「검지 결과를 자연어로 집계·융합하여 **재난 대응 지식의 자산화**」 | 지식 모델 |
| 경남 SFR-005: 「센서의 물리적 위치와 **인근 CCTV를 1:1 또는 N:1로 매핑**하여, 센서 이벤트 발생 시 **연관 카메라 영상을 즉시 호출**」 | **카메라–센서 관계** |
| 경남 기대효과: 「**시·군 경계를 넘나드는** 산불 확산·하천 범람·도로 통제를 **연속 추적**하여 대응 단절 최소화」 | **카메라–카메라 인접 관계** |
| 경남 SFR-012: 「단계별 SOP를 **도, 시·군별로** 자동 제시」 | **조직 계층 × 위험유형 × 등급** |
| KLID SFR-14: 「**사각지대 식별**」「**목적별** CCTV 설치 위치 분석」 | **카메라–구역–위험유형 관계** |
| KLID SFR-14: 「**침수흔적도, 인명피해 우려지역** 지도 기반 시각화」 | **위험구역 개체** |

**여섯 줄 전부가 「관계」를 요구합니다.** 온톨로지라는 말만 없습니다.

### 4-2. 환각을 줄이는 가장 확실한 수단

서울시가 **평가 항목으로** 묻는 「환각 저감 전략」에 대해, 업계 표준 답변은 RAG입니다.
그러나 RAG는 **문서를 찾아줄 뿐**입니다.

> 「이 카메라는 지하차도를 향하고 있고, 볼 수 있는 위험유형은 침수·정체뿐이다」

이런 **제약**은 온톨로지가 겁니다. VLM이 「산불 감지」라고 뱉어도 걸러집니다.
**RAG + 온톨로지 제약**을 함께 쓰는 전략은 대부분의 경쟁사가 준비하지 않습니다.

### 4-3. 왜 우리가 유리한가

온톨로지는 **뼈대**입니다. 채울 내용이 없으면 빈 그래프입니다.

| 우리가 이미 가진 「내용물」 | 화면 |
|---|---|
| 디지털 SOP 단계 정의 | S-86 |
| 이벤트 조치 이력 (`event_actions`) | S-03 |
| SOP 이행 기록 (`event_sop_checks`) | S-03 |
| 영상 반출 관리대장 | S-94 |
| 오류 코드 사전 | S-93 |
| 캘리브레이션(지면·침수심·구간) | S-82 |

**대부분의 VMS 회사는 이 데이터를 애초에 모으지 않습니다.**

### 4-4. ⚠️ 정직하게 — 온톨로지의 위험

| # | 위험 | 대응 |
|---|---|---|
| 1 | **증명하기 어렵다.** 발주처가 못 알아보면 점수가 안 됨 | **반드시 화면으로 보여야** 함 — S-63 사각지대, S-06 타임라인, S-03 근거 표시 |
| 2 | **표준 선택을 아직 못 정한다.** NGSI-LD/Smart Data Models · CityGML · SAREF4CITY가 후보지만 **경남 스마트시티 데이터허브가 무엇을 쓰는지 원문에 없음** | **데이터허브 표준 확인이 선행** — 자체 설계는 우리 규모에 무리 |
| 3 | **설계 경험이 필요하다** | 개발부에 경험자가 있는지 **확인 필요** |
| 4 | 과하게 만들면 **아무도 안 씀** | **화면이 쓰는 관계만** 만든다 — 1단계 설계서의 원칙 |

## 5. GraphDB — 지금은 도입하지 않습니다

### 5-1. 세 가지 이유

| # | 이유 | 근거 |
|---|---|---|
| 1 | **PostgreSQL 단일 원칙 위배** | 프로젝트 제약 사항 |
| 2 | **폐쇄망 설치 부담** | PostGIS·TimescaleDB를 안 넣기로 한 것과 같은 판단. 별도 DBMS는 그보다 큰 추가 |
| 3 | **성능 이점이 안 나옴** | 경남이 **4,500채널**입니다. 4,500 노드 규모는 PostgreSQL 재귀 CTE로 충분 |

### 5-2. 대신 이렇게 합니다

| 필요 | PostgreSQL 안에서 |
|---|---|
| 행정구역·조직 계층 | **`ltree`** (trusted, 추가 설치 없음) |
| 카메라–센서·카메라–카메라 관계 | **관계 테이블** |
| 인접 탐색 (N홉) | **재귀 CTE** (`WITH RECURSIVE`) |
| 거리 계산 | **순수 SQL haversine** — 39지점 **7.2ms** 실측 |

### 5-3. 나중에 다시 볼 조건

**셋 중 하나라도 참이 되면** 재검토합니다.

| # | 조건 |
|---|---|
| 1 | 관계 질의가 **실측으로** 느려질 때 (재귀 CTE 응답 > 500ms) |
| 2 | 관계 깊이가 **5홉을 넘어갈 때** |
| 3 | 발주처가 **명시적으로 요구**할 때 |

> **추측으로 도입하지 않고, 실측이 말할 때 도입합니다.** ONNX·OpenVINO를
> 실측으로 결정했던 것과 같은 방식입니다.

## 6. 그래서 무엇부터

| 단계 | 할 일 | 추가 설치 | 비고 |
|---|---|---|---|
| **1** | **관계 모델 정의** — 카메라·센서·구역·위험유형·SOP | **`ltree` 만** | **본 회차 설계 완료** |
| 2 | 관계를 **화면으로 증명** — S-06 · S-63 · S-03 인접 카메라 | 없음 | |
| 3 | **소형 VLM(2~8B) 상황 요약** 시험 | GPU 필요 | 30B는 파트너 |
| 4 | RAG — `pgvector` 도입 판단 | **바이너리 추가** | 폐쇄망 부담 검토 |
| 5 | GraphDB | — | **5-3 조건 충족 시에만** |

**1단계가 핵심입니다.** 온톨로지는 「도입」하는 물건이 아니라
**데이터를 어떻게 정의하느냐**의 문제라, 지금 안 잡으면 나중에 전면 재작업입니다.

상세 설계는 같은 폴더의 **`relation_model_design.md`** 에 있습니다.
