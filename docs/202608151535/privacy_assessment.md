>
> **AI 학습용 도로 영상 수집 기능이 생겼습니다.** 그동안은 CCTV 영상을 실시간으로
> 보고 버렸는데, 이제 프레임을 **디스크에 오래 보관**합니다. 개인정보 관점에서
> 성격이 다른 처리라 별도 검토가 필요합니다(3-2-C절).
>
> 특히 아래 두 가지는 **개발사가 판단할 수 없는 법적 쟁점**입니다.
> 1. **목적 외 이용 여부** — 「관제」 목적으로 수집한 CCTV 영상을 「AI 학습」에
>    쓰는 것이 같은 목적 범위인지 (8절 신규 문항)
> 2. **학습된 모델에서는 파기가 성립하지 않음** — 원본 프레임은 지울 수 있으나
>    이미 학습에 반영된 가중치에서 특정 영상의 기여를 되돌릴 수 없습니다

> ## ⚠️ 이 문서의 성격을 먼저 밝힙니다
>
> **이것은 법정 개인정보 영향평가서(PIA)가 아닙니다.**
>
> 영향평가는 「개인정보 보호법」에 따라 **개인정보보호위원회가 지정한 평가기관**이
> 수행해야 합니다. 시스템 개발사가 작성한 문서로 갈음할 수 없습니다.
>
> 이 문서의 목적은 두 가지입니다.
> 1. **평가 대상 여부 판단에 필요한 사실관계**를 개발사가 정리해 제공
> 2. 평가가 진행될 경우 **평가기관이 요구할 입력 자료**를 미리 준비
>
> **대상 여부 판단과 실제 평가는 발주 지자체의 개인정보 담당 부서 소관입니다.**

## 1. 대상 여부 판단 자료

### 1-1. 법령상 의무 대상 기준 (참고)

「개인정보 보호법」 제33조 및 시행령 제35조는 공공기관이 일정 규모 이상의
개인정보파일을 운용하는 경우 영향평가를 의무화하고 있습니다. 기준에는 정보주체
수(5만/50만/100만 등)와 **민감정보·고유식별정보 포함 여부**가 관여합니다.

> **⚠️ 구체적 수치 기준과 최신 개정 내용은 반드시 개인정보보호위원회 고시와
> 지자체 담당 부서를 통해 확인하십시오.** 개발사가 이 문서에서 단정하지 않습니다.

### 1-2. 판단에 필요한 우리 시스템의 사실관계

| 질문 | 사실 |
|---|---|
| 고유식별정보를 수집하는가 | **아니오.** 주민등록번호·여권번호·운전면허번호 등 미수집 |
| 민감정보를 수집하는가 | **아니오** (사상·건강·유전·범죄경력 등 미수집) |
| 영상정보를 처리하는가 | **예.** CCTV 실시간 영상 + 현장 제보 사진 |
| 위치정보를 수집하는가 | **예 (제한적).** 제보 시 사용자가 버튼을 눌러야 첨부 |
| 정보주체는 누구인가 | ① 운영 직원(계정 보유자) ② **CCTV에 촬영되는 불특정 시민** |
| 정보주체 규모 | 직원 수십 명 / **시민은 촬영 범위에 따라 불특정 다수** |
| 외부 제공이 있는가 | 문자 발송(SOLAPI), 선택 시 외부 AI(VLM) — 3-4절 |

### 1-3. ★ 개발사 의견

**「불특정 다수 시민의 영상정보를 처리」한다는 점에서, 대상 여부를 반드시
확인해야 한다고 봅니다.** 계정 정보만 보면 규모가 작지만, CCTV 영상은
성격이 다릅니다.

특히 아래 두 가지가 쟁점이 될 것으로 판단합니다.

1. **현장 제보 기능** — 시민이 찍은 사진을 서버에 저장하며, 사람과
   차량번호가 함께 찍힙니다. 위치정보도 붙을 수 있습니다.
2. **외부 AI(VLM) 연계** — 켜면 **CCTV 프레임이 외부 서비스로 전송**됩니다.
   현재는 선택 기능이며 기본 비활성입니다.

> **저장을 포기**하고 화면에 그 사실을 표시합니다. 시험 편의를 위해 개인정보
> 보호를 양보하지 않습니다.
>
> ⚠️ **차량번호판은 여전히 가리지 않습니다** — 사람만 가립니다(4-1절과 동일한
> 한계).

### 3-1. CCTV 영상 (가장 민감)

```
 [CCTV 스트림]
      │  HLS 수신 — 저장하지 않음
      ▼
 [메모리상 프레임]
      │
      ├──▶ 탐지 분석 ──▶ 수치만 남김 (인원 수·밀집도·등급)
      │                   ★ 개인 식별 정보 미포함
      │
      ├──▶ 실시간 관제 화면 ──▶ ⚠️ **마스킹 없이 표시**
      │                          (관제 목적상 사람을 봐야 함)
      │
      └──▶ 관측 스냅샷 ──▶ [사람 영역 픽셀화] ──▶ 화면 표시
                              │ 실패 시
                              └──▶ **표시하지 않음**
```

**저장되는 것은 수치뿐입니다.** 「몇 시 몇 분에 몇 명이 있었고 등급이 얼마였다」는
남지만, 그 사람이 누구인지는 남지 않습니다.

### 3-2-B. 업로드 동영상 (2026-08-12 신규) ★

관리자가 화면에서 분석용 동영상을 올릴 수 있게 됐습니다(S-80).

```
 [관리자가 동영상 업로드]
      │  설정 권한자만 가능 · 최대 500MB
      ▼
 [data/videos/ 에 원본 그대로 저장]   ⚠️ 마스킹하지 않음
      │
      ├──▶ 노면·침수 분석 입력
      └──▶ ROI 설정 화면의 정지영상 ──▶ [사람 영역 픽셀화] ──▶ 표시
```

> ### ⚠️ 업로드 동영상은 원본 그대로 보관됩니다
> 제보 사진과 달리 **마스킹하지 않습니다.** 분석 정확도를 위해 원본이
> 필요하기 때문입니다. 다음이 확인되어야 합니다.
>
> - 어떤 영상을 올릴 것인지 — **기관이 보유한 CCTV 녹화분**이라면 그 자체가
>   이미 기관의 영상정보처리기기 운영·관리 방침 적용 대상입니다
> - 보존기간과 파기 절차 — 현재 **자동 파기가 없습니다**
> - 한 카메라당 한 편만 남고 새로 올리면 이전 것이 지워집니다

### 3-2-C. ★ AI 학습용 도로 영상 수집 (2026-08-13 신규)

관제 중인 CCTV 프레임과 담당자가 올린 영상에서 **학습용 이미지를 뽑아 장기
보관**하는 기능이 생겼습니다(S-44). 지금까지의 처리와 성격이 다릅니다 —
**보고 버리는 것이 아니라 쌓아 두고 다시 쓰는 것**입니다.

```
 [경로 ①] 상시 순회·집중 감시가 관측한 프레임
      │  ※ 스트림을 새로 열지 않고 분석용 프레임을 함께 씀
      ▼
 [사람 영역 마스킹]──실패시──▶ [저장하지 않고 버림] ★
      │ 성공
      ▼
 [data/datasets/road_cctv_own/raw/<지점>/ 에 JPG 저장]
      │  + meta.jsonl (수집 시각·출처·마스킹 상태·번호판 미마스킹 표기)
      ▼
 [사람이 라벨링 → 모델 학습]

 [경로 ②] 담당자가 올린 영상 (현장 촬영·블랙박스)
      │
      ▼
 [프레임 추출 → 사람 마스킹 → 저장] ──▶ [원본 영상 즉시 삭제] ★
```

**설계에 넣은 통제**

| 항목 | 내용 |
|---|---|
| 기본 상태 | **꺼짐**. 관리자가 화면에서 켜야 동작 |
| 권한 | **시스템 설정 권한**(SYS). 관제 권한만으로는 켤 수 없음 |
| 기록 | 켜고 끈 이력이 **감사 로그**에 남음 |
| 마스킹 | **실패하면 저장하지 않음** — 제보 사진보다 강한 원칙 |
| 수집량 | 지점당 하루 8장 · 같은 지점 최소 30분 간격 · 총량 2GB 상한 |
| 원본 영상 | 업로드 경로는 **보관하지 않음**(프레임만 남김) |
| 출처 기록 | `meta.jsonl` 에 수집 시각·경로·해상도·마스킹 상태 |

> ### ⚠️ 그럼에도 남는 문제 세 가지
>
> **① 차량번호판은 여전히 가리지 못합니다.** 사람만 가립니다. 수집한 프레임을
> 외부(위탁 라벨링 업체 등)로 내보내면 번호판이 그대로 나갑니다.
> `meta.jsonl` 에 `plate_masked: false` 로 명시하고 화면에도 표시하지만,
> **표시가 통제는 아닙니다.**
>
> **② 목적 외 이용 여부를 개발사가 판단할 수 없습니다.** 기관이 「교통·방범
> 관제」 목적으로 설치·수집한 CCTV 영상을, 「AI 모델 학습」이라는 다른 목적에
> 쓰는 것이 허용되는지는 **기관의 영상정보처리기기 운영·관리 방침과 개인정보
> 담당 부서의 판단** 사항입니다. 8절에 문항으로 올렸습니다.
>
> **③ 학습된 모델에서는 파기가 성립하지 않습니다.** 원본 JPG 는 지울 수 있지만,
> 이미 학습에 반영된 가중치에서 특정 영상의 기여를 되돌릴 방법이 없습니다.
> 따라서 **수집 단계의 통제가 사실상 마지막 통제**입니다.

### 3-3. 외부 전송

| 대상 | 전송 내용 | 상태 |
|---|---|---|
| SOLAPI (문자) | 수신번호·본문 | 설정 시 동작. **번호는 DB 미저장** |
| **Google Gemini (VLM)** | **CCTV 프레임 이미지** | ⚠️ **선택 기능·기본 비활성** |
| 기상청·홍수통제소 | 지점 좌표 (개인정보 아님) | 동작 |

> ### ⚠️ VLM 연계는 승인 없이 켜면 안 됩니다
> 켜는 순간 **CCTV 영상 프레임이 국외 사업자에게 전송**됩니다.
> 국외 이전에 해당할 수 있으며, 별도 고지·동의 또는 법적 근거가 필요합니다.
> 현재는 API 키가 없으면 자동 비활성이나, **운영 배포 시 명시적으로 차단**할 것을
> 권고합니다.

## 4. 위험도 평가

| # | 위험 | 가능성 | 영향 | 등급 | 현재 대응 |
|---|---|---|---|---|---|
| 1 | **제보 사진의 차량번호 노출** | 높음 | 중간 | ⚠️ **높음** | ❌ **자동 마스킹 없음** — 육안 확인 |
| 2 | **VLM으로 영상 국외 이전** | 낮음(기본 꺼짐) | **높음** | ⚠️ **높음** | 기본 비활성 |
| 3 | **평문 통신(HTTP)으로 세션 탈취** | 중간 | 높음 | ⚠️ **높음** | ❌ **HTTPS 미적용** |
| 4 | 관제 화면 영상의 무단 촬영·유출 | 중간 | 중간 | 중간 | 계정·권한 통제. **열람 이력 미기록** |
| 5 | 마스킹 모델 미동작 시 원본 노출 | 낮음 | 높음 | 중간 | ✅ **실패 시 표시 안 함** |
| 6 | 제보 위치정보로 이동 경로 추정 | 낮음 | 중간 | 낮음 | 사용자가 버튼을 눌러야 첨부 |
| 7 | 계정 탈취 | 낮음 | 높음 | 중간 | ✅ 잠금·2인 승인 |
| 8 | **보관 데이터 무한 누적** | **확실** | 중간 | ⚠️ **높음** | ❌ **파기 정책 미구현** |
| 9 | **업로드 동영상이 원본 그대로 보관**(S-80 카메라 등록분) | 확실 | **높음** | ⚠️ **높음** | ❌ 마스킹 없음 · 파기 없음 |
| 10 | ROI 설정 화면의 정지영상 | 낮음 | 중간 | 낮음 | 마스킹하되 실패 시에도 표시(설정 권한자 한정) |
| **11** | **학습 데이터의 목적 외 이용 소지** | 중간 | **높음** | ⚠️ **높음** | ❌ **판단 미확정** — 8절 문항 |
| **12** | **학습 데이터 반출 시 번호판 노출** | 중간 | **높음** | ⚠️ **높음** | ❌ 표시만 · 반출 통제 없음 |
| **13** | **학습된 모델에서 파기 불가** | 확실 | 중간 | 중간 | 수집 단계 통제가 유일 |
| **14** | 학습 프레임 무한 누적 | 낮음 | 중간 | 낮음 | ✅ 지점당 하루 8장·총량 2GB 상한 |

### 4-1. ★ 최우선 3건

**① 차량번호판 마스킹 미구현 (위험 1)**
사람은 가리지만 번호판은 가리지 못합니다. 전용 검출 모델이 없기 때문입니다.
현재는 화면에 「번호판은 자동으로 가려지지 않으니 육안 확인 필요」를 표시하는
것으로 갈음하고 있습니다. **제보 기능을 운영에 넣으려면 결론이 필요합니다.**

선택지:
- (a) 번호판 검출 모델 추가 개발·도입
- (b) 제보 사진을 **담당자 승인 전까지 비공개**로 두고 승인 시 수동 마스킹
- (c) 제보 기능을 1차 납품 범위에서 제외

**② HTTPS 미적용 (위험 3)**
로그인 비밀번호와 세션 쿠키가 평문으로 오갑니다. 관제망 내부라도 권장되지
않습니다. **코드 변경 없이 배포 설정만으로 해결**되므로 즉시 조치 가능합니다.

**③ 파기 정책 미구현 (위험 8)**
보존기간이 정해지지 않았고 자동 파기 기능도 없습니다. 데이터가 무한히
쌓입니다. 5절 참조.

**④ 학습 데이터의 목적 외 이용 소지 (위험 11) — 2026-08-13 신규**
관제 목적으로 수집한 CCTV 영상을 AI 학습에 쓰는 것이 같은 목적 범위인지
**확정되지 않았습니다.** 기능은 만들었으나 **기본값을 꺼짐으로 두었고**,
켜는 데 시스템 설정 권한과 감사 로그를 요구합니다. 8절 10번 문항의 답이
나오기 전에는 켜지 않는 것이 맞습니다.

## 5. 보존기간·파기 (⚠️ 미구현)

### 5-1. 현재 상태

**파기 기능이 구현되어 있지 않습니다.** 모든 데이터가 영구 보관됩니다.

### 5-2. 권고안 (확인 필요)

| 데이터 | 권고 보존기간 | 근거 |
|---|---|---|
| 감사 로그 | **기록물 관리 규정에 따름** | ⚠️ 기관 확인 필요 |
| 이벤트·조치 이력 | 3~5년 | 사후 책임 규명 |
| 알림 발송 이력 | 3~5년 | 위와 동일 |
| **제보 사진** | **처리 완료 후 즉시 또는 단기** | **개인정보 최소보관** |
| 제보 위치정보 | 처리 완료 후 파기 | |
| **업로드 동영상** | **분석 목적 달성 후 즉시** | 원본 영상이라 가장 민감 |
| 퇴직자 계정 | 즉시 비활성 → 일정 기간 후 삭제 | 감사 로그는 별도 보존 |

> **제보 사진의 보존기간을 가장 짧게 잡을 것을 권고합니다.** 개인정보가 가장
> 많이 담기고, 처리가 끝나면 보관할 이유가 약합니다.

### 5-3. 구현 시 고려사항

- 계정 삭제 시에도 **감사 로그는 남아야 합니다**(`SET NULL` + `login_id` 복제)
- 이벤트 삭제 시 조치 이력이 `CASCADE` 로 함께 사라집니다 — 보존기간을 맞춰야 합니다
- 파일(제보 사진)과 DB 행을 **함께** 지워야 합니다. 한쪽만 지우면 고아가 남습니다

## 6. 정보주체 권리 보장 (⚠️ 미구현)

| 권리 | 현재 상태 |
|---|---|
| 열람 요구 | ❌ 절차·기능 없음 |
| 정정·삭제 요구 | ⚠️ 제보 사진만 담당자가 수동 파기 가능 |
| 처리정지 요구 | ❌ 없음 |
| **개인정보 처리방침 게시** | ❌ **없음** |
| CCTV 촬영 안내판 | 기존 CCTV 설치 시 기관이 처리 (우리 범위 밖) |

> **처리방침 게시는 화면에 추가할 수 있습니다.** 다만 **내용은 기관이 정해야
> 합니다** — 처리 목적·항목·보유기간·위탁 여부는 기관의 판단 사항입니다.

| # | 질문 | 영향 |

| 2 | **감사 로그·이벤트 이력의 보존 연한**은? | 파기 기능 개발 |
| 3 | **제보 사진 보존기간**은? | 위와 동일 |
| 4 | **차량번호판 미마스킹** 상태로 제보 기능을 운영해도 됩니까? | 제보 기능 범위 |
| 5 | 저장 데이터 **암호화 의무** 대상입니까? | 보안 설계 |
| 6 | **외부 AI(VLM)에 CCTV 영상 전송**을 승인하십니까? | 기능 활성 여부 |
| 7 | **개인정보 처리방침** 문안을 제공해 주실 수 있습니까? | 화면 추가 |
| 8 | 학습 목적의 제보 사진 보관이 적법합니까? | 데이터 활용 |
| 9 | **업로드 동영상의 출처와 보존기간**은? 마스킹 없이 보관해도 됩니까? | 3-2-B절 |
| **10** | ★ **관제 목적으로 수집한 CCTV 영상을 「AI 학습」에 쓰는 것이 목적 범위 안입니까?** 기관의 영상정보처리기기 운영·관리 방침에 학습 이용이 포함돼 있습니까? | **자동 수집 기능 사용 가부** |
| **11** | 학습 프레임을 **외부(라벨링 위탁 등)로 반출**해도 됩니까? 번호판이 가려지지 않은 상태입니다 | 라벨링 방식 |
| **12** | 학습 프레임의 **보존기간**은? 학습이 끝난 뒤 원본을 지워야 합니까? | 파기 기능 |
| **13** | ★ **오류 이력의 보존기간**은? 접속 IP·로그인 ID가 함께 남습니다 | 자동 파기 개발 |
| **14** | ★ **모델 시험 미리보기(CCTV 캡처)를 보관해도 됩니까?** 현재 최근 60장만 남깁니다 | 보관 정책 |

> ### ⚠️ 13번 — 오류 이력은 「지울 수 있게」만 해 두었습니다
> 운영자가 화면에서 「처리완료 건 중 N일 이전」을 지우는 방식이며, **자동
> 파기는 없습니다.** 보존 연한이 정해지면 감사 로그·이벤트와 함께 일괄 파기
> 기능을 만들어야 합니다(5절).

> ### ⚠️ 10번은 기능 사용 여부를 가르는 문항입니다
> 목적 범위 밖이라는 판단이 나오면 **자동 수집 기능을 켜서는 안 됩니다.**
> 그래서 이 기능의 기본값을 「꺼짐」으로 두었고, 켜는 데 시스템 설정 권한과
> 감사 로그를 요구합니다. **개발사가 대신 판단할 수 없는 사안입니다.**
