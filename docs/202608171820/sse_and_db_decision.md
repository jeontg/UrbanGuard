## 1. 상황판 SSE 전환

### 무엇이 문제였나

화면이 **1초마다 `/api/risk` 와 `/api/history` 를 물어봤습니다.** 관제 PC 한
대가 하루에 17만 번 넘게 묻는 셈인데 대부분은 **「바뀐 것 없음」** 이라는
답입니다. 갱신 지연도 폴링 주기에 묶여 **이미 바뀐 값을 최대 1초 뒤에**
봤습니다.

### 어떻게 바꿨나

| 항목 | 내용 |
|---|---|
| 방식 | **Server-Sent Events** — 단방향, 추가 의존성 **0** |
| 경로 | `GET /api/stream/risk` |
| 전송 | **바뀔 때만** (전체를 문자열로 만들어 비교) |
| 심박 | 조용해도 **15초마다** 주석 줄 — 중간 장비가 연결을 끊는다 |
| 상한 | 동시 구독 **32** — 새로고침이 연결을 안 닫고 쌓이는 일이 있다 |
| 권한 | **`/api/risk` 와 동일** — 스트림으로 우회해 더 볼 수 없다 |

**왜 WebSocket 이 아닌가** — 화면이 서버에 보낼 것이 없습니다. 단방향이면
충분하고, WebSocket 은 양쪽 상태를 관리해야 합니다. **망분리 환경에서
설치·검토 대상을 늘리지 않는 것**이 우선입니다.

### 끊겼을 때

```
SSE 연결 시도
  ├─ 성공        → 폴링 중단, 스트림으로 갱신
  ├─ 실패·끊김   → 폴링 재개 (화면이 멈추지 않는다)
  ├─ 구독 만석   → 서버가 event: full 로 알림 → 폴링
  └─ 구형 브라우저 → 폴링
```

**첫 화면은 폴링으로 즉시 채웁니다.** SSE 는 첫 값이 올 때까지 빈 화면입니다.

### 부수 효과 — 어긋남이 사라졌습니다

폴링일 때는 `/api/risk` 와 `/api/history` 를 **따로** 불렀습니다. 두 번
왕복하면 그 사이에 값이 바뀌어 **카드와 타임라인이 어긋나는** 순간이
생깁니다. 이제 **한 덩어리로** 보냅니다.

## 2. PostgreSQL 확장 — 넣지 않기로 했습니다

### 확인 결과

설계서에 「PostGIS·TimescaleDB·pgvector 를 얹자」고 썼습니다.
**실제 설치본을 조회해 보니 셋 다 없었습니다.**

| 확장 | 상태 |
|---|---|
| PostGIS · TimescaleDB · pgvector | **설치본에 없음** — 별도 바이너리 필요 |
| earthdistance | 번들에 있으나 **superuser 필요**(`urbanguard` 는 아님) |
| cube · btree_gist | 설치 가능 |

### 그런데 필요가 없습니다

확장 없이 **순수 SQL 하버사인**으로 「부산시청 기준 가까운 순」을 냈습니다.

```
39지점 · 확장 없음 · 7.2ms
    3.89km  광복로
    4.25km  재송삼익아파트삼거리
    5.29km  센텀시티역
```

### 판단

| 확장 | 언제 필요해지나 | 지금 버틸 수 있는 이유 |
|---|---|---|
| **PostGIS** | 지점 수백~수천, 폴리곤 연산 | 39지점 반경 질의가 **7.2ms** |
| **TimescaleDB** | 초당 수천 건 적재 | 우리는 39지점 × 분당 몇 건 |
| **pgvector** | 유사 상황 검색 착수 시 | 아직 그 기능이 없다 |

> ★ **납품 관점이 더 결정적입니다.**
> 망분리 고객사에서 **DBA 가 확장을 따로 설치해야 한다면 「DB 하나 유지」라는
> 이점이 오히려 약해집니다.** 확장을 넣는 순간 설치 가이드·보안 검토·백업
> 절차가 전부 늘어납니다.

**재검토 조건** — 지점 수 수백 이상 · 유사 검색 착수 · 적재량 급증.

## 3. 회귀에서 걸린 것 1건

`test_card_order.py` 가 `"orderBlocks(data.blocks"` 라는 **문자열**을 찾고
있었는데, 그리기를 `renderBoard()` 한 곳으로 모으면서 깨졌습니다.

**동작은 그대로입니다** — 폴링·SSE 둘 다 `renderBoard` 를 지나고 거기서
정렬이 걸립니다. 문자열 검사만 낡은 것이라 의도를 지키면서 새 구조에
맞췄고, **두 경로 모두 `renderBoard` 를 지나는지**까지 확인하도록 강화했습니다.

> 한쪽 경로만 지나면 **그쪽에서만 정렬이 안 걸리는**, 찾기 어려운 상태가
> 됩니다. 그것을 시험이 막습니다.

## 4. 시험 작성 중 만난 함정

**정상 SSE 스트림은 끝나지 않습니다.** TestClient 로 그대로 읽으면 응답이
완결되지 않아 **멈춥니다**(실제로 걸려서 중단했습니다).

구독 상한을 0 으로 낮춰 서버가 **거절 이벤트를 보내고 끝내도록** 만든 뒤
형식을 검사하는 방식으로 바꿨습니다. 거절도 SSE 형식을 지켜야 화면이 폴링으로
되돌아갈 수 있으므로, **이 경로를 확인하는 것 자체가 의미가 있습니다.**

## 5. ⚠️ 발견한 데이터 결함 — 확인 필요

공간 질의를 시험하다 나왔습니다.

```
등록 CCTV 39개소 · 좌표 있음 39개 · 서로 다른 좌표 38개
겹치는 좌표 (35.147345, 129.059051)
    BLOCK-BEOMNAEGOL : 범내골교차로   (부산진구)
    BLOCK-GUANGBOK   : 광복로         (중구)
```

두 곳은 **실제로 다른 지역**입니다.

| 영향 | 내용 |
|---|---|
| 지도 | 두 지점이 **겹쳐 표시**된다 |
| 반경 질의 | **같은 장소로 취급**된다 |
| 기상 연계 | 한쪽이 잘못된 지역 강수량을 받는다 |

**어느 쪽 좌표가 맞는지는 판단할 수 없어 그대로 두었습니다.** 확인해 주시면
고치겠습니다.
