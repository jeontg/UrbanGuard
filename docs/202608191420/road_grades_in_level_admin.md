## 1. 무엇이 문제였나

「노면은 S-95에서 빠졌나요?」라는 물음에서 시작했습니다. 확인해 보니 **의도한
제외**가 맞았습니다 — 2026-08-19 오전에 「노면 등급은 그대로 두세요」로
확정한 건입니다.

**그런데 확인하다 다른 것이 나왔습니다.**

```python
ROAD_PER100M_WATCH  = 1.0    # 관찰
ROAD_PER100M_REPAIR = 3.0    # 보수 필요
ROAD_PER100M_URGENT = 6.0    # 긴급
```

★ **노면 구간값은 어디서도 바꿀 수 없었습니다.** 화면·설정 어느 곳에도
이 값을 고칠 자리가 없었습니다(확인함 — `calibration.py` 밖에서 참조 0건).

> **「등급 이름을 통일하지 않는다」와 「구간 숫자를 화면에서 못 바꾼다」는
> 서로 다른 문제입니다.** 앞엣것만 결정돼 있었습니다.

침수·인파는 기관이 바꿀 수 있는데 **노면만 못 바꾸는 것은 이유가 없습니다.**
기관마다 도로 등급 기준이 다르면 **코드를 고쳐야** 했습니다.

## 2. 그냥 넣으면 안 되는 이유

★ **이 부분이 이번 작업의 알맹이입니다.**

노면 「양호·관찰·보수 필요·긴급」은 **위험등급이 아니라 정비 등급**입니다.

| | 침수·인파 | 노면 |
|---|---|---|
| 등급 | 관심 · 주의 · 경계 · 심각 | 양호 · 관찰 · 보수 필요 · 긴급 |
| 뜻하는 것 | **지금 위험한가** | **언제 고쳐야 하는가** |
| 시간 축 | 실시간(초·분) | 주 · 월 단위 |
| 쓰는 자리 | 상황판 이벤트 · 경보 | 정비 계획 · 예산 |
| 가장 높은 등급 | 「심각」 = **지금 통제하라** | 「긴급」 = **빨리 보수하라** |

⚠️ **섞어 세면 상황판에서 침수 「심각」과 노면 「긴급」 중 무엇이 더 급한지
알 수 없게 됩니다.** 그리고 노면 「긴급」이 위험등급 비교에 끼면 **정비
대상이 즉시 경보**됩니다.

## 3. 어떻게 했나 — 담되, 쓰이는 자리는 분리

### 3-1. 등급 표에 **성격** 칸을 넣었습니다

`risk_levels.kind` — `risk`(위험) / `maintenance`(정비).

```
risk         1 interest     관심
risk         2 caution      주의
risk         3 alert        경계
risk         4 severe       심각
maintenance  1 road_good    양호
maintenance  2 road_watch   관찰
maintenance  3 road_repair  보수 필요
maintenance  4 road_urgent  긴급
```

코드에 `road_` 접두사를 붙였습니다 — **겹치면 「긴급」과 「심각」이 같은 행을
가리켜 통일한 셈이 됩니다.**

### 3-2. 조회 함수가 정비 등급을 걸러냅니다

`core/vocabulary.py` 의 `active_levels` · `level_order` · `rank` ·
`critical_labels` 가 **기본으로 위험등급만** 봅니다. 정비 등급이 필요하면
`kind` 를 명시해서 부릅니다.

```python
V.rank(db, "긴급")        # 0  ← 위험등급이 아니다
V.rank(db, "심각")        # 4
```

### 3-3. 마이그레이션 `c5b8e2f31d47`

- `kind` 칸 추가(기존 행은 전부 `risk` — **판정이 바뀌지 않습니다**)
- 노면 4등급 + 구간 3행 심기
- **지금 코드에 박혀 있던 값 그대로**(1·3·6) 옮겼습니다 — 값을 손보는 것은
  기관이 화면에서 할 일이지 마이그레이션이 할 일이 아닙니다
- **업·다운·업 확인**

### 3-4. 화면에 성격 설명을 붙였습니다

**🛠 정비 등급** 묶음을 점선으로 갈라 놓고 「**위험등급 아님**」 배지를 답니다.
그 안에 2절의 비교표를 그대로 띄우고, 두 가지를 못박습니다.

- ⚠️ **노면 등급은 경보를 만들지 않습니다** — 상황판으로 올라갈 때는 별도
  규칙으로 위험등급(관심·주의·경계)으로 옮겨 적힙니다
- ⚠️ **「미보정」은 「양호」가 아닙니다** — 구간 길이를 안 넣어 판정을 못 한
  것이지 **점검이 끝났다는 뜻이 아닙니다**

### 3-5. 판정이 실제로 표를 읽습니다

`calibration.road_level(per, db=...)` 이 구간 표를 먼저 봅니다. 표를 못 읽으면
**코드 기본값으로 내려갑니다** — DB가 죽었다고 노면 판정이 멎으면 안 됩니다.

## 4. 만들면서 결함 넷을 잡았습니다

### ① 제가 넣은 필터가 구간 조회를 깨뜨렸습니다

`thresholds()` 가 `level_order()` 를 쓰는데, 그것을 위험등급만 담게 바꾸는
순간 **노면 구간이 통째로 버려졌습니다.** 도메인의 성격을 보는
`order_for_domain()` 을 따로 만들어 고쳤습니다.

### ② 노면만 순서 검사가 무력화됐습니다

⚠️ **가장 위험했던 것입니다.**

저장 시 「높은 등급의 문턱이 낮은 등급보다 커야 한다」를 검사하는데,
`level_order` 가 위험등급만 담아 **노면 등급이 전부 seq 0** 이 됐습니다.
그러면 값으로만 정렬한 뒤 자기 자신과 비교하는 꼴이라 **검사가 늘
통과**합니다.

> **막고 있다고 믿는 검사가 실제로는 아무것도 안 막는 상태**였습니다.
> 시험(`test_노면도_순서_검사를_받는다`)으로 못박았습니다.

### ③ 등급 이름 변경이 항상 400 이 됐습니다

이름 폼은 위험등급만 그리는데 라우트는 **모든 행**에 이름을 요구했습니다.
없는 칸을 「비웠다」로 읽어 거부한 것입니다.

★ **없는 것과 비운 것은 다릅니다.** 폼에 없는 칸은 건드리지 않도록 고쳤습니다.

### ④ 설계서 현행성 시험이 물렀습니다

문서 **전체**에서 컬럼 이름만 찾고 있어, **다른 표에 같은 이름의 컬럼이 있으면
통과**했습니다. 실제로 `risk_levels.kind` 와 `events.hazard_type_code` 가
빠져 있는데도 **시험은 초록이었습니다.**

→ **표의 절 안에서** 찾도록 조였고, 빠진 두 컬럼을 설계서에 채웠습니다.
