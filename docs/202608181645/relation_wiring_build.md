## 0. 결론 먼저

○ **네 가지 모두 붙였습니다.** ①S-80 방향각·인접 생성 ②S-03 주변 지점
  ③위험등급 판정 연결 ④상·하류 지정과 **선행 경고**

○ ★ **선행 경고가 이번 회차의 알맹이입니다.** 상류에서 「경계」 이상 사건이
  열려 있는데 하류가 조용하면, **잠기기 전에** 상황판에 뜹니다.
  경남 제안요청서 기대효과의 「연속 추적」이 실제로 요구하는 기능입니다

○ ★ **등급 비교를 이름에서 seq 로 바꿨습니다.** 기관이 「심각」을 「위험」으로
  바꿔도 문턱이 그대로 맞습니다 — 경남 SFR-012 「최소 4단계 **이상**」 대응

○ ⚠️ **관계를 등록하지 않으면 화면이 그대로입니다.** 카드가 아예 안 보입니다.
  빈 카드로 자리를 차지하지 않게 했습니다

## 1. ① S-80 — 방향각과 인접 자동 생성

### 방향 입력

`cameras` 수정 폼에 **방위각·상하각·화각·설치 목적** 4칸을 넣었습니다.

| 칸 | 범위 | 비고 |
|---|---|---|
| 방위각 | 0~359 | 북 0 · 동 90 · 남 180 · 서 270 |
| 상하각 | -90~90 | 내려보면 음수 |
| 화각 | 1~360 | |
| 설치 목적 | 방범·재난·교통·시설·기타 | KLID SFR-14 「목적별 분류」 |

> ⚠️ **비워 두는 것이 정상입니다.** 화면 문구에도 「모르면 비움」이라 적었습니다.
> 0 으로 채우면 **「전부 북쪽을 본다」**가 되어 사각지대 분석이 통째로 거짓이
> 됩니다. 시험으로도 못박았습니다(`test_bearing_can_be_saved_and_left_blank`).

> ⚠️ 일괄 등록처럼 **방향 칸이 없는 경로에서는 기존 값을 건드리지 않습니다**
> (`_apply_aim` 이 키 존재 여부를 봅니다). 안 그러면 엑셀 업로드 한 번에
> 방향각이 전부 지워집니다.

### 인접 자동 생성

「인접 관계 자동 생성」 카드에서 **반경을 넣고 미리보기 → 생성**합니다.

| 항목 | 내용 |
|---|---|
| 기본 반경 | **500m** (50~5000 허용) |
| 미리보기 | **아무것도 쓰지 않고** 건수만 알려 줌 |
| 재생성 | `auto=True` 인접만 교체 — **사람이 넣은 상·하류는 그대로** |
| 좌표 결함 | 거리 0인 쌍을 **세어서 화면에 경고** |

> ⚠️ 라우트를 `{camera_id}/delete` **위에** 뒀습니다. 아래에 두면
> `/settings/cameras/links/build` 가 `camera_id="links"` 로 잡혀
> 「카메라를 찾을 수 없습니다」가 됩니다 — **지역 해지에서 실제로 겪었던
> 문제**라 시험으로 못박았습니다(`test_links_build_route_is_not_shadowed`).

## 2. ② S-03 — 주변 지점

이벤트 상세에 **주변 지점** 카드가 생겼습니다.

| 표시 | 뜻 |
|---|---|
| **하류** (붉게) | 지금 사건이 **다음으로 번질 수 있는** 방향 |
| 인접 | 옆에 있는 지점 |

**하류가 인접보다 앞에 옵니다.** 인접은 「옆에 있다」지만 하류는 「다음에
잠긴다」이기 때문입니다. 최대 8곳까지만 띄웁니다 — 도심은 반경 500m 안에
지점이 열 개 넘게 들어가 화면이 목록으로 덮입니다.

근거는 경남 SFR-001 「연속 추적」과 202608172039 조사에서 확인한 통상 사양
「알람 발생 카메라 **주변 다중 카메라 자동 확인**」입니다 — KT GiGAeyes 에는
있고 우리엔 없던 기능입니다.

## 3. ③ 위험등급을 판정에 연결

### 이름 비교를 없앴습니다

`vocabulary.rank(db, 등급)` 이 **seq 를 돌려줍니다.** code 든 label 이든 받습니다.

```
관심 1 · 주의 2 · 경계 3 · 심각 4      ← risk_levels 표에서 옴
```

**이름으로 비교하면 기관이 이름을 바꾸는 순간 조용히 틀립니다.**
seq 비교는 그대로 맞습니다.

### 단독 발송 판정

`notifications.solo_send_allowed(등급, db=...)` 가 **`risk_levels.is_critical`
을 먼저 봅니다.** 하드코딩 `roles.CRITICAL_LEVELS` 는 **되돌아갈 자리**로만
남겼습니다.

> ⚠️ **표가 비어 있으면 하드코딩으로 되돌아갑니다.** 빈 집합을 「아무도
> 허용 안 함」으로 읽으면, 어휘를 아직 안 심은 설치본에서 **심각 상황에
> 단독 발송이 막힙니다.** 안전한 쪽으로 넘어지는 것처럼 보이지만 실제로는
> **골든타임을 잃습니다.**

### ⚠️ 발견 — 침수 단계 어휘가 다릅니다

`calibration.flood_level()` 이 돌려주는 값은
**「통제 권고 · 위험 · 주의 · 관심」**으로, 4단계 위험등급
**「관심 · 주의 · 경계 · 심각」**과 **어휘가 다릅니다.**

**이번에 통일하지 않았습니다.** 화면에 보이는 문자열이 바뀌면 운영자가 읽는
말이 달라지고, 이건 우리가 정할 일이 아닙니다. **어느 쪽으로 맞출지 확인이
필요합니다.**

## 4. ④ 상·하류 지정과 ★ 선행 경고

### 지정 (S-80)

「상·하류 지정」 카드에서 **상류 → 하류**를 고릅니다. 지정된 쌍은 표로 보이고
해제할 수 있습니다.

| 규칙 | 이유 |
|---|---|
| 같은 지점 금지 | |
| **반대로 이미 지정돼 있으면 거부** | 물이 두 방향으로 흐를 수 없다 |
| 양방향 저장 (`downstream` + `upstream`) | 하류에서 「내 위가 어디냐」를 물을 수 있어야 한다 |
| `auto=False` | **자동 생성이 건드리지 않는다** |

> ⚠️ **좌표로는 알 수 없습니다.** 지형과 배수 계통을 아는 담당자가 지정해야
> 합니다. 화면에도 그렇게 적었습니다.

### ★ 선행 경고 (S-01)

상황판에 **선행 경고** 카드가 뜹니다.

```
[선행 경고 1곳]
  초량지하차도 — 아직 조용함
  상류 범내골교차로 「경계」 진행 중
```

| 규칙 | 이유 |
|---|---|
| 문턱 **seq 3(경계) 이상** | 이름이 아니라 순위로 본다 |
| 하류에 **이미 사건이 있으면 경고 안 함** | 아는 일을 다시 알리면 **경보 피로**만 쌓인다 |
| 종결된 이벤트는 제외 | |
| **인접만으로는 경고 안 함** | 「옆에 있다」는 「다음 차례」가 아니다 |
| 어휘에 없는 등급(`미보정`)은 rank 0 | 문턱을 절대 못 넘는다 |
| 조회 실패해도 **상황판은 뜬다** | 부가 기능이 죽어도 관제 화면은 살아야 한다 |

## 5. 검증

| 항목 | 결과 |
|---|---|
| 신규 시험 | **33건** — 관계 흐름 19 · 화면 14 |
| 누적 신규 | 25 + 33 = **58건** |
| **전체 회귀** | **1,134건 통과 · 3건 건너뜀 · 실패 0** (137초) |
| 직전 회차 | 1,101건 → **+33건이 전부 신규분** |

### 시험이 못박은 것 (발췌)

| # | 내용 |
|---|---|
| 1 | `links/build` 가 **`{camera_id}` 로 안 잡힌다** |
| 2 | 미리보기는 **아무것도 쓰지 않는다** |
| 3 | 방향각을 **비워 둘 수 있다**, 범위 밖은 거부 |
| 4 | 자동 재생성이 **사람이 넣은 상·하류를 지우지 않는다** |
| 5 | 반대 방향 지정을 **막는다** |
| 6 | 문턱이 **seq 로** 판정된다 (5단계 기관 흉내 시험 포함) |
| 7 | 하류가 이미 바쁘면 **경고하지 않는다** |
| 8 | 인접만으로는 **경고하지 않는다** |
| 9 | 관계가 없으면 **카드가 안 보인다** (S-03·S-01 각각) |
| 10 | 권한 없는 사용자는 **403** |
