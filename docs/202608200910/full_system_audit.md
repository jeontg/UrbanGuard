## 1. ★★ 결함 ① — 상대 임포트 점 하나

```python
# traffic_weather/perception/traffic_tracker.py:162
from ....common import tracking     # ← 점이 하나 많음
```

`tot_dashboard.traffic_weather.perception` 은 깊이 3이라 **`...`** 이어야
합니다. 네 개라 **패키지 밖으로 나가 `ImportError`** 가 났습니다.

### 왜 이렇게 커졌나

블록 루프 전체가 `try/except` 로 감싸져 있습니다. 예외가 나면 **한 줄만 찍고
다음 틱으로 넘어갑니다.** 그래서 매 틱마다 본문이 통째로 실패했고,

- perception 갱신 ✗
- 침수 위험도 갱신 ✗
- 스냅샷 생성 ✗
- 상황판 store 갱신 ✗

**이 모든 것이 조용히 멈춰 있었습니다.**

### ⚠️ 왜 아무도 몰랐나 — 두 가지가 겹쳤습니다

1. **함수 안 지연 임포트**라 모듈을 임포트할 때는 안 터집니다. 시험이
   `import` 만으로는 잡을 수 없습니다
2. 예외를 **한 줄로 잘라 삼켜** 트레이스백이 없었습니다 —
   **54,515번 나도 어디서 났는지 알 수 없었습니다**

### 무엇을 했나

- 임포트 수정
- **블록마다 첫 한 번은 트레이스백을 남기도록** 계측. 매번 남기면 로그가
  터지고(실제로 54,515줄), 안 남기면 원인을 영영 못 찾습니다
- **전 파일 상대 임포트 깊이 검사 시험** 신설 — 145개 파일, 위반 0

## 2. ★★ 결함 ② — 제 어제 수정이 절반이었습니다

①을 고치자 **가려져 있던 것**이 드러났습니다.

```
'LRASPP' object has no attribute 'predict'
```

2026-08-19 에 「백엔드를 파일에서 판별(auto)」로 **적재는 고쳤는데, 추론
호출부는 그대로** `self._water_backend` 를 보고 있었습니다. 그 값은
`"auto"` 라 `"torchvision"` 과도 `"ultralytics"` 와도 같지 않아 **늘
ultralytics 분기**로 떨어졌고, torchvision 모델에 `.predict` 를 불렀습니다.

> ★ **「모델이 열렸다」와 「추론이 된다」는 다른 말입니다.**
> `models_loaded: 3` 이었지만 **한 장도 처리하지 못했습니다.**
> 어제 「처리 완료」라고 적은 것은 **불완전한 보고였습니다.**

→ **실제로 열린 백엔드**(`_water_backend_effective`)를 보도록 고쳤습니다.

### 검증

```
고치기 전 : [runner:] 오류 54,515회
고친 뒤   : 0회
/api/health: torchvision · 적재 7 · ok True · 블록 7
```

## 3. ★ 결함 ③ — 「최근이 먼저」가 지켜지지 않았습니다

`crowd_observations` 를 `observed_at` **하나로만** 정렬하고 있었습니다.
같은 초에 들어온 관측은 서로 순위가 없어(tie) **실행마다 순서가 뒤집힙니다.**

실제로 시험이 4·6·8 을 넣고 「최근이 먼저(8)」를 기대했는데 **4를 받았습니다.**

⚠️ **시험 문제가 아니라 운영 문제입니다.** 관제요원이 「가장 최근 관측」이라고
믿는 값이 사실은 **그 초의 아무 것**이 됩니다.

같은 구조를 **9곳**에서 찾아 `id` 2차 키를 넣었습니다 — 인파 이력(2)·노면
이력(2)·오류 목록(2)·이벤트 목록(2)·시설물·민원·감사 로그.

★ `id` 는 단조 증가하므로 묶인 순서를 확실히 깹니다. **정렬 tie 만 깨므로
동작이 달라지지 않습니다.**
