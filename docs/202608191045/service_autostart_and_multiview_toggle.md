## 1. 서비스가 안 뜬 진짜 이유

`data/logs/serve.log` 의 마지막 기록입니다.

```
[2026-08-18 12:14:17] ⚠ 비정상 종료 (code 1073807364) · 2240.8분 동작 후 죽었습니다.
[2026-08-18 12:14:17] 5초 뒤 재기동합니다 (연속 1회째).
```

`1073807364` = `0x40010004` — **바깥에서 강제 종료된** 코드입니다(콘솔 창 닫힘 등).
그 뒤 재기동 기록이 **한 줄도 없습니다.**

★ **감시 프로세스까지 같은 순간에 함께 죽었습니다.** 콘솔 창을 닫으면
자식만이 아니라 감시까지 통째로 내려갑니다. **되살릴 것이 남아 있지 않았습니다.**

> `scripts/serve.py` 머리말에 적어 둔 한계가 그대로 일어난 것입니다 —
> 「죽으면 되살린다」는 하지만 **「처음에 누가 띄우는가」는 못 합니다.**

### 곁가지 — 미리보기 패널로는 UrbanGuard 를 못 띄웁니다

미리보기가 읽는 파일이 **`flood_t` 쪽 `launch.json`** 입니다. 거기 있는 항목은
상대 경로라 **flood_t 서비스**를 띄웁니다. flood_t 는 읽기 전용이라 그쪽에
항목을 더할 수도 없습니다. 그래서 **명령·스크립트로 띄웁니다.**

## 2. 작업 스케줄러 등록

### 만든 파일

| 파일 | 하는 일 |
|---|---|
| `scripts/urbanguard-service.ps1` | 등록·해제·기동·종료·재기동·상태·안내 |
| `scripts/urbanguard-run.cmd` | 실제 기동 (작업과 사람이 **같은 경로**를 씁니다) |
| `scripts/urbanguard-start.cmd` | cmd·탐색기용 기동 |
| `scripts/urbanguard-stop.cmd` | cmd·탐색기용 종료 |

### 쓰는 법

```bash
powershell -ExecutionPolicy Bypass -File scripts\urbanguard-service.ps1 -Action install
```

| 동작 | 명령 |
|---|---|
| 등록 | `-Action install` |
| 기동 | `-Action start` 또는 `scripts\urbanguard-start.cmd` |
| **종료** | `-Action stop` 또는 `scripts\urbanguard-stop.cmd` |
| 재기동 | `-Action restart` |
| 상태 | `-Action status` |
| 등록 해제 | `-Action uninstall` |
| 서비스 등록 안내 | `-Action guide` |

`.cmd` 는 **탐색기에서 두 번 눌러도** 됩니다. 그때만 창이 남고, 스크립트에서
부르면 안 멈춥니다 — 자동화에서 멈춰 있는 것은 고장과 구분이 안 됩니다.

### ⚠️ 이 등록의 한계 — 숨기지 않습니다

**관리자 권한이 없어 「부팅 시」로는 등록할 수 없었습니다.** 지금 등록한 것은
**「로그온 시」**입니다.

> 서버가 재부팅되면 **누군가 로그인해야** 서비스가 뜹니다.
> **무인 서버에서는 이것으로 부족합니다.**

운영 납품에서는 관리자 권한으로 **윈도우 서비스(NSSM)** 로 등록해야 합니다.
필요한 명령은 `-Action guide` 에 그대로 있습니다.

## 3. 종료가 왜 두 단계인가

★ **이 부분이 이번 스크립트의 알맹이입니다.**

감시(`serve.py`)를 남겨 둔 채 자식(uvicorn)만 죽이면 **5초 뒤 되살아납니다.**
그것이 감시의 존재 이유입니다. 그래서 순서가 정해져 있습니다.

1. **작업을 끝낸다** — 안 하면 작업이 「실행 중」으로 남아, 다음 기동이
   `MultipleInstances=IgnoreNew` 때문에 **조용히 무시**됩니다
2. **감시를 먼저 죽인다** (`/T` 로 자식까지)
3. **홀로 남은 자식을 정리한다**
4. **포트가 실제로 풀렸는지 확인한다** — 확인 못 한 종료는 종료가 아닙니다

### 다른 파이썬을 죽이지 않습니다

같은 장비에 `flood_t` 서비스가 있고 그쪽도 `python.exe` 로 돕니다.
**명령줄에 이 저장소 경로가 들어 있는 프로세스만** 고릅니다.

## 4. 만들면서 잡은 것 세 가지

### ① `pythonw.exe` 로는 못 띄웁니다

처음에 콘솔 없는 `pythonw.exe` 로 등록하려다 자식이 **code 1 로 즉사**했습니다.
「콘솔 핸들이 없어서」라고 봤는데 **틀렸습니다.**

프로세스 목록을 실제로 보니 이렇습니다.

```
.venv\Scripts\pythonw.exe serve.py          ← venv 껍데기
 └ Python312\pythonw.exe serve.py           ← 기본 인터프리터로 넘어감
```

★ **venv 의 `python(w).exe` 는 기본 인터프리터를 자식으로 다시 띄우는
껍데기**였고, `pythonw` 쪽은 `sys.executable` 이 **기본 파이썬**으로 잡혔습니다.
그래서 uvicorn 이 없는 인터프리터로 자식을 띄운 것입니다.

→ `python.exe` + **출력 리디렉션**으로 갔습니다. `python.exe` 는 정상입니다.

> 상태 화면에서 프로세스가 「감시 2개·서비스 2개」로 보이는 것도 같은 이유입니다.
> **중복이 아니라 껍데기와 알맹이가 함께 세어진 것**입니다.

### ② 이미 죽은 프로세스를 또 죽이려다 확인 단계를 건너뛰었습니다

`/T` 로 부모를 죽이면 자식도 함께 죽는데, 미리 뽑아 둔 목록으로 그 자식을 또
죽이려 하니 `taskkill` 이 오류를 냈고 — PowerShell 5.1 이 네이티브 명령의
stderr 를 오류로 처리해 **스크립트가 거기서 멈췄습니다.**

⚠️ **종료는 다 해 놓고 「포트가 풀렸는지」 확인을 못 했습니다.** 기능은
됐지만 **되었다고 말할 근거가 없는 상태**였습니다. 살아 있는지 먼저 보고,
`stderr` 는 `cmd` 안에서 삼키도록 고쳤습니다.

### ③ 상태 화면에서 로그가 깨졌습니다

`serve.log` 는 BOM 없는 UTF-8 인데 PowerShell 5.1 의 기본값은 cp949 라
한글이 통째로 깨졌습니다. **장애를 보려고 여는 자리에서 로그를 못 읽으면
없느니만 못합니다.** `-Encoding UTF8` 을 붙였습니다.

## 5. 멀티뷰 동작 켜기·끄기 (S-05)

### 왜 필요한가

칸마다 CCTV 원본을 잡아 오는 일이라, **16분할이면 4초마다 16지점**을
건드립니다. 자리를 비우거나 다른 화면을 볼 때도 계속 돌면 서버가 그 부담을
그대로 집니다.

### ★ 멈춤은 「그리기 정지」가 아니라 「불러오기 정지」입니다

그리기만 멈추면 **서버 부담은 그대로**입니다. 타일 하나가 CCTV 원본 한 번이라,
불러오기를 멈춰야 실제로 줄어듭니다.

### ⚠️ 멈춘 화면이 「지금」처럼 보이면 안 됩니다

멈추면 마지막 그림이 그대로 남습니다. 관제요원이 그것을 현재 상황으로 읽으면
**없는 안전을 봅니다.** 그래서 멈춤에는 **세 가지가 반드시 따라옵니다.**

| 표시 | 자리 | 왜 |
|---|---|---|
| 경고 띠 | 화면 위 | 한눈에 보입니다 |
| **칸마다 「⏸ 멈춤」** | 타일 우상단 | ★ 큰 화면에서는 위 띠가 **시야 밖으로 밀려납니다** |
| 마지막 갱신 시각 | 도구줄 오른쪽 | 언제 것인지 없으면 판단할 수 없습니다 |

### 앞뒤가 맞게 다듬은 두 곳

- **멈춘 채 지점을 바꾸면** 그 칸은 불러옵니다 — 고르고 아무것도 안 나오면
  고장으로 읽힙니다. 대신 **그 칸의 멈춤 딱지를 지웁니다.** 방금 가져온
  그림에 멈춤 딱지가 붙어 있으면 그 표시 자체를 아무도 안 믿게 됩니다
- **멈춘 채 화면을 열면** 아직 못 받은 칸이 「불러오는 중…」으로 남습니다.
  영원히 오지 않을 것을 기다린다는 뜻이라 **「멈춤 — ▶ 다시 시작을 누르세요」**
  로 바꿉니다

### 기본값은 켜짐

⚠️ **관제 화면이 아무 말 없이 멎어 있으면 안 됩니다.** 저장된 값이 없거나
`localStorage` 를 못 쓰는 환경에서도 **켜짐으로 시작**합니다.

설정은 **이 브라우저 안에서만** 삽니다(사람마다·자리마다 다릅니다).

## 6. 곁가지 — 기관명이 깨져 있었습니다

화면 제목이 `◇入갬◇◇◇◇` 로 나오고 있었습니다. **DB 값 자체가 손상**돼
있었습니다.

| 설정 | 복원한 값 |
|---|---|
| `org_name` | **부산광역시** |
| `solution_name` | **통합 도시안전 관제** |

**cp949 로 인코딩된 것을 UTF-8 로 읽은** 결과입니다. 손상된 값을 같은 방식으로
재현해 **바이트 단위로 일치**함을 확인한 뒤에만 되돌렸습니다 — 추측으로
채우지 않았습니다.

**앱 코드에는 이 변환이 없습니다**(설정 저장 경로에 cp949 변환 0건). 콘솔을
거친 일회성 입력으로 들어간 값으로 보입니다.
